## 跨回合规划器 crossn（2026-10-07 下午，svsim f492ffe）

1 号会话的 `svsim.agents.crossturn_agent`，spec 后缀 `crossnKzZrR`：

## CR 刻度对照（2026-10-07 傍晚）

Salem 给了一个经验数据点："2300 对 2100 CR 往往有 70% 左右的胜率"。把三种刻度放在一起比：

| CR 分差 | 游戏规则的稳态式（`learn/rating.py`：0.5 + 分差/800，175 封顶） | 联赛表现用的 200 CR/logit | Salem 经验（200 分 ≈ 70%，即 236 CR/logit） |
|---|---|---|---|
| 50 | 56.2% | 56.2% | 55.3% |
| 100 | 62.5% | 62.2% | 60.4% |
| 150 | 68.8% | 67.9% | 65.4% |
| 175 | 71.9% | 70.6% | 67.7% |
| 200 | 75.0%（超过 175 的规则：赢 +8、输 −24，稳态 75%） | 73.1% | **70.0%** |

- 游戏的稳态式回答的是"按这个胜率，积分最终停在多大的分差"（期望得分为零的平衡点）。
- Salem 的数字是实际天梯上两个分数段之间观察到的胜率。实际分数不在平衡点上，还有波动，所以曲线更平。
- 两者在 200 分差处差 5 个百分点。在我们常见的 55%～60% 区间，同一个胜率换成 CR，按 Salem 的刻度要大 15%～20%。

**定了（架构线程，2026-10-07）**：
- 报告里的主数字用 **Salem 刻度：236 CR/logit，200 分 ≈ 70%**，括号里留游戏稳态式。
- 理由：CR 在这里的用途是"对人意味着什么"。Salem 的经验值说的就是这个意思，游戏稳态式说的是"按规则积分会停在哪"。
- 两者不是谁对谁错：一个是平衡点，一个是实际观察。不要因为"规则里写的是 800"又换回去。
- BT 拟合出的 bot 对 bot 斜率只作诊断，不当报告刻度。
- 1 号会话在 (b) 之后改 `rating.py` / `gate.cr_text` 时按这个来。在那之前，评测台自己打印的 CR 仍是稳态式；本分支的 `fixed_run.py` 两种都打印。
