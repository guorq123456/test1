# 主线 B：按局面难度分配搜索次数（平均算力不变）

**条件**：对手卡表已知（牌序、手牌未知）。

## 预注册（架构线程 13:56Z；写在任何门的结果之前，之后不改）

**机制**（建造线设计）：
- **B1**：按合法动作数分配搜索次数。
- **B2**：分块提前停，省下的次数给同一回合后面的决策。
- 两个机制各过一组门，**B1 先**。

**门**：
- A = 强档 + 分配机制（建造线给的串），B = `level-strong`（强档，每步均匀 200 次）。交叉格用 `--versus` 是我改的，架构线程 14:08Z 确认。
- 每个机制两格，定长 300 对，没有 SPRT：

| 格 | 模式 | 一对的得分 | B1 种子库 | B2 种子库 |
|---|---|---|---|---|
| 跳费龙镜像 | 直接对打（`--fixed --max 600`） | A 两局的平均 | 61600000 | 61800000 |
| 连击妖对机锋 | `--versus level-strong`（`--fixed --max 1200`）：A、B 打连击妖，C = 强档打机锋 | 0.5 + A − B | 61700000 | 61900000 |

- 连击妖对机锋不是镜像。如果直接对打，A 打连击妖、B 打机锋，卡组强弱会混进来，50% 就不是零点了。所以这一格和 C2 推广门一样用 `--versus`：A、B 在同一副发牌上打同一个 C。两种模式的一对得分零点都是 50%，可以合并。
- 输出：`analysis/gates/alloc/<B1|B2>_<我方>_<对方>.jsonl`。

**算力对齐**：分配方案的参数 k 由本机用 `search_cost` 标定（182 个局面、`--iterations 200`、两遍取优），A 的平均开销对 B 在 ±3% 以内。

**判读**：
- **装不装**：两格按对合并（600 对，每对权重相同，按格分层重抽），一对得分的下沿 > 50% 就装；**但任一格的上沿 < 50%（那一格明显变差）就否决，不装**（架构线程 14:08Z 定，写在任何结果之前）。理由：搜索规则是全局装的，明显伤到一个对位就不装。
- 两格各报一对得分、区间、CR、先后手。交叉格的用意是检验这条规则不是只对镜像有效。
- 我用 gate_report 每格读一次，再出合并数。

**照记，不改判读**：
- B1、B2 各判各的，单侧误通过率各约 2.5%。
- **B2 的算力对齐有个口子**：`search_cost` 量的是单个决策点的开销，B2 把次数在同一回合的决策之间挪，单点标定不一定等于每回合实际花的。门里顺带记每局 A、B 的总迭代次数：建造线会给 `agent.last_iterations`，以及每局的中位数、p90、总和（架构线程 14:08Z），我事后报 A ÷ B。这一条只作旁注，不是判门条件。
- 连击妖对机锋这一格现装的是 C2 模型，它的门上增益第 5 轮没复核出来。A、B 用同一个评估器，所以不影响这道门，只记一笔。

## 预注册补充：K、N 怎么标（架构线程 14:32Z；写在任何 B 结果之前）

**顺序**：本机先在空机上标 K、标 N，再四道门并行跑。

**B1 的 K**（按合法动作数分配的系数）：
- 两份局面各 182 个：s200 跳费龙镜像；`data/pairings-20261008/nemesis-t_elf-t`（连击妖、机锋两侧的决策点都有）。
- 各用 `--fit-alloc` 得 K_ramp、K_en，K = 两者平均。
- 再各用 `--alloc legal:K` 验证耗时比：两格平均在 ±3% 以内就通过，单格超 3% 只注明。
- 超了就 K ← K × (1 − 平均偏差)，最多再验一次。
- 建造线 a84f3f6 的 search_cost 能一次读多个文件，本机不用，只作对照。
- **记一句**：按耗时对齐时，B1 平均每步约 158 次迭代，不是 200。宽局面（合法动作多）每次迭代更贵，B1 又正好把次数往宽局面挪，同样的时间买到的迭代就少了。这是机制本身的一部分，对齐的是算力（时间），不影响公平。

**B2 的 N**（分块提前停时每步的预算上限）：
- 整局标定：`search_cost --whole-games 40 --workers 1`，空机。
- 每格 N ∈ {220, 250, 280}，各和均匀 200 同种子打 40 局，以**每局总秒数**相对均匀 200 的百分比为准；每步毫秒、每局决策数、每局迭代数一并记。
- 两格平均最接近 0% 的 N：在相邻两档之间线性插值取整。三档全偏一边，就再加一档。
- 选定的 N 两格各再打 40 局验证：平均在 ±3% 以内通过，单格超 3% 只注明。
- 标定用门的同一个种子库（61800000 / 61900000），标定局不进门的统计。
- **我加的一条防护**：N 只按耗时选，标定局的胜负不看、不记，所以和门同库不会影响判读。标定输出里如果带了胜负，读的时候跳过，不拿来比较各档 N。

**改动：B2 的算力对齐口径**（架构线程 15:19Z；写在 B2 任何结果之前，照实标为改动；B1 两道门已开跑，不受影响）：
- **等算力改成按每个决策的平均毫秒**：A 相对 B 的两格平均在 ±3% 以内。不再用每局总秒数。
- **为什么改**：B2 会改变走法，同种子下每局的决策数在 85.8～94.1 之间跳，40 局的整局秒数噪声约 ±8%。连击妖对机锋那格按整局秒数甚至不单调（N = 190：−1.2%，210：+16.0%，220：+8.9%，250：+16.0%）；按每步毫秒就是单调的（190：−6.2%，210：+5.8%，220：+4.4%，250：+13.1%）。
- 按每步毫秒在 190～210 之间插值，得到 **N = 200**，本机在做 40 局验证。验证仍超 ±3%，就按比例修一次 N，直接开门，并注明实测偏差，不再循环。
- **B1 不重标**：B1 的验证本来就是按每步毫秒，两格 −4.2% / +7.9%，平均 +1.9%。两种口径都在线内。
- **判读时一起报**：两格各自的实测算力比（每步毫秒），以及每局 A ÷ B 的迭代总数。两条线的交叉格都偏向 A 约 +8%。
- **我加一句量级**：按 J2（200 次以上每翻一倍约 +13 CR），A 多 8% 的算力约合 +1.4 CR，远小于一道 300 对门能分辨的大小（约 ±30 CR）。所以交叉格偏 8% 照记即可，不影响判读。

**门里的 A 串**（K、N 填本机标出的值，本机记在 `analysis/gates/alloc/README.md`，我这边也照抄）：
- B1：`mcts:200+plan+learned+phased+alloc=legal:K`
- B2：`mcts:N+plan+learned+phased+alloc=bank`
- B2 门里每局 A ÷ B 的迭代总数照旧只作旁注。

## B1 门结果（本机 8288c12；代码 a61019b；K = 27.61；输出在 `gates_B1.txt`，对局文件抄在 `analysis/gates/alloc/`）

条件：对手卡表已知（牌序、手牌未知）。照预注册判；两个文件的种子、对数逐个核过。

| 格 | 模式 | 一对的得分（95%） | CR（稳态式） | A 先手 / 后手 | 迭代总数 A ÷ B | 每决策迭代 A / B |
|---|---|---|---|---|---|---|
| 跳费龙镜像（61600000） | 直接对打 | 52.7% ± 3.0%（49.6%～55.7%） | +25（+21） | 56.0% / 49.3% | 1.009 | 201.1 / 200.0 |
| 连击妖对机锋（61700000） | --versus | 50.5% ± 4.0%（46.5%～54.5%）；A 对 C 49.2%，B 对 C 48.7% | +5（+4） | 54.3% / 44.0% | **0.776** | **157.2 / 200.0** |
| **两格按对合并（600 对，按格分层重抽）** | | **51.6%（49.1%～54.1%）** | **+15** | | | |

- **判定：B1 不装。** 合并下沿 49.1% < 50%。两格上沿都在 50% 以上，否决条件没触发。
- **交叉格对 A 偏紧**（协调线 15:3x 提醒，我核过）：
  - 连击妖一方 A 每步平均只用了 157 次迭代，是 B 的 78%。
  - 原因：K 是在机锋对连击妖的整份局面上标的，两边的决策混在一起。连击妖自己的局面合法动作少，按 K × 合法动作数分到的次数就少。耗时验证的 +7.9% 是那份局面上两边合起来的数，不是门里连击妖这一边的。
  - **更正**：上面「改动」一节里写的「两条线的交叉格都偏向 A 约 +8%」，对 B1 来说方向反了。门里实际是 A 少用约 22%。
  - **值多少**：按 J2（200 次以上每翻一倍约 +13 CR），22% 的缺口约 −5 CR；按 100→200 那段的斜率（+0.18 logit ≈ +42 CR 每翻一倍），约 −15 CR。摊到合并结果上是 2～7 CR，足以把合并下沿推到 50% 上下。
  - 所以 B1 这次**不是干净的失败**：照规则不装，但门对 A 偏紧，两格点估计都偏正（+25、+5）。记作「B1 在交叉格未在等算力下测过」。
- **下一步**（架构线程 15:38Z / 15:39Z 定，取代我原来的建议）：
  - **B2 先跑完。**
  - **B2 过了**：B1 就此关闭。`+alloc=` 只能取一个值，两个机制不叠加。
  - **B2 也不装**：才做 B1 的第二次尝试，而且**不是按卡组分别标 K**（上线只有一个串，分卡组的 K 等于把卡组名当参数），而是建造线把分配改成不依赖卡组的**自归一版**：用本局 agent 自己决策的合法动作数均值做归一，K 不再固定。新候选、新预注册、新库，命令由架构线程给；预注册里写明「同一机制的第二次尝试，单侧误通过率约翻倍到 5%」。
  - **B2 的交叉格**可能有同样的混合问题（N 是在双方都用 bank 的自对局上标的，门里 A 只打连击妖）。门出来后我按 iterations 核连击妖一方的 A ÷ B，偏离大照实记；交叉格不匹配时怎么判，见下一节（架构线程 15:46Z 定）。

- **架构线程 15:35Z 的决定**（协调线转）：
  - **B1 不装，现在不补格**（后续见上面「下一步」）。
  - **交叉格记作「算力不匹配，不是有效的等算力测试」**：50.5% 是「少用两成算力打平」，既不算过也不算不过，不计入 B1 的判定。
  - 镜像格是干净的等算力测试（A ÷ B 迭代 1.009）：+25 CR，区间约 −4～+46，含 0，和 J2「同一个评估器下挪算力值不了多少」一致。
  - 不按组合分别标 K：上线只有一个 K，分格的 K 不是要上线的东西；镜像格已经说明效果很小。
  - 以后要救 B1，正路是做成不依赖卡组的自归一分配（按本局自己决策的合法动作均值归一，不用固定 K）。那是新候选，另开门。
- **两种读法的分歧照实写**：
  - 预注册的判定规则是两格按对合并：51.6%（49.1%～54.1%），不装。
  - 架构线程的读法把交叉格剔掉、只看镜像格：52.7%（49.6%～55.7%），也不装。
  - 结论相同。「剔掉交叉格」是看过数据之后的改动，照实标注；正式判定仍以预注册的合并数为准。

## B2 交叉格「算力不匹配」的判法（架构线程 15:46Z 定；写在 B2 任何结果之前，开读之前）

条件：对手卡表已知（牌序、手牌未知）。

- **按墙钟，不按迭代**：B2 在同样的时间里迭代数比均匀 200 少得多（标定里 N = 190 时迭代 −19%，每步毫秒只 −6%），用迭代比会把时间上对齐了的格误判成不匹配。我原来提议用迭代比，理由写的是「每次迭代开销差不多」，这句不对，照架构线程的改。
  - 建造线在 gate 的每对记录里加 A、B 各自的每决策平均毫秒（`ms` / `ms_b`，只计搜索的步）。本机验证完 N 后等这个提交，最多等 15 分钟，没到就用备用口径开门。
- **匹配的定义**：交叉格里连击妖一方的每决策毫秒 A ÷ B 在 **0.90～1.10** 之内算匹配。镜像格的比值也照报。
  - **备用口径**（门的行里没有 `ms` 字段时）：迭代比 A ÷ B 落在 **r0 × [0.90, 1.10]** 之内算匹配。r0 = N = 200 验证跑里 A 的每决策迭代 ÷ 200（同一格的自对局；分得出连击妖一侧就用那一侧，分不出就用两侧合计）。**r0 在开门前写进这里**：（待本机报）。
- **匹配时**：照预注册。两格合并下沿 > 50% 装；任一格上沿 < 50% 否决。
- **不匹配时**：
  - 只看镜像格，镜像格下沿 > 50% 才装；
  - 交叉格只报不判；
  - 只有当 A 在交叉格的算力不少于 B（比 ≥ 1）、而且上沿 < 50% 时，才用交叉格否决。
- B1「只看镜像格」是看过数据后的读法、正式判定以合并数为准，这条标注架构线程认可（见上面 B1 一节）。

## 依据：搜索分布在 200 次下也一样「平」（13:5x 补，回答架构线程第 4 问）

原表（`../search-sharpness/README.md`）是 2026-10-07 用 v2 100 次、原版跳费龙内战量的。建造线标 k 用的是 200 级，所以我拿 refit-200 的两份自对弈数据重算：同样是跳费龙比赛版镜像、同一套模型，各取前 300 局，一份 200 次（种子 54800000），一份 100 次（种子 55000000）。脚本 `../search-sharpness/sharpness.py`，代码 6ff1625（C2 装机前；当时镜像走借来的 `ramp-ramp`，和生成数据时相同）。输出在 `../search-sharpness/results_ramp-t_s{200,100}_300games_seed*.txt`。

| 组 | 最高访问占比 100 → 200 | 最高占比 ≥ 0.8 100 → 200 | 搜索 = 贪心首选 100 → 200 |
|---|---|---|---|
| 回合开始 | 32% → 34% | 3% → 5% | 62% → 60% |
| 回合中 | 49% → 52% | 16% → 20% | 70% → 68% |
| 结束回合那一步 | 58% → 60% | 13% → 20% | 98% → 98% |
| 自己第 1～3 回合 | 41% → 43% | 0% → 0% | 85% → 85% |
| 自己第 4～6 回合 | 43% → 45% | 12% → 14% | 66% → 65% |
| 自己第 7 回合以后 | 45% → 48% | 16% → 22% | 64% → 60% |
| 全部 | 43% → 46% | 11% → 14% | 69% → 67% |

- **差别不大**：200 次只比 100 次尖 2～3 个点；推翻贪心率从 31% 到 33%，几乎不变。按回合位置的规律（回合开始最平、推翻最多；结束回合那一步几乎不推翻；第 7 回合以后推翻最多）完全一样。
- 和原表（原版跳费龙、v2 100 次，全部 41% / 10% / 68%）也接近。
- 所以 B1 / B2 的依据在 200 级照样成立，用 200 级标 k 没问题。
- 唯一变化稍大的是第 7 回合以后：最高占比 ≥ 0.8 从 16% 到 22%，推翻率从 36% 到 40%。后期的决策点在多给次数后，既更常收敛，也更常推翻贪心。这和「后期决策难、值得多给次数」的设计方向一致。
