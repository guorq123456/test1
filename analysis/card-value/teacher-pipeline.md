# 老师数据流水线：按对局组合复用（2026-10-07）

手牌条件价值的老师数据，每个对局组合产一份，学生拿它训练。做法和跳费龙镜像的 1200 条 + G_end 400 条一样（见 `README.md`）。定稿方案是架构分支的 `docs/hand-value-design.md`：真值脱离评估器族，G_end 为主，G_next 做方差缩减。

## 1. 每个对局要准备什么

| 输入 | 说明 |
|---|---|
| 自对弈记录 | 当前 bot 在这个对局上的自对弈，`learn.netdata --agent <bot> --explore 0`，每行一局，带双方卡组和全部动作。条数不少于 300 局，抽样从这里抽。 |
| bot | 打两支的 bot：这个对局当前的 v2 等价物，即该对局的 ENDED / ACT 拟合加 `+plan+learned`。`realized.py` 里现在写死成 `mcts:100+plan+learned+phased`（`V2`）；接新对局时改成参数 `--bot`。 |
| 裁判 | G_next 用的强搜索，现在是 `mcts-raw:400+learned+phased`（`JUDGE`），同样改成参数 `--judge`。 |
| 老师 | 1 号的 `CrossTurnAgent`（`keep_value`），现在的设置是重新搜索 100 次、我方下回合用 30 次搜索。 |

记录里不需要额外保存分支随机数种子：每一项的种子由（记录文件，`--seed`，抽样序号 n）唯一确定，见第 2 节，重跑能完全复现。

## 2. 抽样和随机化

- **抽位置**：
  - 按 `--seed` 建一个随机数源，先在记录里均匀抽一局，再在这局里均匀抽一个"自己回合的第一个决策"（`turn_starts`）。
  - 有的位置主线一张牌也不打，所以先抽 2 倍再筛。
  - 第 n 个候选的项种子是 `seed × 100000 + n`。
- **抽牌 c**：老师搜出的主线里，这回合要打的牌随机挑一张。
- **确定化**：第 j 个确定化用 `Random(项种子 × 1000 + j)`：重洗我方牌库、重分对手手牌和牌库、重设引擎随机数种子。两支用同一个确定化（clone），双方 bot 的种子也相同（`项种子 × 1000 + 10j` 及其 +1、+3）。这就是同随机数配对。
- **两组**：确定化分成独立的两组（前一半、后一半），用来估噪声天花板和去衰减相关。

## 3. 每一项量什么

| 字段 | 含义 | 次数 |
|---|---|---|
| `T`, `se` | 老师：这回合留着 c 减主线，推演过对手回合和我方下回合。用老师自己的确定化。 | 8 个确定化 |
| `Q` | 对照：一回合树里，"不打 c 的最好一条线"减"打 c 的最好一条线" | 1 棵树 |
| `G`, `G1`, `G2`, `G_samples` | G_next：bot 打完这回合（一支禁打 c），bot 打对手回合，下回合开头由裁判判绝对胜率，两支相减 | 2 组 × 4 |
| `G_end`, `G_end1`, `G_end2`, `G_end_samples` | 真值：同样的确定化和种子，两支都由 bot 打到终局，胜 1 / 平 0.5 / 负 0，两支相减 | 2 组 × 16（K=32；第一轮可以先 K=8） |
| `seed`, `i`, `turn`, `own_turn`, `first`, `card` | 项种子、动作下标、回合、自己第几回合、是否先手、c 的卡号 | |

接新对局时每行再加两个字段，只当元数据用来分组，**不进学生的输入**：
- `pairing`：比如 `"elf-t/ramp-t"`；
- `records`：记录文件名加哈希。

学生的门控用 goldfish 剖面，不用卡组 id（架构线程 2026-10-07 的 general-bot-plan，以及手牌价值方案第 3 节的修改）。

## 4. 每个对局多少条

- **先 800 条。**
- 两个判据的区间太宽，就加到 1200 条，不要先缩：
  - r_dis(G_end, G_next) 的自助区间跨过 0.6；
  - Spearman(T, G_end) 去衰减后的区间宽度超过 0.4。
- 加条数是在同一个 `--seed` 下续跑（`--items 1200`，已量过的种子会自动跳过）。新加的 400 条和前 800 条来自同一个抽样序列。
- G_end 的 K：K=8 时信度只有约 0.28（跳费龙镜像 400 条），所以生产标签用 K=32，按 Spearman–Brown 信度约 0.6。G_next 当控制变量：G_end − β·(G_next − 均值)，β 用这个对局自己的数据估。

## 5. 算力（跳费龙镜像的实测，4 个工作进程）

- `realized.py`（T、Q、G_next）：1200 条大约 2.5 小时，中间有别的任务抢 CPU。
- `realized_end.py`，K=8：400 条约 1 小时。K=32 是 4 倍。
- 一个对局 800 条，K=32 全套，单机大约 13～15 小时。10 个对局组合按这个乘。
- 机器不够时可以先 K=8 出第一个答案，再在后台补到 K=32（和这次跳费龙镜像的顺序一样）。

## 6. 跑法

```
# 1) T、Q、G_next（对局的自对弈记录，800 条）
cd <svsim checkout> && PYTHONPATH=.:<test1>/analysis/card-value python3 <test1>/analysis/card-value/realized.py \
    <对局的自对弈记录.jsonl> --items 800 --k 4 --research 100 --next-search 30 --seed 1 --workers 4 \
    --out <对局>_realized.jsonl
# 2) G_end（同一批项，K=32）
PYTHONPATH=.:<test1>/analysis/card-value python3 <test1>/analysis/card-value/realized_end.py \
    <同上的记录> --rows <对局>_realized.jsonl --items 800 --k 16 --seed 1 --workers 4 --out <对局>_end.jsonl
# 3) 报数
python3 analyse.py <对局>_end.jsonl --target G_end        # T 在 Q 之外有没有信息（偏相关、AUC）
python3 end_vs_next.py <对局>_end.jsonl --boot 2000       # 交叉半组的真值相关：G_end 对 G_next、T 对 G_end
```

## 7. 每轮报什么（手牌价值方案第 1、4 节）

- Spearman(T, G_end)：原始值，加交叉半组去衰减后的值和区间。
- r_dis(G_end, G_next)：原始 r、两边的两组一致度、去衰减值和区间（这个对局 G_next 能不能做降噪）。
- Salem 80 回合留牌 AUC：只有跳费龙镜像有，用 `teacher_eval.py` + `report.py`。学生过了单回合 Q 对照（70%）才接入搜索。其他对局没有 Salem 的标签，只报上面两个数。
- 迭代时再报 Spearman(T_new, T_old)，看标签稳定了没有。

## 8. 已知的限度

- 两支动作一旦不同，引擎随机数的消耗就分叉了。同随机数法只能做到这里。
- G_end 是相对当前 bot 的：bot 不会用的牌，留着也兑现不了，所以标签会低估。每轮用新 bot 重新产标签（迭代回路）就是为了这个。
- 为什么要交叉半组：G_next 和 G_end 用同一批确定化，到下回合开头之前走同一条路，两者共享噪声。直接相关会偏高，原式去衰减会超过 1，所以去衰减一律用交叉半组。
- 老师只在"主线要打的牌"上量，从来不打的牌（例如一直留在手里的收益牌）不会被抽到。要补的话，抽牌规则可以加一类"手里有、主线不打"的牌，按对局另开一批。
