# 视野修正标签的候选 A、B：门的预注册（架构线程 2026-10-10 07:18Z、07:33Z 布置；写在候选做出来、任何门的对局之前）

**条件**：对手卡表已知（牌序、手牌未知）。

**起因**：M5（`README-m5.md`）里，最大 PP 和手牌按 G_end 定的价格明显高于 T 和现装模型；SEP 是模型给得比 T 和 G_end 都高。建造线据此做一个候选：
- 标签改成 L″ = L + Σ_r (price_G,r − price_T,r) · Δr，r ∈ {最大 PP，手牌张数，SEP}；
  - L 是第 1 步的标签；Δr 是这一对打法在 r 上的差（16 个 T 回合末的平均差，同 M5）；
  - 价格按半交叉拟合：一半的标签用另一半的价格（`m5/m5_halves.json`：只用训练开头、不含 end，按局号奇偶分半）。
- 然后重拟原版跳费龙镜像的回合末（ENDED）模型，其余照第 1 步候选的做法。ACT 模型不动。
- 候选的目录名和提交号由建造线定，开门前补在这里。

## 开门前的检查（在留出开头上；任一条不过就不开门）

用 `prices.py --pregate <候选的规格>`，在第 1 步的 179 个留出开头上（不含 end，505 对）：
1. **价格往 G_end 那边动**：候选的 ΔV 在 M5 的同一个回归量矩阵上回归。最大 PP 和手牌两项的价格都要高于现装模型在同样对子上的价格（G_end 给这两样的价格都高于模型）。看点估计。
2. **排序不变差**：和 ΔT 同号的比例（ΔT = 0 的不算，ΔV = 0 算一半），候选减现装不低于 −1 个百分点。
- 冒烟（候选 = 现装自己）：两边价格相同、同号率都是 79.0%（442 对，和第 1 步留出读数的 0.787 对得上）→ 第 1 条「否」→ 不开门。工具按预期工作。

## 门

- **A** = `mcts:N+plan+learned+phased=<候选目录>`；**B** = `level-strong`。
- **等算力**：只换权重、特征不变，所以每决策的毫秒应该一样。照惯例复核：
  - 门命令 `--fixed --max 40`，20 对，种子 66899000～66899019；
  - A ÷ B 的每搜索决策毫秒比在 0.97～1.03 之外，就修一次 N = round(200 ÷ 毫秒比)。
- **门**：原版跳费龙镜像直接对打（`--deck ramp --opponent ramp`），`--fixed --max 600`，**定长 300 对**，种子 **66800000～66800299**（库 66800000）。
- **判定**：单门规矩 (S)，下沿 > 50%。**没有确认门**。装机要 Salem 本人的话。
- **过的概率**（跳费龙镜像的对分标准误按以往门取 1.4～1.75 个百分点）：真实效果 0 / +1 / +3 个百分点时，约 2.5% / 8%～11% / 40%～57%。
- **J40**（架构线程）：门过，置信 30%。
- **在哪里跑**（架构线程 07:33Z 改的，在候选做出来之前标在这里）：分析线的容器，3 个进程，排在 M4 和 `+lethal3` 门之后。复核和门在同一台机器、同样的进程数下跑。
- **每局进化次数**（J41 的对照，不另花算力）：
  - 用附带脚本 `lethal2_games.py play` 以门的种子重打、留记录（同一台机器上逐局和门相同）；
  - 再用 `read --package none` 数每局进化次数：A（候选）和 B（现装 `level-strong`）各一个数，A ÷ B 的比值，区间按对重抽 2000 次。
  - A 这一门只报，不设 J。
- 照报：A 先手 / 后手的分数；两局走法完全相同的对数；门的毫秒比。

## 候选 B：A 再加「我方随从张数」（架构线程 07:33Z；写在 B 做出来之前）

- **标签**：L‴ = L″ + (price_G − price_T) · Δ我方随从张数，同样按半交叉拟合。M5 的控制项里，G_end 给我方随从张数 +0.72、T 给 −0.53。我方随从属性和、对手 HP 先不加。
- **开门前的检查**：同 A 的两条（最大 PP 和手牌价格都高于现装；和 ΔT 同号的比例不低于现装 1 个百分点以上）。没过就跳过它的门，下一个空位顺延。
- **门**：设计和 A 一样。
  - 原版跳费龙镜像，`--fixed --max 600`，**定长 300 对**，种子 **66900000～66900299**；
  - 复核 20 对，种子 66999000～66999019，毫秒比在 0.97～1.03 之外就修一次 N；
  - 判定 (S) 下沿 > 50%。
- **在哪里跑**：同 A，分析线的容器，3 个进程，排在 A 的门之后。
- **判断**（架构线程）：

  - **J41**：B 每局进化次数比现装少 10% 以上，置信 55%。从 B 这一门的对局里直接读，不另花算力：附带脚本重打留记录，看「每局进化次数 A ÷ B」的点估计是否 < 0.90（门里 A 是候选 B，B 是现装 `level-strong`）。A 那一门的同一个数作对照。
