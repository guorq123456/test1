# 视野修正标签的候选 A、B：门的预注册（架构线程 2026-10-10 07:18Z、07:33Z 布置；写在候选做出来、任何门的对局之前）

**条件**：对手卡表已知（牌序、手牌未知）。

**起因**：M5（`README-m5.md`）里，最大 PP 和手牌按 G_end 定的价格明显高于 T 和现装模型；SEP 是模型给得比 T 和 G_end 都高。建造线据此做一个候选：
- 标签改成 L″ = L + Σ_r (price_G,r − price_T,r) · Δr，r ∈ {最大 PP，手牌张数，SEP}；
  - L 是第 1 步的标签；Δr 是这一对打法在 r 上的差（16 个 T 回合末的平均差，同 M5）；
  - 价格按半交叉拟合：一半的标签用另一半的价格（`m5/m5_halves.json`：只用训练开头、不含 end，按局号奇偶分半）。
- 然后重拟原版跳费龙镜像的回合末（ENDED）模型，其余照第 1 步候选的做法。ACT 模型不动。
- 候选的目录名和提交号由建造线定，开门前补在这里。

## 候选 A 到了（2026-10-10 07:37Z；补在门的任何对局之前）

- **目录** `cand-th-ramp-ramp`，建造线 **850237d**（没装）。智能体串 `mcts:N+plan+learned+phased=cand-th-ramp-ramp`。做法在它的 `svsim/learn/phased_models/cand-th-ramp-ramp/README.md` 和 `analysis/horizon/fit_h.py`。
- **和上面写的不同的一处（照记，不改判定）**：分半交叉拟合按**开头号 k 的奇偶**分，不是本文件写的「按局号奇偶」（`m5/m5_halves.json` 的分法）。
  - 回归本身照 M5 的 `fit`：只取训练开头、不含 end，五项资源加八项控制，G_end 按 K 加权、T 不加权。老师重跑的例子（不在 M5 里的开头）用全部训练开头的价格。
  - 两种分法的差别：按 k 分，同一局的几个开头会落在两半里，相关的结果会进到对方那一半的价格里，交叉拟合就没有按局分那么干净。按 k 分时两半的 G − T（最大 PP +5.64 / +5.17）比按局分（+2.97 / +8.04）接近得多，和这个说法一致。
  - 对门的影响：门比的是做出来的这个候选本身，判定照旧。留出开头和训练开头在第 1 步就是按局分开的，所以下面开门前的检查不受影响。
- **开门前的检查**：本容器，svsim 850237d，`prices.py --pregate`，原样输出在 `horizon/pregate_A.txt`：
  - 留出开头的对子 505 个，价格写成「候选 / 现装」：最大 PP +5.81 / +1.20，手牌 +2.84 / +2.09，SEP −1.10 / +2.13，剩余 EP +0.89 / +0.79，剩余 PP −1.78 / −1.95。
  - (1) 是：最大 PP、手牌的价格都高于现装。
  - (2) 是：和 ΔT 同号的比例，442 对上候选 79.6%、现装 79.0%，差 +0.7。
  - 结论：**开门**。数字和建造线自己报的逐项一致。它的同号率 73.76% / 73.08% 是把 ΔT = 0 的对子也算进分母（505 对），两边差同样是 +0.7。
- **N**：建造线量的是第 1 步前 60 个开头的整回合，每决策毫秒比 0.956，它建议 N = 200。这道门照上面写的规矩：先用 N = 200，在本容器做 20 对复核；比值在 0.97～1.03 之外才修一次。
