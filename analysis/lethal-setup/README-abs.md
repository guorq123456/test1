# `+abs`（回传和平均改用绝对胜率）：门前读数和等算力门的预注册（架构线程 2026-10-10 09:02Z 布置；写在候选做出来、任何读数和对局之前）

**条件**：对手卡表已知（牌序、手牌未知）。

**起因**：建造线查清了题 1 两个数为什么差那么多（0.92 对 0.088）。
- 搜索里的价值是中心化的：σ((score − center) / 8)，center 是「什么都不做就结束回合」的分数，题 1 是 −37.92。两个数是同一个局面的两种刻度。
- 架构线程的推断：在中心化的 σ 空间里对确定化取平均，落后时搜索会变得怕风险，优化的是「输得别太难看」，不是赢的机会。

**候选 `+abs`**（建造线做完 `+complex` 后接着做；目录名、提交号、智能体串、是否叠在 `+complex` 上，开门前补在这里）

- 选子节点时用 min–max 归一化。

## 门前读数（建造线读，分析线判）

- **读法**：
  - 原版跳费龙镜像，用现装自对弈的局面。在每个搜索决策上，`+abs` 和现装用同一个种子各搜一次，看根节点选的走法是否不同。
  - 按决策开头局面的绝对胜率 σ(score / 8)（现装评估）分三档：< 0.15、0.15～0.85、> 0.85。
- **J47**（架构线程，置信 **60%**），两条都要成立：
  1. 根选择不同的总比例 ≥ 3%；
  2. < 0.15 和 > 0.85 两档**合起来**的不同比例，至少是 0.15～0.85 那档的 2 倍。
- 照报：每档的决策数、不同数、比例；总决策数；两档分开各自的比例。
- 「两档合起来」是分析线对原话「这两档的比例」的读法。架构线程如果要两档各自都 ≥ 2 倍，在建造线读出之前说，这里改并标出。

## 门（设计同 `+complex` 的门）

- **A** = `+abs` 的智能体串（建造线给）；**B** = `level-strong`（N_B = 200 起）。
- **原版跳费龙镜像**直接对打，`--fixed --max 600`，**定长 300 对**，种子 **67200000～67200299**。
- **等算力复核**：
  - 门命令 `--fixed --max 40`，20 对，种子 67299000～67299019，看门自己的每搜索决策毫秒 A ÷ B；
  - 同时用 `turn_cost.py` 量第 1 步训练开头的整回合毫秒 A ÷ B；两个比值相差 3 个百分点以上就用整回合的；
  - 用的那个比值在 0.97～1.03 之外，就修一次 N_B = round(200 × 比值)。
  - `+abs` 只改回传和选子节点的算法，按理每决策毫秒不变。如果它叠在 `+complex` 上，就照 `+complex` 门的同一套办法。

- **在哪里跑**：分析线的容器，3 个进程，排在 `+complex` 的门之后。J47 不过也照样开门，J47 只是门前的行为读数，不是开门条件。
