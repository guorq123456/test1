# 运营：斩杀兑现（M1）、铺垫（M2）、方向（M3、M4）：预注册（架构线程 2026-10-10 02:13Z、02:17Z 布置；写在任何对局和计数之前；只报，不装）

**条件**：对手卡表已知（牌序、手牌未知）。

**起因**：Salem 02:11Z（海盗谜题那条线）的原话：

> bot处理这样的复杂局面能力非常差，因此导致中盘能力很差——现有训练提升不上去bot强度，我认为类似的局面能快速得到最优解是一部分水平——但如何通过运营创造出这样的局面才是2000+CR玩家间的差距，而bot现在完全没有这方面能力

- 他的谜题：海盗皇家，8 PP，对手 10 HP。`find_lethal` 找到正好 10 点的斩杀；`level-strong` 三个种子三次都停在对手 4 HP。原因建造线在查。
- Salem 02:16Z 又补了一句：「运营也不只是下回合斩杀概率的量——如何判断当前局面发展方向尝试找到对局最可能赢的方向是运营更重要的方面」。所以 M2 留着，只是其中一部分；主要的测量改成「方向」（M3、M4，见后）。
- 前两件事分开量：
  - **M1 战术**：有斩杀时打没打出来；
  - **M2 运营**：回合末给自己下回合留下斩杀的机会有多大，Salem 和 bot 比。

**两者的工具差别**（照记）：
- `level-strong` 自带的斩杀筛（`LethalAgent`）是 2000 节点、`screen=200`，外加 near 规则；
- `find_lethal` 的默认是 20000 节点、8 个样本、不筛。
- 这里「有斩杀」一律按 `find_lethal` 默认参数的 `sure`：一条不经过任何随机节点、无论牌序和随机结果都赢的线。
- 本机量过（第 1 步自对弈 80 个回合开头）：`find_lethal` 默认参数平均 2.2 秒（中位 0.07，p90 9.9，最长 15），13/80 没在 20000 节点内跑完。

## M1：斩杀兑现（建造线数，分析线读）

**定义**（分析线 02:2xZ 提给建造线，等它确认；有改动在任何计数之前标出来）
- **单位**：自己回合的开头，即每回合第一个主阶段决策（同学生数据）。
- **来源**：两边都是 `level-strong` 自己打的局，结果直接看记录。
  - 第 1 步的 1000 局自对弈（RC 6f11111，原版跳费龙镜像）；
  - 建造线的 golden 记录对局（cefd7c1，五个对局组合；具体哪些局由建造线报）。
- **分母**：真实局面上 `find_lethal(state)`（默认参数）返回 `sure=True` 的开头。它用对手的真实手牌；自己回合里对手手牌几乎不起作用。
- **漏掉**：记录里，这个回合结束前行动方没有赢下比赛。
- **份额** = 漏掉 ÷ 分母。
  - 区间按局重抽 2000 次（种子 0），同一局里的几个开头一起抽；另报 Wilson 区间。
  - 两个来源合起来为主，分来源（golden 再按对局组合）照报。
- **只报的诊断**：
  1. `level-strong` 自己的筛在这个开头上判不判 sure；
  2. 漏掉的回合里，结束回合前最后一个决策上 `find_lethal` 还判不判 sure：判 sure 就是「放着没打」，不判就是「先走坏了」；
  3. `complete=False` 且没找到 sure 的开头数：这些可能漏数了，不进分母。
- **J30**（架构线程）：份额 ≥ 3%，置信 50%。看点估计。

## M2：铺垫，Salem 对 bot（P_NL）

**量什么**：回合末的 P_NL = 我方下回合有斩杀的概率。
- 用建造线的 `next_lethal_prob(state, k, seed, reply_spec="level-strong")`：
  - 对手在 k 个确定化上用 `level-strong` 打完它的回合；
  - 然后在我方下回合开头跑 `find_lethal`；
  - sure 记 1。
- 细节等建造线确认（同上，有改动在任何运行之前标出来）：
  - 传入的是我方 `EndTurn` 已执行的局面；
  - 确定化从我方视角；
  - 下回合开头用默认参数，不 sure 记 0；
  - 对手回合里我方被打死记 0，我方赢了记 1。

**开头和两条线**（第 0 步的数据，RC 84d735e，读于 28a57e5）
- **开头**：Salem 27 局里轮到他的 235 个回合开头（第 0 步的 k = 300～534）。已经去掉他当回合斩杀的回合，以及记录停在回合中间的回合。
- **Salem 的线**：他这回合的记录（第 0 步 plans 里的 salem）。
- **bot 的线**：`level-strong` 从同一开头在真实局面上打完这回合（第 0 步 plans 里的 bot，种子 65960000 + k）。
- **怎么得到回合末**：两条线都在真实开头上按存下的动作逐步重放。某一步不合法就记复现失败，那个开头不算，照报个数。
- **两条线相同的情况**：第 0 步去重时 Salem 的线有 74 个开头和 bot 的回合末相同（合并进 bot）。这些开头两条线是同一个局面、同一个种子，差恰好为 0，只算一次。另外 161 个开头两条线不同。
- **当回合就赢了的线**：bot 的线可能在这一回合直接赢（Salem 自己当回合斩杀的回合已去掉），这时 P_NL 记 1。个数照报，另报去掉这些开头的结果。

**参数**
- **k = 16**：每个确定化约 3 秒（RC 上约是本机的 1.2 倍）；最多 396 个不同的回合末 × 16 ≈ 6300 个样本，RC 12 进程约 30～40 分钟，在一小时之内。
  - 如果建造线的工具冒烟显示每样本超过本机 4.5 秒，改用 k = 12，在运行之前标出来。
- **种子**：第 i 个开头（i = 0～234，即 k − 300）传 seed = **66500000 + 100 i**，两条线同一个 seed（配对）。确定化和回复 agent 的种子由工具从 seed 派生。

**报什么**（读法写在任何运行之前）
- 两条线各自的平均 P_NL。
- **配对差** P_NL(Salem) − P_NL(bot) 的平均，区间按开头重抽 2000 次（种子 0）。
  - 235 个开头为主，只算两条线不同的 161 个也报。
- **按回合数**（Salem 自己第几回合，即第 0 步 starts 的 own_turn）：
  - 前期 1～3（81 个开头）；
  - **中盘 4～7（103 个），单独一行**；
  - 后期 8 及以后（51 个）；
  - 另附逐回合的表。
- 任一条线 P_NL > 0 的开头占比。
- Salem > bot 的占比、bot > Salem 的占比（按 P_NL 严格比）。
- **J31**（架构线程）：平均差 > 0 且区间不含 0，置信 65%。
  - 架构线程的理由（推断的部分）：两回合老师用 bot 走我方下一回合，而 bot 自己会漏斩杀，所以铺垫的线被低估。
- 照记：P_NL 只量了「留下斩杀机会」这一面，不量这条线给对手留下了什么。一条线 P_NL 高，不等于它整体更好。

**种子库**：66500000～66599999（实际用到 66500000～66523499 一带，加上工具在每个 seed 之后派生的）。M1 不用种子（计数，`find_lethal` 用它自己的 seed 0）。下一个空位 **66600000**。

**重放核对**（`setup_prob.py check`，本机，svsim c4b887f；不算 P_NL，在任何 M2 运行之前）
- 235 个开头，两条线都在真实开头上逐步重放到回合结束：复现失败 0，当回合就赢的 0。

## M3：不同的那些回合，Salem 往哪个方向走（只用现有数据；描述，不设 J）

**开头**：第 0 步 Salem 局里他的线自成一个候选的 **85 个回合**（RC 84d735e；读于 28a57e5，J21 用的就是这 85 个）。每个都有 T（2 个种子 × 8 个确定化）和 G_end（每条线 32 局）。
- 照记：另有 76 个开头，Salem 的线和 bot 不同，但和别的候选（second、save 等）走到同一个回合末，第 0 步没有给它们单独打 G_end。这 76 个不在 M3 里。

**回合末局面**：两条线都在真实开头上重放（同 M2 的核对，0 失败）。
- 取结束回合之前的局面，记未用的 PP；
- 再用 `search.evaluate.after_end_of_turn` 结算回合末效果、不开始对手回合（同 ENDED 模型看到的），其余字段都在这个局面上取。

**描述的差**（Salem − bot；只用通用字段，不用任何按卡的估值表）
- 对手主战者 HP；
- 对手场上随从：张数、属性和（攻击 + 当前体力）；对手护符张数；
- 我方场上随从：张数、属性和；我方护符张数；
- 我方手牌张数；
- 未用的 PP；EP、SEP；
- 通用计数：墓地（shadows）、本局进化次数（evolutions）、我方护符倒计时之和、领袖区（crests 等）张数。

**归类规则**（写在看任何差之前；每条都是「Salem 比 bot 多做了什么」）
- **race**（多打脸）：对手 HP 的差 ≤ −2。
- **clear**（多清场）：对手随从属性和的差 ≤ −3，或对手随从张数的差 ≤ −1。
- **develop**（多铺场）：我方随从属性和的差 ≥ +3，或我方随从张数的差 ≥ +1。架构线程的单子里没有这一类；它是和清场相对的另一个常见方向，我方场面也在要描述的字段里，所以单列。
- **conserve**（多留资源）：手牌的差 ≥ +1，或未用 PP 的差 ≥ +2，或 EP 的差 ≥ +1，或 SEP 的差 ≥ +1。
- **setup**（多铺垫）：P_NL 的差 ≥ +0.125（16 个确定化里多 2 个），等 M2 出来以后加。
- 恰好一条成立 → 归那一类；两条及以上 → **mixed**（记下是哪几条）；一条都不成立 → **small**（差都在阈值以下）。
- 先报没有 setup 的版本；M2 出来后，再报加上 setup 的版本。

**报什么**
- 各类的个数（mixed 再列组合）；
- 每类里 T 偏向 Salem 的比例（16 个 T 的平均严格更高，同第 0 步）和 G_end 偏向 Salem 的比例（32 局的平均，相等算一半，同第 0 步）；
- 每个描述字段的差的平均和中位数。
- 用途：看 bot 在哪个方向上判断错。描述，不判。

## M4：按方向打到终局（建造线写工具；分析线读）

**做法**
- 从 M3 那 85 个开头的两个回合末（Salem 的线、bot 的线）出发，各打到终局 K 次：
  - 我方在剩下的整局里一直照一个方向走；
  - 对手用 bot 走（具体见下）。
- **方向**：候选风格的多回合版本，由建造线写成工具：
  - race：斩杀时钟；
  - clear：新写；
  - conserve：keep / save；
  - default：不加方向。
- 一条线的分数 = 各方向胜率的最大值；取到最大的那个方向就是这条线选的方向（打平时按 default、race、clear、conserve 的顺序取前一个）。
- 每局都从回合末重新确定化隐藏信息（我方视角），每局一个种子。同一开头的两条线、四个方向用同一批 K 个种子（配对）。

**参数**（分析线定）
- **打到终局用的 agent**：对手和各方向底下的搜索都用第 0 步 G_end 的 bot `mcts:100+plan+learned+phased`，和第 0 步的 G_end 一致，也比 `level-strong` 省一半。
- **K = 12**：85 × 2 × 4 × 12 = 8160 局。按 G_end 每局约 2.8 CPU 秒、方向策略再加约五成算，约 3.4 万进程秒，RC 12 进程约 50 分钟。
  - 建造线的工具冒烟以后，如果估计超过 75 分钟，改用 K = 8，在运行之前标出来。
- **种子**：第 i 个开头（85 个按第 0 步的 k 排，i = 0～84）用 **66540000 + 500 i**，由工具派生每局的种子。

**报什么**（读法写在任何运行之前）
- 分数偏向 Salem 的比例：Salem 的分数严格更高算 1，相等算一半。
- **配对差**：每个开头「分数偏向 Salem」减「T 偏向 Salem」，平均和区间（按开头重抽 2000 次，种子 0）。
- 和第 0 步 G_end 胜者的一致率：两者都不打平的开头上，偏向同一边的比例。
- 两条线各方向的平均胜率；选中方向的分布；和 M3 归类的交叉表。
- **J32**（架构线程）：在这 85 个回合上，这个分数偏向 Salem 的比例高于 T 的 54.1%，置信 55%。看点估计。

**要先写下的局限**（架构线程）
- 在有噪声的估计上取最大，会往上偏；两条线偏得一样多。
- 整局固定一个方向很粗糙，真人会中途换方向。
- 对手策略是 bot。
