# 运营局面题：从 M4 里自动挑（架构线程 2026-10-10 08:32Z 布置；写在挑选和复测之前）

**条件**：对手卡表已知（牌序、手牌未知）。

**起因**：Salem 离开六个多小时了。挑局面这一步不等他，先自动挑；他回来给了自己挑的局面，再排到前面。题目交给建造线，照海盗题的办法拆：
- bot 的搜索有没有想到 Salem 的打法；
- 评估器怎么给两边打分；
- 搜索加到 15 倍会不会变。

## 1. 候选（只用 M4 已有的行，`m4_rows.jsonl`）

- 85 个开头，只看 **default** 方向。
- 每个开头的分 d = Salem 的线的胜率 − bot 的线的胜率。两条线都从各自的回合末出发，K = 12，用同一批种子。
- 按 d 从大到小排，记第 6 名的 d 为 d₆。
  - d ≥ d₆ + 1/12 的开头直接入选（1/12 = 12 局里的一局）。
  - 剩下的名额，从 |d − d₆| < 1/12 的开头里补，顺序是：M3 归为 mixed 的优先，再按 d 大的优先，再按 k 小的优先。
- 取满 6 个。

## 2. 复测（新种子，配对）

- 这 6 个开头，两条线各打 **K = 48** 局，只走 default 方向。
- 工具和 M4 相同：`direction.py m4run`，svsim 23b317d，双方都是 `mcts:100+plan+learned+phased`。
- **种子**：第 i 个开头（i 是它在 M4 里的号，0～84）用 **67000000 + 500 i**，由工具派生 48 个对局种子。两条线用同一批 48 个种子。
- 每个开头算两个数：
  - 配对差 = 48 个种子上「Salem 的线的结果 − bot 的线的结果」的平均（胜 1、平 0.5、负 0）；
  - 95% 区间：按种子成对重抽 2000 次（随机数种子 0），取百分位。

## 3. 定题

- 入选条件：复测里配对差 > 0，且区间下沿 > 0。
- 入选的按配对差从大到小取前 3 个；配对差相同的，下沿大的优先，再按 k 小的优先。
- 一个都不剩就照实报，**不放宽标准**。

## 交回给架构线程的（每题一份）

- 对局号、全局回合；
- 双方当时的场面和手牌；
- Salem 那回合怎么打的、bot 那回合怎么打的；
- 复测的两个胜率和配对差（含区间）。
- 牌名用常用名。

## 机器和算力

- 分析线的容器，**1 个进程**（`taskset -c 0`，nice 10），和 `+lethal3` 门并行跑。门经 `svsim.tools.host` 固定在 CPU 1～3。
- 6 × 2 × 48 = 576 局，按 M4 的单位成本（每局约 1.5 进程秒）约 15～25 分钟。
- 照记：复测和 `+lethal3` 门同时在跑，可能稍微影响门的毫秒读数。门的 A、B 在同一批对局里同时计时，影响对两边差不多。

## 种子

- 库 **67000000～67099999**：复测用 67000000 + 500 i 起（i = 0～84，每个开头 48 个派生种子）。
- 下一个空位 **67100000**。
- 66900000～66999999 仍是退回、可再分配。

## 建造线拆题的结果和判定（建造线 829ee1d，`analysis/puzzles3/README.md`；架构线程 08:58Z 判）

- **J43 对（3 / 3）**：现装评估器三题都偏向 Salem 的回合末（Salem / bot：题 1 0.726 / 0.088，题 2 0.587 / 0.282，题 3 0.652 / 0.403）。题 1 只对抽到好牌之后的那个回合末成立。
- **J44 错**：三题都不是规划器表达不了某个选择或弃牌步骤。这几回合不是斩杀回合，规划器不参与，搜索把每种弃牌选择都列成合法走法。
- **题 2、题 3 是搜索预算问题**：弃牌选择把根节点的走法数撑大了（题 2 有 56 个，题 3 是金银的弃牌组合 15 个），200 次迭代找不到 Salem 的打法。mcts:400～600 以上能解，mcts:1043 两题都是 8 / 8。
- **题 1 建造线认为是抽牌**：琪米卡入场抽到口人魔（剩下 27 张里 3 张，约 11%），口人魔入场又给了两张赤流；回合开头没有别的办法解掉 11/11 的正义。建造线建议去掉这题，或者把抽牌重新发再测。→ 下面的复测。

## 题 1 复测：预注册（架构线程 08:58Z 布置；写在复测之前）

**条件**：对手卡表已知（牌序、手牌未知）。

**做法**
- 从题 1 的开头（k = 320）出发，每局：
  1. 用本局种子做一次确定化（`svsim.core.view.determinize`，Salem 视角）。Salem 自己的牌堆重新洗过，琪米卡入场抽的那张牌就是从 Salem 剩下的牌堆里重新随机发的；对手的手牌和牌堆也重新猜。
  2. 第一步固定成和 Salem 一样：下琪米卡、选波菈莱（记录里的那个动作）。
  3. 之后由 `level-strong` 打完这个回合（种子同本局）。
  4. 从回合末按 default 方向打到终局：`direction_rollout(…, "default", k = 1, seed = 本局种子)`，双方 `mcts:100+plan+learned+phased`，同 M4 和复测。
- **K = 48**。第 j 局的种子是 `random.Random(67100000)` 依次取的第 j 个 `randrange(2**31)`，和 `direction_rollout(seed = 67100000)` 派生的 48 个种子相同。
- svsim 23b317d（同 M4 和复测），本容器 1 个进程。

**读法**
- **主读数**：「先下琪米卡」这条线的 48 局，逐局配对 bot 原来那条线（下正义、结束）在复测里的 48 局（0 / 48，种子 67003500 派生）。
  - 配对差 = 两条线逐局结果之差的平均（胜 1、平 0.5、负 0）；95% 区间按局成对重抽 2000 次（随机数种子 0），取百分位。
  - bot 原来那条线 48 局全是 0，所以配对差就等于琪米卡线的胜率，区间也一样。
- **另报**：
  - bot 的线用这次的种子（67100000）再打 48 局，和琪米卡线逐局配对，看配对差；
  - 琪米卡抽到口人魔的局数；
  - `level-strong` 打完这回合后，对手的正义还在场上的局数。
- **J46**（架构线程）：先下琪米卡平均下来比 bot 的线好，配对差区间不含 0，**置信 65%**。

## 题 1 复测的结果（2026-10-10 09:1xZ；本容器 CPU 0，1 个进程，和 `+lethal3` 海盗镜像那格的门并行；svsim 23b317d；`puzzles.py p1run / p1read`，输出 `puzzles/p1.txt`、`p1_rows.jsonl`）

**怎么读**（照记，不改判定）
- 平均下来，先下琪米卡比下正义只多约 6 个百分点，区间碰到 0。两条线都几乎必输。
