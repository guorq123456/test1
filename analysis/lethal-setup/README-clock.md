## 门（设计同第 1 步候选和视野候选的门）

- **A** = `mcts:N+plan+learned+phased=<候选目录>`；**B** = `level-strong`。
- **原版跳费龙镜像**直接对打，`--fixed --max 600`，**定长 300 对**，种子 **67500000～67500299**。
- **等算力复核**（在门之前）：
  - 门命令 `--fixed --max 40`，20 对，种子 67599000～67599019，看门自己的每搜索决策毫秒 A ÷ B（N = 200 起）；
  - 同时用 `turn_cost.py --n 300` 量整回合毫秒 A ÷ B。新特征要算「几回合能打死对面」，评估可能变贵，所以整回合这一项要紧。
  - 两个比值相差 3 个百分点以上，用整回合的；用的那个比值在 0.97～1.03 之外，就修一次 A 的 N = round(200 ÷ 比值)，不再复核。
- **判定**：单门规矩 (S)，`pooled.py` 逐对重抽 4000 次的下沿 > 50%。没有确认门。装机要 Salem 本人的话。
- **过的概率**：真实效果 0 / +1 / +3 个百分点时，约 2.5% / 8%～11% / 40%～57%。
- **J55**（架构线程）：门过，置信 **25%**。
- **在哪里跑**：分析线的容器，3 个进程，排在 `+abs0`、`+par=4` 的门之后。
- **照报**：A 先手 / 后手的分数；两局走法完全相同的对数；门的毫秒比；复核的两个比值和最终的 N。

## 排序集：Salem 回合末的大尺子（架构线程 10:55Z 布置；写在任何打分之前；只作描述加判断，不是开门条件）

**条件**：对手卡表已知（牌序、手牌未知）。

**范围**：M4 的 85 个开头（`m4_rows.jsonl`）。

**每个开头记下**
- **G_end**：Salem 的线和 bot 的线（第 0 步 bot 的计划）各自的 default 方向胜率，取自 M4（K = 12）。复测过的 6 个（320、313、445、455、329、518）改用复测值（K = 48，`puzzles/retest_rows.jsonl`）。ΔG = Salem − bot。
- **评估器打分**：两个回合末各打一个分。
  - 回合末和打分都照建造线 `analysis/puzzles3/ops.py` 的 `turn_end` / `judge_end`：
    - 打完这回合的动作，不执行结束回合，先结算回合末能力，对手还没开始；
    - 用评估器的回合末模型给行动方打分 σ(z / SCALE)；对局已经结束的记 1 / 0。
  - ΔV = Salem − bot。评估器默认是现装（`level-strong` 的权重），换成任何智能体串的权重都能用。
- **M3 的类别**（`m3_rows.jsonl`）。
- 存成 `ranking/rows.jsonl`。候选到了，只加一列候选的打分，别的不动。

**读法**
- 只看 **|ΔG| ≥ 0.10** 的开头。
- **同号率**：ΔV 和 ΔG 同号的比例，ΔV = 0 算一半；区间按开头重抽 2000 次（随机数种子 0）。
- 再按 M3 的类别分开报（每类的开头数、同号率）。
- 候选到了，在**同一批开头**上算候选的同号率、候选减现装的差，差的区间也按开头成对重抽 2000 次。
- **J56**（架构线程，置信 **40%**）：斩杀时钟候选在这个集上的同号率比现装高 **5 个百分点以上**（看点估计）。

**机器**：本容器单进程，svsim ab63f3c（现装的权重和 23b317d 相同）。打分是确定的，不用种子库。
