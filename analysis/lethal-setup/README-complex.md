## 结果和判定（2026-10-10 10:2xZ；本容器 3 个进程，svsim b9db716；`analysis/gates/complex/gate.jsonl`、`gate_pooled.txt`）

**条件**：对手卡表已知（牌序、手牌未知）。

- **核对**：300 对，种子 66900000～66900299 齐，用时 722 秒。
- **A = `level-strong+complex` 对 B = `mcts:207+plan+learned+phased`：48.5%**
  - 正态区间 45.5%～51.5%；`pooled.py` 逐对重抽 45.5%～51.5%；CR 约 −14（−43～+14）。
  - **(S) 下沿 > 50%：不过。**
  - **J45**（置信 35%）**→ 错。**
- 照报：
  - A 先手 59.0%、后手 38.0%；两局走法完全相同的对 13 / 300。
  - 门里每搜索决策毫秒比 0.964。B 按整回合配平以后多了 3.5% 迭代，所以按决策平均 A 显得便宜。
  - 复核：门的 20 对 1.003，整回合 1.036 → N_B 207。
- **怎么读**（照记，不改判定）
  - 题库里 `+complex` 解开了题 2、题 3（6 / 6，现装 0 / 6）。档位分歧的测量也说明宽决策上 200 次和 1043 次分歧最大（`README-gap.md` 第 2 件）。
  - 但把同样的总算力从窄决策挪到宽决策，在整局对打里没有换来胜率：点估计 −1.5 个百分点，区间 −4.5～+1.5。
  - 推断：窄决策上省下的那些迭代并不是白花的。走法 ≤ 3 的决策两档几乎不分歧，但它们的搜索值还要被同一回合后面的决策和斩杀检查用到；或者宽决策上加的那点预算（平均约 21 × 走法数）还不够跨过 1043 那样的差距。没有检验。
