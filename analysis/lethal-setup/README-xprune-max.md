## 顺手报：被剪掉的是不是「最强」档自己会选的（只作描述）

- 架构线程要的是：A 侧剪枝起作用的弃牌决策里，B 的选择落在被剪掉那部分的比例。
  - 门不留走法记录。就算重打留了记录，A 和 B 走到的局面也不同，任何记录里都没有「B 在 A 的局面上会选什么」。要得到它，得在 A 的局面上另跑 B 的搜索，那就不是「从日志里拿」了。
  - 所以照「拿不到就不报」，原样那个数**不报**。
- **改报一个能从记录里拿到的近似量**（先写在这里，再算）：
  - 附带重打：`lethal2_games.py play` 以门的种子、同样的两个智能体串重打 300 对、留记录，再用 `read --package none` 逐局核对得分和门一样（同强档那次）。
  - 在记录里，取主阶段、合法走法 ≥ 2、`XPrune(3, 3, "cost")` 会剪掉至少一个合法走法的决策（「剪枝起作用」，定义同 `README-xprune.md`），A、B 分开数：**这一方实际选的那步，是不是正好会被剪掉**。
  - **B 侧**就是：「最强」档如果开着 xprune，它自己的选择有多少会被剪掉。这是建造线那个安全率（1043 的报告集上 27%）在对局里的版本。
  - **A 侧**是核对：搜索在根节点上不会选被剪掉的走法，只有规划器 / 斩杀那条路直接给出走法时才可能出现，应该接近 0。
  - 同样的数也在强档那道门已有的附带重打记录上算一份（68200000，B = `level-strong`）作对照。脚本 `xprune_count.py`，加的这一列写在这份预注册之后、算之前。
- **重打在哪里跑**：
  - 最强档重打和门本身差不多贵（约 1 小时）。先问建造线的容器能不能和门同时跑（N 定了以后对局只取决于代码和种子）。
