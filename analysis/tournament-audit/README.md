# 比赛卡组的卡牌脚本核对（2026-10-07）

牌名按对照表（架构分支 469f714 的 analysis/card-glossary.md），写常用名（费用身材）。

**范围**：架构线程给的四套比赛卡表标准版（48ebbee 的 analysis/tournament-decks-2026-10-07.md）：连击妖、机锋（宇宙鱼）、跳费龙比赛版、旗皇比赛版。加上每套的自由位，一共 103 张不同的卡。四套之间有共用的卡，按卡组计是 107 条。核心卡（每套固定的那部分）57 条：连击妖 7、机锋 31、跳费龙 10、旗皇 9。

**做法**：
- 官方卡面：用 svsim/tools/fetch_cards.py 拉官网数据，中英文的本体面和进化面加上官方 Q&A。这份数据只放在本地，不提交，因为是 Cygames 的内容。
- 核对对象：1 号分支 2353f07 的 svsim 脚本，每张卡逐条核。核对项：发动时机、目标和谁来选、数值、条件（连击、爆能强化、吟唱、纹章、信仰、牌组无重复、协作等）、进化面和超进化面、关键词和身材，以及它生成的衍生卡和纹章。
- 顺序：先核心卡，再标准版其余，最后只在自由位出现的卡。分五路并行做，机锋卡多，拆成两路。
- 回归测试：每张有效果的卡写一条，在 test1 分支的 `tests/test_tournament_*.py`，共 115 个，另外每套有一个合并核对身材和关键词的测试。脚本如果错了，测试按官方行为写、标 `xfail(strict=True)`；修好以后会自动报出来。
- 运行方式：用 1 号分支的配置跑，免得导入 test1 自己那份旧 svsim：

```
cd <1 号分支的 checkout> && python3 -m pytest -c pyproject.toml --rootdir . <test1>/tests/test_tournament_*.py -q -p no:cacheprovider
```

**结果**：115 个全部通过，没有 xfail。在 2353f07 和 1 号最新的 f03050f 上都跑过。

**核心卡错误率 0/57**。逐条结果在 `findings_*.json`：每张卡一条，写了核对要点和对应的测试名。

几处旁证：
- 旗皇那一路在测试进程里临时改坏了 24 处脚本，没有动模拟器文件。每处都至少让一个测试失败，说明测试真能抓到错。
- 机锋那一路把随机种子换成 0～39 各跑一遍，全过。
- 连击妖、跳费龙两路用比赛卡表各打了 300 局随机对局，不变量检查全过，没有崩溃。

**引擎的通用规则**：各路核对的结论一致，都与官方词汇表和 Q&A 相符。
- "进化时"在用进化点或超进化点进化时都发动；"超进化时"只在用超进化点时发动；被卡牌效果进化时两者都不发动。例如波菈莱（2费 0/2）超进化时一共拿 3 张天刀深渊，不是 1+3。
- 爆能强化在 PP 够时强制发动。法术要凑齐目标才能使用；入场曲目标不够也能用。
- 分配伤害从最早登场的随从开始。连击把正在使用的这张也算进去。

**不算错误、但值得知道的几处**（findings 里都标 ok，加了备注）：

1. **关键词不是"永久"写法**：佐伊（5费 5/5）强化后的疾驰、正义（10费 8/8）进化后的威慑、塞达&贝阿朵丽丝（4费 3/2）给的疾驰和毁灭、无音的包围、黄金之靴、黄金项链。这些是直接写进 `keywords`，没有走 `give_keywords`。如果以后同一个关键词被限时给予又到期，会被一起删掉。现在这四套和中立卡池里没有限时关键词，不影响对局。
2. **玩家确认过、官方原文没写明的解读**：
   - 大游戏世界（1费 倒数护符）自己也算"战场上的其他卡牌"，所以打出任何原始费用 1 的卡都会推进倒数。
   - 机锋（1费 1/1）的纹章只在真的进化了随从时才消耗"每回合一次"。
   - 斯洛士（3费 0/2）给对手的纹章在吟唱归零那回合仍发动第 3 项。
   - 锻磨保镖（4费 4/4）没有可选随从时照样回复 4 点。
   - 吉尔克、爱卡随机加入手牌时，按被破坏的次数加权。
   - 蒂亚（2费 2/2）进化的 +2/+2 也算"获得增加"。
3. **结算顺序的细节**：目前的卡池里看不出差别。
   - 牢头（7费 5/6）的 -0/-4 是逐个结算、逐个判死的。
   - 圣德芬（6费 7/6）的瞬念召唤排在已入队的"回合开始时"能力之前。
   - 斯洛士"回合结束时若已进化"是在结算时判定，不是在回合结束开始时。
   - 尤艾尔&苏丝雅（5费 4/3）的纹章进化排在被使用随从自己的入场曲之后。
4. **边缘情况**：
   - 玛尔斯（8费 1/5）：士兵在结算前已离场时，仍给自己 +1/+0。
   - 萨莎妮德（1费 1/1）：两次满足条件会叠两份信仰效果，要 20 次进化才会出现。
   - 诚心的尽小花：把自己的卡变成伊鞠的小鬼时，小鬼当回合就能攻击随从。官方词汇表写的是变身成随从后下回合才能攻击。**复查后不是问题**：伊鞠的小鬼本身有突进（3/3），变身出来算新上场，突进本来就能当回合攻击随从；词汇表那句说的是不带疾驰或突进的随从。
5. **没有实现的**：巴尔特的纹章（测试佐伊的伤害上限时用对手已进化的正义代替）。它不在这四套里。

结论：这四套卡组缺的不是脚本，脚本也没发现错误。剩下的问题在搜索和评估器那一层：组合回合的搜索支持，以及按对局的评估器。

## 起手的行为检查：D / R-A / R-B，2000 手（`mulligan_check.py`）

**1 号实现的参考**：`mulligan_check.py` 里的 `RULES_A`、`rules_b`、`layer` 和 `decide_b`（test1 38b62fc），按草案的语义实现了 §7.1 和 §7.2 的扩展：先后手、按对手、搭档、叠加优先级，以及 §5b 的条件变体。

- **条件**：对手卡表已知（牌序、手牌未知）。只比起手，不打对局。
- **做法**：每套卡组 × 4 个对手 × 先后手，各 250 手，用引擎发牌（每手一个种子）。三种换牌方式在同一个种子上比较：
  - D：现在 bot 用的默认起手；
  - R-A：草案 §7.1，只用现有 Rules；
  - R-B：草案 §7.2，加上扩展，`--variants` 再打开 §5b 的条件变体。
- **目标的判法**：换牌后双方都空过回合，看第 t 回合开头手里有没有目标牌。
- **配对的含义**：换回去的牌洗进牌库用的是同一串随机数，所以不在被换上来那几张里的牌，在牌库里的位置两种方式下一样。差别只来自多换的那几张。这是配对比较，很敏感，但"到第 5 回合摸没摸到"这类目标本来就不太受换牌影响。
