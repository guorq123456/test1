### 0.2 把握怎么定（按〔M〕§1 L57–63 的分级）

- **高**：B 级（有比赛成绩）的原话；或者 C 级原话和你的原话、文档里标「高」的算术结论互相印证。
- **中**：单一的 C 级原话；或者文档自己的〔推断〕，并且 §9 标的是「中」以上。
- **低**：下面几种情况都算低。
  - 只有 D 级来源。〔M〕L62 明说 D 级「只当卡表来源，不当推理依据」。
  - §1 没给作者分级。
  - 拿调整前的说法套到调整后。
  - 我从卡组的运转逻辑自己推出来的。
- **层级**：A／B 是比赛或职业层面，C 是天梯强玩家，D 和没分级的是天梯攻略。

### 0.3 关于模块，有几件事要先知道（〔MU〕和模拟器源码）

0. 规则本身：起手 4 张，可以换 0～4 张，只能换一次；先手第 1 回合也抽 1 张（〔RU〕L63–68）。
1. **`_deck_key` 现在只认识 rhino、ramp、pirate、combo、face 五套**（〔MU〕L52–53），四套 `-t` 卡组都不认识。所以 1 号要先把这四套的 40 张登记进去，PLAYER_RULES 才会生效。哈希在 `scratchpad/audit/tournament-decks.md`。
2. `Rules` 里没有阈值字段。阈值是 `mulligan(state, threshold=5)` 传给 `by_rules` 的（〔MU〕L59、L74）。下面四套都用默认的 5，低于 5 费的牌也写进了显式的 keep 或 redraw 集合。
3. **`ramp-t` 的基础规则和现有的跳费兜底（〔MU〕L87–88）行为完全一样。**
   - 模拟器的 `ramps()`（`svsim/search/race.py` L275–278）在这套卡组里认出 9 张跳费卡：龙之启示、佐伊、金银（靠加速）。9×8 ≥ 40，所以兜底本来就会生效。
   - 把基础规则写进 PLAYER_RULES，作用只有一个：给 timing 层提供先验，keep 是 0.9，redraw 是 0.1（`learn/timing.py` L118–124）。
   - 真正的差别要等 §5 的扩展做出来才有。
4. `nemesis-t` 的基础规则也几乎等于默认规则，因为两张必留牌都是 1 费。真正想表达的东西也要靠 §5 的扩展。
5. **dossier 里金银的官方卡面缺了「加速」一段。**
   - 〔DO〕的中文和英文 text 都只有「舍弃 2 张、所有敌人 4 点、超进化抽 3」。
   - 模拟器的脚本说明写着 `Accelerate (3): see LumioreAccelerate`，实现在 `svsim/cards/dragon.py` L203–207，效果是「最大 PP +1」。
   - 〔ED〕L226 核对过脚本，GameWith 也把它叫作「アクセラレート」的跳费牌（〔ED〕L72）。
   - 所以本稿把金银当作 3 费跳费卡。卡面数据要不要补，请 1 号确认。

## 1. 连击妖（elf-t）

### 1.1 卡表
这套卡表和 JCS しょーや、JCS まっつ、职业联赛第 8 节后半 ZETA CQCQ、VARREL まっつ 四套完全相同（〔PS〕in_elf.md L1–23 的对应列）。它属于 Spicies 的无飞燕构筑：19 套比赛精灵全是这个构筑（〔M〕L219–221）。

### 1.2 运转逻辑，开局需要什么
- **引擎是妖安的纹章**（〔M〕E1 L224）。第一个进化回合（先手第 5、后手第 4 回合）打出妖安并进化，拿到纹章。之后 3 回合，每回合结束时连击 ≥3，牌库里的随从就 +1/+1。纹章原文见〔T1〕L122。
- 那一回合的标准打法是「妖安＋进化＋任意 1 张 1 费牌」，正好连击 3（〔V1〕L286，〔T1〕L129）。
- **摸到纹章本身就不稳**（〔M〕E2 L226，§9 L408 标「高」）。只留妖安和大游戏世界、其余全换，到进化回合手里有妖安的概率是先手 67%、后手 64%。
- 架构讨论把曲千代和魅禄列成引擎。按 meta 文档，这两张的角色是：
  - 魅禄（3费 2/2）：Spicies 的妥协留牌，前期解场或补手数，中盘还是进化对象（〔ED〕L165）。
  - 曲千代（3费 2/2）：连击 3 时对全体敌方随从 4 点（卡面），是中盘清场牌（〔M〕L113；Spicies 的立ち回り，〔ED〕L168）。**没有任何留牌来源提到它。**
- 所以开局要的是：尽早找到妖安和大游戏世界，同时前期场面不能被压住。

### 1.3 规则（只用现有 `Rules`）

- ① 最优先：妖安、大游戏世界。
- ② 妥协留：根延潜伏者、魅禄。「ダストデイズが見えていなくてもキープする」。

### 1.4 现有 `Rules` 表达不了的
- **按对手换规则（`vs`）。**
  - Spicies 原话：对主教这类「序盤の面の取り合いの価値が低い」的对手，只全力找妖安和大游戏世界（〔ED〕L166）。
  - 四套卡组里没有这类对手。Spicies 对跳费龙反而强调「序盤の盤面」很重要（〔ED〕L169）。所以**眼下不需要 `vs` 条目**。以后加了主教卡组，就在对主教时把根延潜伏者和魅禄移进 redraw。
- **候选：对旗皇留曲千代。**
  - 〔M〕M2 L113 认为「精灵的曲千代连击 AoE 能一次清掉海盗的小身材」。但它是〔推断〕，也只是三个解释里的一个，而且讲的不是留牌。
  - 把握低。没写进 snippet，请你判。
- **不该加「没有妖安就全换」。** Spicies 明说没见到妖安也妥协留根延潜伏者和魅禄（〔ED〕L165）。E2 的 67%／64% 是按「只留妖安和大游戏世界」建的模（〔M〕L226），那只是计算假设，不是打法建议。
- 先手和后手：来源里没有区别。E2 两边的概率也差不多。

### 1.5 把握和层级
- **这是四套里唯一有职业原话的。** Spicies 是 MURASH 的职业选手、B 级（〔M〕L60、L72），他的卡表就是 19 套比赛卡表（〔M〕L221）。
- 两点限制：
  - 这篇是调整当天（09-29）发的，而且只抓取过 1 次（〔ED〕L162）。
  - 海盗的斥候和炮手在调整里被加强（〔T1〕L149），这篇没覆盖到。
- D 级来源大体一致：Game8 共通留妖安、次点留魅禄（〔ED〕L159）；hqzuki 多留枝叶大姐大（〔ED〕L180）。NARU 是飞燕版，必留的精灵陷阱师不在这套卡里（〔ED〕L175），不适用。

## 2. 机锋（nemesis-t）

### 2.1 卡表
这套卡表和职业联赛第 8 节后半 VARREL Terarina、CR ふえた 两套完全相同（〔PS〕in_cut.md L1–44 的「PS8b VL terarina」「PS8b CR fueta」两列），是 A 级的职业联赛卡表。和 JCS 的 5 套比：它不带大游戏世界和愚劣的兵器（JCS 5 套里这两张各有 4 套带，〔NE〕L172），多带了爱卡和个性店主。

### 2.2 运转逻辑，开局需要什么
- **H1**（〔M〕L266）：机锋是卡组里唯一有必杀的超越者随从。它进化时抽到的必杀随从只能是另一张机锋，抽完牌库没有重复卡，就拿到纹章。卡面见〔DO〕10974110。
- **H3**（〔M〕L270–275）：第一个进化回合（先手第 5、后手第 4 回合）用进化点进化机锋，拿到纹章，同时打开一系列「单卡时」效果：
  - 青锈小卒 5 点
  - 锻磨保镖 4 点或回 4
  - 铸铁亲信 破坏加疾驰
  - 白牙燐敛 全体破坏
  - 屈辱流放 多抽 2
- **H4**（〔M〕L279，§9 L411 标「中～高」）：只算 3 张机锋，进化回合前拿到约 65%；把屈辱流放（抽一张必杀超越者随从，也就是机锋）算作第 4 条出路，约 76～79%。这两个数是按「4 张起手，其余全换」建的模（〔NE〕L211）。
- 这套牌的主体是快攻加 AF：
  - 「核心是快攻＋AF」（〔M〕L261）。
  - ミホノブルボ（C 级，〔M〕L277）说这是 aggro（〔NE〕L180）。他认为最高价值的一回合是后手第 7 回合「额外 PP＋露莉亚＋卡密希拉或鱼牢头超进化」。
- 所以开局要的是：进化回合前手里有机锋或屈辱流放，加上一条能出牌的低费曲线。

叠加顺序：基础 → 先手或后手 → `vs[对手]` → `vs[对手]` 里的先手或后手。上层说留的牌从下层的 redraw 里拿掉，上层说换的牌从下层的 keep 里拿掉。`needs` 和 `at_most` 按 id 覆盖。

还要注意 timing 层：`Timing.keep_chance` 只读 keep、redraw、at_most（`learn/timing.py` L118–124）。如果第 0 层有学到的数据，`needs` 和 `need_one_of` 会被忽略。所以要么在 `timing.keep` 之前先用 `resolve` 合并，要么 timing 层也认这两个字段。

```python
# [ext] 扩展草图：替换 svsim/agents/mulligan.py 里的 Rules 和 by_rules，再加 overlay、resolve
from dataclasses import dataclass, field


@dataclass(frozen=True)
class Rules:
    redraw: frozenset = frozenset()       # 总是换
    keep: frozenset = frozenset()         # 总是留，不管费用
    at_most: dict = field(default_factory=dict)   # card id -> 最多留几张
    # ---- 扩展，默认值就是现在的行为 ----
    first: "Rules | None" = None          # E1：先手时叠加
    second: "Rules | None" = None         # E1：后手时叠加
    vs: dict = field(default_factory=dict)        # E2：对手卡组 key -> Rules
    needs: dict = field(default_factory=dict)     # E3：card id -> frozenset(搭档 id)
    need_one_of: frozenset = frozenset()  # E4：起手一张都没有就全换


def overlay(base: Rules, top: "Rules | None") -> Rules:
    """把 top 叠在 base 上（先后手、对手字段由 resolve 处理，不往下传）。"""
    if top is None:
        return base
    return Rules(redraw=(base.redraw - top.keep) | top.redraw,
                 keep=(base.keep - top.redraw) | top.keep,
                 at_most={**base.at_most, **top.at_most},
                 needs={**base.needs, **top.needs},
                 need_one_of=top.need_one_of or base.need_one_of)


def resolve(rules: Rules, going_first: bool, foe: "str | None") -> Rules:
    """顺序：基础 → 先后手 → 对手 → 对手里的先后手。"""
    def side(r):
        return r.first if going_first else r.second
    out = overlay(rules, side(rules))
    v = rules.vs.get(foe)
    if v is not None:
        out = overlay(overlay(out, v), side(v))
    return out


def by_rules(hand, rules: Rules, threshold: int = 5) -> tuple:
    ids = [c.defn.card_id for c in hand]
    if rules.need_one_of and not rules.need_one_of.intersection(ids):
        return tuple(range(len(hand)))                      # E4：全换
    kept, counts = [], {}
    for i, c in enumerate(hand):
        cid = ids[i]
        if cid in rules.redraw:
            continue
        if cid in rules.at_most and counts.get(cid, 0) >= rules.at_most[cid]:
            continue
        if cid in rules.keep or c.cost < threshold:
            kept.append(i)
            counts[cid] = counts.get(cid, 0) + 1
    changed = True
    while changed:                                          # E3：没有搭档的牌反复剔除
        changed = False
        for i in list(kept):
            partners = rules.needs.get(ids[i])
            if partners and not any(ids[j] in partners for j in kept if j != i):
                kept.remove(i)
                changed = True
    return tuple(i for i in range(len(hand)) if i not in kept)

#         ...（timing.keep 和 by_rules 都用合并后的 rules）
```

## 5b. 方法规矩和可切换的变体

- **连击妖·曲千代（3费 2/2）条件留**（草案，把握低）：
  - 依据：曲千代的价值在连击 3 时对敌方全体 4 点（卡面）。〔M〕L113 和 Spicies 的立ち回り〔ED〕L168 都把它当中盘清场牌。要在第 4～5 回合凑连击 3，同回合得先出两张便宜牌。比如 5 PP 时 1+1+3，后手第 4 回合配额外 PP 也行。这套卡里 1～2 费有 23 张（〔DO〕）。

- **机锋·看第 1～2 回合有没有牌下**（草案，把握低）：

## 10. bot 自己算起手：验收设计（架构线程 18:08Z；1 号实现，test1 验收）

**做法（1 号）**：对每个换牌子集（4 张起手最多 2^4 = 16 种），做 N 次短推演，取估值最高的子集。
- 推演到前 5 回合，双方都是当前 bot。对手按已知卡表抽牌，对应现在的评测条件"对手卡表已知（牌序、手牌未知）"。
- 估值用回合结束模型，或者推演到第 5 回合时的 ENDED 分。
- 这是"看情况"的通用做法，也不查固定表。

**三个方案**：D = 默认起手（现在的分层：timing → PLAYER_RULES → 跳费兜底 → 5 费阈值）；R = 规则版（本草案，变体按开关）；C = 自己算。

**一、行为检查**（先做，不烧对局）：
1. 固定 2000 手起手：每套卡组 × 先后手，起手用固定种子发牌。三个方案各自决定换哪几张，报这几样：
   - 每张牌的留牌率；
   - 平均换几张；
   - C 和 R 的一致率，逐张列出差别最大的；
   - 卡组目标的达成率：跳费龙第 3 回合前摸到跳费、连击妖进化回合手里有妖安、旗皇前 3 回合有 2 费随从、机锋前 2 回合有牌下。用一样的后续抽牌种子算。
2. C 的成本：每次起手用多少毫秒（N × 16 次推演），按 N = 4 / 8 / 16 各量一次。N 定在估值排序稳定的地方：两次独立运行选中的子集一致率 ≥ 90%。

**二、对局闸门**（行为检查没有明显问题再跑）：
- 对比：R 对 D、C 对 D；两者都过时，再跑 C 对 R。
- 先在跳费龙镜像上跑：模型已经有了，也有 Salem 的起手可以对照。四套比赛卡组登记以后，每套卡组对四个对手各跑一组。
- 每组至少 300 局。座位成对（同种子换座位），同一个种子库。先 SPRT（H0 50% / H1 55%，最多 1200 局），再换种子库定长 600 局。报以下几项：
  - 得分 ± 95% 区间；
  - CR（Salem 刻度，括号里是游戏公式）；
  - 按真实先后手分开的胜率；
  - 条件行"对手卡表已知（牌序、手牌未知）"。
- **等算力**：
  - 对局里的搜索两边完全一样（同一个 spec、同样的迭代数）。差别只在 C 起手时多花的推演。
  - 前 50 局核一次墙钟：比较每局的总思考时间（起手加全部决策）。C 那边多出 5% 以上，就把 D（或 R）的每步迭代数按比例加上去，以墙钟为准。
  - 另外报一个"不补偿"的结果作参考，但结论以等算力为准。
- **推断对已知的消融**：C 的对手按已知卡表抽牌，天梯里做不到。所以在 C 过了闸门以后，再跑一个 C′：对手卡表换成 E 步的后验，按比赛卡表混合抽。C′ 对 C 的差距，就是"起手知道对手卡表"的那部分强度。
