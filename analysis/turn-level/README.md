## 候选（建造线的生成器 ce6f95a；每个开头 4～6 种）

`generate(局面, spec="v2s", seed=65960000 + k, salem=他这回合的动作)`，在真实局面的拷贝上走出每种打法，每一步由 agent 现场决定：
1. **bot**：`level-strong`（v2s）打完这一回合。
2. **second、third**：bot 搜索根节点访问次数第 2、第 3 的第一步，之后由 bot 打完这回合。
3. **race（铺路打法，时钟目标）**：整回合规划器 `search.turnplan`，回合末按「我方斩杀时钟还要几回合」打分，越少越好，平手看 bot 的评估。
4. **留资源**：bot 在老师的一个限制下打完这回合：`keep:<卡号>`（主线要出的最贵的那张）、`save`（主线用了额外 PP 时）、`noevo`（主线进化时）。
5. **end**：什么都不做，结束回合。
6. **salem**（只在 Salem 局里）：他这回合的记录，照原样。

- **去重**：回合末局面（`search.lethal.state_key`）相同的候选算一个，合并进来的类别记在 merged 里。每类按它合并进去的那个打法的 T 算。
- 候选少于 4 个的开头照算，单独计数。
- 照记：state_key 区分场上位置。所以同样几张牌、出牌顺序不同的两个打法，算两个候选。冒烟里有一例（k = 72 的 second 和 third），老师逐个确定化给出完全一样的值。报告里另数「有两个候选 T 完全打平」的开头。主线排第一按「没有候选的 T 严格大于主线」算，所以打平不算输。
  - 建造线的意见（02:53Z）：保持按 state_key 区分顺序。这个引擎里场上顺序有实际作用：`CardInstance.order` 决定回合末效果的结算先后，越早上场越先结算。这一类占比高的话，可以再加一个「忽略顺序」的次级键，只用于统计。最后由架构线程定。

## 候选在确定化里怎么复现（开跑前补的；回答架构线程 02:40Z 的问题）

- 生成器的打法是在真实局面上走出来的，T 和 G_end 却要在别的确定化里走同一个打法。
- **规矩**：
  - 照打法的动作键走（`search.mcts.action_key`，用卡号和位置描述一个动作，各确定化通用）；
  - 打法里的结束回合，就在那里结束；
  - 某一步在这个确定化里没有对应的合法动作（或者被这类打法自己的限制禁止）时，回合剩下的部分交给**这类候选自己的策略**接着打：
    - bot / second / third / salem 交给 bot（v2s）；
    - keep / save / noevo 交给带同样限制的 bot；
    - race 交给 race 规划器；
    - end 不会对不上。
  - 所以在确定化和真实局面一样的那段前缀上，就是照原样重放；从不一样的地方起（几乎都是回合中途抽到的牌不同），等于在这个确定化里把这类候选重新生成。T 和 G_end 用同一个规矩。
  - 接手策略的种子：T 是 10 × (65920000 + 2k + s) + 确定化序号；G_end 是 10 × (65930000 + 100m + j)。
- **为什么不全部重新生成**：每个确定化都重新生成一遍，T 要多花 535 × 2 × 8 次生成，大约 RC 上多 1 个多小时。而且对不上几乎都发生在回合中途抽牌之后，前缀照放和重新生成是一回事。
- **为什么不用老师现成的 `CrossTurnAgent.outcomes`**：
  - 它的 `forbids()` 只认限制的名字，"bot" 这类名字会报错；
  - 它走完打法的结束回合以后，会交给策略头接着打。这样 end 和 Salem 故意少打的回合都会被补上动作。
  - 所以 T 是照老师的打分重写的：同一个 agent、同样的种子和 8 个确定化，对手回合和我方下回合照老师的推演，最后用 ENDED 模型打分。只换了「自己这回合怎么走」这一段。
- **复现失败的比例照报**：按类别报，再报对不上之前走了几步。冒烟的数在文末。

## 标签

- **T**：
  - 用 n30 老师的推演：`CrossTurnAgent(mcts-raw:100+learned+phased, next_turn=True, next_search=30, samples=8)`。所有候选在同一组 8 个确定化上走完自己的回合（复现规矩见上一节），再推演对手回合和我方下回合，用 ENDED 模型打分。所以候选之间是**配对的**。
  - 开跑前改的：原来写的是直接调 `.outcomes(state, {候选: 打法})`，理由见上一节。
  - 两个种子，T 取平均。
  - 每个候选另外保留 2 × 8 = 16 个逐确定化的值，用来算两两之差的配对标准误。
- **G_end（验证）**：
  - 取 **150 个开头**：
    - Salem 局里**他的打法和 bot 主线不同**的回合，最多 100 个；
    - 自对弈的开头，补满 150。
    - 两边都按 Random(65950000) 打乱后取。
  - 每个开头 K = 32（2 组 × 16 个确定化）。所有候选在同一个确定化、同一组 bot 种子上走完自己的回合，然后由 bot 对打到终局。
  - 「他的打法和 bot 主线不同」= salem 这个候选没有并进 bot（回合末局面不同）。
  - 回合之后对打的 bot 是 `mcts:100+plan+learned+phased`，和分辨实验的 G_end 一样（老师 ≈ 终局真值就是在它上面量的）。种子 10 × 那个数 + 3（我方）、+ 1（对手）。
  - G_end(候选) = 平均胜负。

## 报什么（区间按开头重抽 2000 次）

1. **按开头**：
   - bot 主线在候选里按 T 的名次；
   - 后悔 = 最好候选的 T − 主线的 T，单位是胜率百分点。
   - 自对弈和 Salem 局分开报。
   - **「差距在噪声以上」的开头**：最好的候选和最差的候选之间，配对差的 |z| > 1.96（16 个逐确定化的配对差，两个种子合起来算）。J20 只算这些开头；全部开头的数也报。
2. **每类候选赢 bot 主线的比例**：T 大于主线的比例，以及显著大于（|z| > 1.96）的比例。
3. **Salem 局里，他的打法和 bot 主线不同的回合**：
   - T 偏向谁：他的 T > 主线 T 的比例；
   - G_end 偏向谁：在有 G_end 的那些回合上，他的 G_end > 主线 G_end 的比例。相等算一半。
4. **T 和 G_end 一致不一致**：150 个开头上，候选之间按 T 和按 G_end 的排序相关。G_end 两组的一致度照报，用来折算噪声。
5. **开跑前补的（分析线加的，都不改 J20～J22 的定义）**：
   - **交叉种子的后悔**（副读）：用一个种子的 8 个确定化挑出最好的候选，在另一个种子上量它比主线好多少，两个方向平均。第 1 条的后悔是在 4～6 个带噪的值里取最大，会偏高；这个不偏。两个数并列报。
   - **复现失败**：按类别报，T 和 G_end 各一份（见「候选在确定化里怎么复现」）。
   - 候选数的分布、少于 4 个的开头数、有两个候选 T 完全打平的开头数。
   - **同一开头两种打法之差：ΔT 对 ΔG_end**（架构线程 07:19Z，第 0 步数据到之前写入；这个数决定第 1 步拿什么当标签）：
     - 在 150 个打到终局的开头上，每个没合并的打法减 bot 的打法，得到 ΔT（16 个确定化的平均）和 ΔG_end（32 局的平均）。
     - 报：Spearman(ΔT, ΔG_end)；两边各自的信度（ΔT 是两个种子之间，ΔG_end 是两组 16 局之间，都用 Spearman-Brown 折成整份）；折算后的值 = Spearman ÷ √(两个信度之积)。区间按开头重抽 2000 次。
     - 合起来报一次，再按候选类别分开报，尤其是 race。T 只看两回合，铺路的回报可能落在第三回合以后。
     - **读法（架构线程原文）**：折算后 ≥ 0.7，第 1 步照原计划主要用 T；0.5～0.7，标签改成 T 和 G_end 混合，G_end 的份额按两边信度定；< 0.5，第 1 步不用 T 当主标签，先想更长视野的老师。
     - **架构线程 07:22Z 定了**：读法按**不含 end** 那一行定，两行都报。要是不含 end 那行的区间跨过两个读法分界（0.5 或 0.7），就按区间中点定，并在读数里写明「区间跨档」。
     - 原来的提议（我补的）：「合起来」分含 end 和不含 end 两行。end 几乎总是差得多，ΔT 和 ΔG_end 都很大，又容易分辨，会主导合起来的相关（往哪边带要看数据，冒烟的 5 个开头里不含 end 反而更高，只有 16 对，不作数）；第 1 步要的是 T 能不能把像样的备选排对。我建议读法按不含 end 那一行定，两行都报。
   - **留资源类守没守住自己的限制**（架构线程 07:16Z，第 0 步数据到之前补的）：生成器的 `_agent_decider` 把 veto 挂在内层搜索上，可 level-strong 外面那层斩杀规划器不看 veto（学生数据的验证集里查出来的同一个绕过）。所以在真实局面的打法上逐个查：keep:c 候选里 c 本回合离了手的比例、save 候选里用了额外 PP 的比例、noevo 候选里进化了的比例，以及其中因此并进 bot 打法的个数。只报、不重跑；超过 20% 就在读数里写明这类的结论不算数，第 1 步造标签前先修。`report --selfplay selfplay.jsonl` 打出这一节。

## RC 的命令（库 65900000；svsim 用建造线 42e187a 或之后：要 ce6f95a 的生成器和 42e187a 的启动器）

## 冒烟测试（库外，种子库 99900000；只量时间和复现失败，数不当结果）

- 5 个开头：学生数据冒烟的库外自对弈里 3 个（第 4、9、8 个自己回合），Salem 局里 2 个（10 局一个第 4 回合，17 局一个第 5 回合）。

- **复现失败**（老师的 16 个确定化 × 每个候选）：

### 标签：T 和 G_end 混合（逐对收缩；架构线程让我提，我选这一种）
- **对子**：每个开头里，每个没合并的候选对 bot 的打法。ΔT = 16 个确定化上 value(候选) − value(bot) 的平均；ΔG = K 个配对结果差的平均。
- **校准**（只用训练开头、不含 end 的对子）：
  - b：过原点回归 ΔG ≈ b · ΔT，把 T 的差换算到终局胜率差的尺度；
  - s²_G：每局结果差的方差（逐对算样本方差，再在对子之间平均）；
  - τ²：真实 ΔG 里 b · ΔT 解释不了的那部分方差，用矩估计：mean((ΔG − bΔT)²) − mean(s²_G / K) − b² · mean(vT)，vT 是 16 个 T 差的方差 ÷ 16。下限 1e-4，撞下限时照报。
- **每对的标签和权重**：
  - w = τ² / (τ² + s²_G / K)；
  - 标签 L = bΔT + w · (ΔG − bΔT)：以 T 的换算值为底，按 G_end 的可靠程度往 G_end 拉；
  - 方差 V = (1 − w)² · (τ² + b² vT) + w² · s²_G / K，权重 = 1 / V。
  - 份额由噪声定，等价于按两边的信度定：K = 4 时 ΔG_end 的单对信度很低（按第 0 步的 0.70 @ K = 32 用 Spearman-Brown 换算，约 0.23），所以 w 小，主要靠 T；K 越大，w 越大。
- **只有 T 的对子**（`card-value/student_read/teacher_ends.jsonl.gz` 的 25 万个确定化对；架构线程要并进来）：每个（局面, 限制）两个种子的 16 个差平均成 ΔT，L = bΔT，V = τ² + b² vT。按学生数据的局面切分（g % 11）留出。
- **没有可比的对子不进标签**：16 个 T 差全为 0（这个打法在每个 T 确定化上都和 bot 走成一样），同 02:38Z 的规矩。老师重跑那批照办。各自计数报出来。
- **end**：保留，但把它的总权重压到第 1 步对子总权重的 **10%**（训练开头）。
- **例子**：一个对子的标签 L 和权重 W，平均分给它所有确定化上的回合末对：T 的 16 个加 G_end 的 K 个。两条线动作完全相同的确定化不要；回合中途终局的那一端由训练器定（建造线现在是排除并计数）。
- **另一种不选**：两个损失项（T 对、G_end 对）各自加权。T 和 G_end 不在同一个尺度上（b 不是 1），也不是同一个量（第 0 步折算后相关 0.64）。收缩法先把 T 换算到 G_end 的尺度，再按噪声把两者合成一个标签，训练器只要一个损失项。
- 训练标签权重的有效样本量照报；建造线的 fit 有自己的等权退路（ESS < 30%）。
- 命令 `step1.py labels`，写出 `labels.jsonl`：第一行是校准，其后每对一行。

**校准**（训练开头、不含 end 的 4,384 对）：
- b = **0.888**（ΔG ≈ 0.888 · ΔT，过原点）；

- τ² = **0.0178**，没撞下限；T 换算后解释不了的真实差，标准差约 0.13。
- 由此，训练开头（K = 4）w = 0.0178 / (0.0178 + 0.247 / 4) ≈ **0.22**：每对标签往 G_end 拉 22%。
