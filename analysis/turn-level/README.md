## 候选（建造线的生成器；每个开头 4～6 种）

1. **bot 主线**：`level-strong` 在这个开头的搜索主线，打完这一回合。
2. **次好第一步、第三好第一步**：根节点访问次数第 2、第 3 的第一步，之后由 bot 打完这回合。
3. **铺路打法（时钟目标）**：照建造线生成器的定义。
4. **留资源的打法**：照建造线生成器的定义，比如不进化、不按额外 PP、留下主线要出的牌。
5. **直接结束**：什么都不做，结束回合。
6. **Salem 局里，加上他自己这一回合的打法**：照记录重放。重放到某一步在确定化里不合法时，后面由 bot 打完，同时记下这件事。

- **去重**：回合末局面完全相同的候选算一个，记下合并了几个。
- 候选少于 4 个的开头照算，单独计数。

## 标签

- **T**：
  - 用 n30 老师的推演：`CrossTurnAgent(mcts-raw:100+learned+phased, next_turn=True, next_search=30, samples=8).outcomes(state, {候选: 打法})`。所有候选在同一组 8 个确定化上走完自己的回合，再推演对手回合和我方下回合，用 ENDED 模型打分。所以候选之间是**配对的**。
  - 两个种子，T 取平均。
  - 每个候选另外保留 2 × 8 = 16 个逐确定化的值，用来算两两之差的配对标准误。
- **G_end（验证）**：
  - 取 **150 个开头**：
    - Salem 局里**他的打法和 bot 主线不同**的回合，最多 100 个；
    - 自对弈的开头，补满 150。
    - 两边都按 Random(65950000) 打乱后取。
  - 每个开头 K = 32（2 组 × 16 个确定化）。所有候选在同一个确定化、同一组 bot 种子上走完自己的回合，然后由 bot 对打到终局。
  - G_end(候选) = 平均胜负。

## 报什么（区间按开头重抽 2000 次）

1. **按开头**：
   - bot 主线在候选里按 T 的名次；
   - 后悔 = 最好候选的 T − 主线的 T，单位是胜率百分点。
   - 自对弈和 Salem 局分开报。
   - **「差距在噪声以上」的开头**：最好的候选和最差的候选之间，配对差的 |z| > 1.96（16 个逐确定化的配对差，两个种子合起来算）。J20 只算这些开头；全部开头的数也报。
2. **每类候选赢 bot 主线的比例**：T 大于主线的比例，以及显著大于（|z| > 1.96）的比例。
3. **Salem 局里，他的打法和 bot 主线不同的回合**：
   - T 偏向谁：他的 T > 主线 T 的比例；
   - G_end 偏向谁：在有 G_end 的那些回合上，他的 G_end > 主线 G_end 的比例。相等算一半。
4. **T 和 G_end 一致不一致**：150 个开头上，候选之间按 T 和按 G_end 的排序相关。G_end 两组的一致度照报，用来折算噪声。

## 判断（架构线程的原文，写在任何第 0 步数据之前）

- **J20**：强档自对弈的回合开头上，bot 自己的打法在 4～6 种候选里按 T 排第一的比例 ≤ 50%（只算候选之间差距在噪声以上的开头），平均后悔 ≥ 2 个百分点胜率。置信 60%。
