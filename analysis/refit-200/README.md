## 为什么做

- J1：同一个旗皇对连击妖的模型，在 v2（100 次）下多赢 12 个胜率点，在 v2s（200 次）下多赢 18～19 个（`analysis/deck-league/README.md`）。评估器的价值要到 200 级才完全显出来。

## 门

- A = 候选（A200、A′ 或 A100），B = 现装（第一段是借用的 Game8 模型），C = v2s 打对手卡组（`--versus v2s`）。

## 一起报的

1. **留出对数损失**：A200、A′、A100、B 在同一个留出集上的对数损失和判对率，ENDED、ACT 分开。
   - 留出集有两份：200 级数据的 400 局和 100 级数据的 400 局，两份都报。对数损失只对终局胜负算（A′ 训练时用了 q 值，留出评估仍按胜负）。
   - B 没见过这两份数据（它的训练数据是另一批），所以对 B 也公平。
   - 区间：在留出局上按局重抽 2000 次，A − B 的对数损失差带 95% 区间。
2. **「留出改善 ↔ 棋力改善」是否一致**（E2、M3 时不一致）：
   - 留出改善 = A 的对数损失比 B 低，而且差的 95% 区间不含 0（看 200 级留出集、ACT）；
   - 棋力改善 = 门的区间下沿 > 50%；
   - 两样同时成立或同时不成立：一致；只有留出改善：和 E2 一样不一致；只有棋力改善：照实报。
3. 先后手拆分，A、B 逐局相同的局数，每回合用时。
4. **待查项**（主攻 C 转来，架构线程 06:01Z）：A200、A′、A100 和 B 的 `me_sep`、`op_sep`（超进化点）系数并列。现装模型给「留着一个超进化点」约 0.6 logit，可能让浅搜不肯超进化（`analysis/evaluator-gaps/README.md` 附表）；看 200 级重拟合以后这个系数怎么变，再定要不要单独处理。只报数，不改读法。

## 预注册的读法（结果出来以后不改）

每段分开读：

- **A200 过门**（下沿 > 50%）：支持「200 级数据更好」。按第 12 条装机（按新门装机，200 级）。
- **A200 不过门**：不装。
  - 若对照组也跑了、A100 也不过门：数据量和 200 级都没让同样形式的线性模型变强，瓶颈更可能在特征（J6 的后半句），转主攻 C。
- **数据量和数据质量**（只在对照组跑了时读）：A200 − A100 按种子配对。
  - A200 − A100 的区间下沿 > 0：是「数据质量」（200 级），不只是数据量；
  - 区间含 0、而且两者都过门：主要是「数据量」；
  - 其他情况照实报。
- **标签和数据深度**（A′，架构线程 05:45Z 补）：
  - A′ 过门、A200 不过门：增量来自标签（200 级搜索的 q 值），不是数据的深度；
  - A′ − A200 按种子配对，区间下沿 > 0：q 值标签在 200 级数据之上还有增量；含 0：分不开；
  - 两者都过门：装哪个看配对差，差含 0 时装 A200（形式更简单，和现装一致）。
- **第一段的特别说明**：B 是借来的 Game8 模型，A200 赢了也可能只是因为「终于有了比赛版跳费龙自己的数据」。A100 能分开：A100 也过门，就主要是卡表和数据量；只有 A200 过门，才是 200 级的贡献。
