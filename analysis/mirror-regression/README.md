# 跳费龙内战回归局面（来自 Salem 的 10 局）

**评测条件**：对手卡表已知（牌序、手牌未知）。bot 的确定化把对手的手牌和牌库整个重洗再切分（view.determinize），所以它知道对手的 40 张，只是不知道顺序和手牌。天梯里这不成立（架构线程 17:43Z）。

牌名按对照表（架构分支 469f714 的 analysis/card-glossary.md）：正义（10费 8/8）、班德（9费 9/9）、金银（8费 6/6）、牢头（7费 5/6）、口人魔（7费 5/4，即 754）、佐伊（5费 5/5）、波菈莱（2费 0/2）、琪米卡（2费 2/1）、露莉亚（2费 1/1）、宣扬的龙人（2费 2/1）。

这套局面用来检查新 bot 能不能在同样的局面做出高手的选择。它是测试，不是写进 bot 的规则。来源是 Salem 在超凡陪练台上和网页 bot（`mcts:200+plan+learned`）打的 10 局跳费龙内战，Salem 10-0。

每个局面是 Salem 某个回合开始时的局面（座位 0）。被测的 agent 从这里替 Salem 打完整个回合，检查的是这一整回合有没有做到某件事。

## 文件

- `positions.json`：对局记录只存一份（`records`），局面（`positions`）按 `game` + `at` 引用。`at` 是动作下标：重放前 `at` 个动作，就到这个回合开始。每个局面带当时的局面摘要（`context`）、Salem 这一回合实际怎么打（`salem_turn`）、检查条件（`check`）和理由（`why`）。
- `build_positions.py`：从对局 JSON 生成 `positions.json`。
- `cross_turn.json`、`build_cross_turn.py`：跨回合探针集（24 个局面，见后面一节）。局面引用 `positions.json` 里的对局记录。
- `check.py`：跑一个 agent，报告每个局面和每一类的通过率。agent 写成 `salem` 时，重放 Salem 自己的回合，用来验证检查本身写得对：现在 52/52 全过。

```
cd <svsim 仓库> && PYTHONPATH=. python3 check.py positions.json "mcts:200+plan+learned" 3
SVSIM_WEIGHTS=<只放 dragon.json 的目录> PYTHONPATH=. python3 check.py positions.json "mcts:200+plan+learned" 3
```

## 八类检查

| 类别 | 数量 | 通过条件（整回合） |
|---|---|---|
| `lethal` | 10 | 这一回合就赢（攻击、效果、回合结束伤害都算） |
| `super_evolve` | 11 | 超进化 Salem 超进化的那张（正义 5、班德 6） |
| `discard` | 9 | 弃牌时不弃正义或班德（Salem 弃的是波菈莱、深渊、咆哮） |
| `answer_threat` | 8 | 对面回合开始时最大的随从，这回合结束前被解掉（用什么解都行）；打出的赤流都打在当时最大的随从上 |
| `red_hold` | 1 | 对面只有小随从时，不把赤流打在小随从上 |
| `erntz_unevolved` | 3 | 10 血以下，白板下正义（不进化），拿那 8 点回血 |
| `bonus_keep` | 6 | 后手自己第 1 回合，回合结束后额外 PP 还在（没按，或按了没花：引擎会退回）。**行为观察项，不算缺口**（见更正） |
| `bonus_ramp` | 4 | 后手自己第 2 回合，用额外 PP 打 3 费跳费 |

## 注意

- 这一回合直接赢了的，除额外 PP 两类外，所有检查都算通过：赢了就不必再问别的。
- 这些是 Salem 在那一个局面的选择，不保证是唯一正确答案。Salem 说过超进化正义还是班德"要看双方资源，没有固定答案"。所以这套局面适合看趋势（新 bot 的通过率有没有上升），不适合单个局面判对错。
- `discard`、`red_hold` 这类检查，不弃牌、不打赤流也算通过，只拦"做错的那一步"。
- 52 个局面太少，不能用来比较两个 bot 谁更强，那是评测台（`svsim/tools/gate.py`）的事。这里只回答"像不像高手"。
- 一个检查可以有几个条件，全部满足才算通过（探针集用到）。

## 更正（2026-10-07 下午）：`bonus_keep`

原来的 `bonus_keep` 只要按了额外 PP 按钮就算失败。但引擎会在回合结束时退回没花掉的额外 PP，按了不花等于没用。现在改成看回合结束后额外 PP 还在不在。

后果：
- **现装 bot（不带 `+phased`）其实一直留着额外 PP。** 它们是按了按钮又没花，旧检查算成失败。
- **v2、v2s 是真的花掉了。**
- 所以"后手第 1 回合留额外 PP"不是所有 bot 共同的缺口，而是 `+phased` 带来的**行为变化**。
- Salem 看过以后说："我的六局样本数太少，这个问题是部分情况下后1用掉额外能量点确实更好。"所以这一类改成**行为观察项**：照常报告，但不当成缺口，也不计入"像不像 Salem"的总分。好坏交给评测台判断（`../cross-turn/README.md` 的"额外 PP 值多少胜率"）。

200 个随机开局里，后手第 1 回合用掉额外 PP 的比例：v2、v2s 82%，现装 22%（`../cross-turn/README.md`）。下面两张旧表的 `bonus_keep` 用的是旧检查，按原样保留。修正后的数字见"修正后的基线"一节。

## 跨回合探针集 `cross_turn.json`（25 个局面，验收用其中 20 个）

跨回合规划器的定向验收集。新 bot 要在这些局面把走法改过来，同时不能把 52 个局面和评测台打坏。

**怎么选出来的。** 把 Salem 10 局的全部 94 个回合，和 v2、v2s 从同一回合开头各打 5 次的走法，逐回合对照着读（`../cross-turn/play_turns.py`，`../cross-turn/turns_v2_v2s_e8d190a.jsonl`）。选出 Salem 和 bot 走法不同、且原因要到这一回合之后才看得出来的局面，也就是留 PP、留关键牌、进化或超进化时机、为下回合铺路这几类。每个局面里写了：
- Salem 怎么打（`salem_turn`）；
- bot 最常见的打法和次数（`bot_turn`）；
- 为什么要跨回合才看得出来（`why`）；
- 把握（`confidence`：高或中；第 1 回合额外 PP 的 4 个是"看局面"，依赖对手手牌判断的是"belief"，这两种不计入验收；低的没放进来，列在下面）；
- 对应的 52 个局面里的哪一个（`related`）。

检查和 52 个局面用同一个 `check.py`，Salem 自己的回合 25/25 全过。三个探针文件里给人看的文字（why、salem_turn、context）都按对照表写常用名（费用身材），Salem 的原话一字不动；检查条件里还是模拟器的全名（`glossary.py`）。

```
cd <svsim 仓库> && PYTHONPATH=. python3 check.py cross_turn.json "mcts:200+plan+learned+phased" 5
```

| 类别 | 数量 | 通过条件（整回合） | 为什么要跨回合才看得出来 |
|---|---|---|---|
| `bonus_keep` | 4 | 回合结束后额外 PP 还在 | 留到第 2 回合，2+1 PP 打 3 费跳费。**看局面**：Salem 说部分情况下第 1 回合用掉更好，这一类只观察，不计入验收 |

## Salem 27 局的失误分析（2026-10-08，`salem_mistakes.py`；给构建会话的 B 当输入）

**条件**：对手卡表已知（牌序、手牌未知）。v2s（`mcts:200+plan+learned+phased`），构建分支 3effa47。

**为什么做**：Salem 在这 27 局里没标过失误（「应该有部分失误和噪声，可能需要你自己进行数据分析」）。B 要模仿他的对局，先把 bot 看得出的失误筛掉。

**做法**：
- **哪些算决策**：Salem（0 号位）的每一个决策都算，包括出牌、攻击、进化、结束回合和其他选择。只有一个合法动作的不算。一共 667 个。
- **bot 想走哪步**：在这个局面上，用 v2s 自己的搜索换 8 个种子各搜一次（每次迭代都按已知卡表重新发对手的牌），取访问最多的那步。
- **遗憾（配对）**：
  - 同一组 8 个确定化上，他那步和 bot 那步各走一遍；
  - 这一回合剩下的部分都由 v2s（完整 agent）打完；
  - 对实际到达的回合结束局面做一次评估（对局结束就记胜负）。
  - 遗憾 = bot 那步之后的胜率 − 他那步之后的胜率，单位是胜率点。可以是负数，表示他那步更好。他那步就是 bot 那步时记 0。
- **F1 硬失误**：回合开始用 5000 节点的必杀搜索（不设筛选，和冒烟探针一样）找到必胜线，这一回合却没赢。这一回合的所有决策都标 F1。
- **F2 疑似失误**：遗憾 ≥ 15 个胜率点，只对非进化类决策标。
- **进化类一律不标**：进化或超进化某目标、有点不进化而结束回合、这回合下了又进化的牌。这正是 B 要学的。
- **一处更正**（`root_regret_points` 一列保留作对照）：
