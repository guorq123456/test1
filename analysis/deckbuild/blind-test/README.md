## 为什么要对照

只拿 bot 的名单去比天梯，对上了也说明不了多少：七个职业里取前三，碰巧对上的机会本来就不小。

所以要有一份「不费脑子」的对照名单，bot 必须明显比它更接近天梯，才算学到了东西。

## 指标（比对时 Salem 提供天梯一侧：每个职业的主流卡表，和职业强弱排名）

1. **重合张数。** 每个职业，拿 bot 名单里这个职业排名最高的一副，和天梯这个职业最主流的卡表比，数两副共有多少张（同一张卡按较少的份数算）。对照名单同样算一遍。
   - 通过线：7 个职业里至少 5 个 bot 比对照重合得多，而且 7 个职业平均多 3 张以上。
2. **职业排名。** bot 名单按各职业最强一副的循环赛得分给职业排名；对照名单用同样的循环赛排名。两份排名各自和天梯的职业排名算 Spearman 相关。
   - 通过线：bot 的相关高于对照。
3. **新卡张数。** bot 的 T1 卡组每副平均带几张第 10 弹的卡，和天梯 T1 卡组比（计划文件判断 12）。
4. **像不像。** Salem 看 bot 的每副 T1 卡组，判断它是不是天梯上某个 T1 套路（是 / 否）。Claude 组同样判一遍。
5. **模拟器里互打（只在所有名单都冻结之后；10-29 21:5xZ 定稿）。**
   - 名单：sources.txt 列的各组（对照、g1、g2、g3、p2-g1、p2-g2、p2-g3；bot 组冻结后补一行），每组每职业取一副，是这组自己排得最高的那副：先看标签里的档位（T1/T2/T3、S/P/W、STRONG/PLAYABLE/WEAK、强/可玩/弱），同档按文件里的先后。每副先按卡名改合法（同名重印卡只换卡号，第 4 张换掉）。程序是 roster.py，只打印每组的副数和档位，不打印卡组。
   - 对局：只打不同组之间的卡组（deckbuild --league --cross-groups），每对 10 个发牌，每个发牌双方各先手一次（20 局）。8 组各 7 副时是 1372 对、27440 局。种子：第一遍 85900000 起，第二遍 85920000 起。
   - 两把尺子：第一遍用便宜 bot（mcts:100+plan）。第二遍原写「强档评分」，现改为：12 万或 26 万局练出的共用打牌网，哪个过门（对手写评分的 bot 过五成）用哪个；都没过，就用 mcts:400 手写评分，并注明这一遍和便宜 bot 盲点相同（10-28 验证，两者排名相关 0.97），信息量小。改的原因：强档的网是在四套旧卡组上练的，10-29 实测搬到新卡组只有 22.5～25.5%，当尺子比便宜 bot 还差。这个改动在任何互打对局之前做出。
   - 报告：每组对其他所有组的平均得分；bot 组对每一组、各 Claude 子组之间两两的得分（两组卡组之间所有对局的平均）；标准误按发牌算。
   - 注意：bot 组的卡组本来就是对着便宜 bot 挑出来的，便宜 bot 那一遍偏向 bot 组；两遍结果不一致时，以第二遍为准，并把不一致本身记下来。

- 卡组的强弱由便宜 bot（手写评分的一回合搜索）打出来的胜率决定。它看不见「先铺垫、后兑现」的打法，证据机制正属于这种。

- bot 从没和人或外部 bot 打过。
- 最终名单冻结时另行提交，并写明用的是哪些搜索的结果。
