# 200 次和 800 次搜索在一般对局里选得不一样的地方：第一步是哪一类（架构线程 18:12；只报数，不出候选、不开门）

**条件**：对手卡表已知（牌序、手牌未知）。

**问题**：J14 里「搜索次数不够」那一类（#2、#5、#9）都是多步连招：先用额外 PP 再出牌，或者出牌再超进化。这类局面在一般对局里多不多？200 次和 800 次选得不一样时，800 次选的第一步多半是哪一类？这个测量为 C3 之后选下一条线做准备：
- 如果不一致的大头是「用额外 PP」或「进化 / 超进化」开头的连招，就考虑做动作合并，例如把「用额外 PP 并出 X」算成一个根节点动作。这是搜索侧的改动，和 B 线的次数重分配不同。
- 如果比例很小，或者类别很分散，就不做。

## 方法（写在任何结果之前）

- **局面**：从联赛重跑 3000 局（`local/pairings-20261008` 的 `analysis/local-runs/league-after-20261008-part{1,2,3}.jsonl.gz`，v2s 对 v2s，四套比赛卡组）里抽。
  - 只取有配对模型的 11 个一方（同 `../c3-threat/`），每个一方 50 个，共 550 个。
  - 局面要求：主阶段，轮到这一方走，合法动作多于 1 个。
  - 先把 3000 局按固定种子 65400000 打乱，按顺序取，每局最多取 1 个局面。
- **搜索**：用现装第 22 版的强档 `mcts:N+plan+learned+phased`（代码 b9f2aca），N = 200 和 800，各 3 个种子。第 i 个局面、第 s 个种子用 65400000 + 10 i + s（200 次用 s = 0、1、2，800 次用 s = 5、6、7）。在分析线自己的容器里跑。
- **比较**：用 `search.mcts.action_key` 比走法。
  - 每个 N 取多数票（3 个里至少 2 个相同）；
  - 两个 N 都有多数、且多数不同，记「不一致」；
  - 有一边没有多数的，单独记。
- **报什么**：
  1. 不一致的比例（全部，和逐个一方）；
  2. 不一致时，800 次多数选的第一步属于哪一类：用额外 PP、进化 / 超进化、出牌、攻击、结束回合；
  3. 对照的噪声：同一个 N 的 3 个种子不全相同的比例。
- 种子库 65400000（下一个可用 65500000）。
