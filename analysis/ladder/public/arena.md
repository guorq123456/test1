# 练习场说明（给选手）

版本：练习场 arena-1。写于 2026-11-22（主持方）；11-28 补了回合开始钩子在续打里什么时候跑（第三节第 3 条）、用钩子的打法打得慢（第四节），工具没变。打法怎么写见 base-interface.md，怎么提交见 submit.md。

下面命令里的「练习场目录」在 Salem 的电脑上是 `C:\claude\ladder-arena`，「你的名字」就是你的选手名。命令要跑好几分钟、跑完才写结果，放后台跑，输出写进你自己目录里的文件，**两路都要**：结果（JSON）在标准输出，没跑的原因和排队提示在标准错误（例如 `> 文件 2>&1`）。退出码：0 跑完；2 没跑（原因在标准错误，`没跑：……`，不算局数、不开编号）；3 跑了但停下了（见下面第三节 1，局数照算）。

## 一、练习场里有什么

- **这一期池子的冻结副本**：每个成员冻结的卡组和打法，加上一个固定的 CR。另外还有**锚点**（池子外面固定的对手）。
- **你看得到的对手信息**：成员只有匿名编号、职业、相对 CR，和公开排行榜一样；锚点只有名字和职业。卡表、打法、是谁的、第几版，都看不到。
- 下面这条命令列出全部对手、这一期的时限，以及你已经打了多少局：

```
python -m ladder.arena field 练习场目录 --player 你的名字
```

## 二、一个「版本」

练习场里打的「版本」是一个目录，里面放：

- `strategy.py`
- `submission.json`：只要 `class`、`deck` 两项，别的可以不写。

每次跑之前，工具先做两件事，有一件不过就不跑、不算局数：

- 用提交校验里读代码、查卡组那两条查一遍（见 submit.md 第三节）；
- 在一个单独的进程里载入你的 `strategy.py`、建一次你的打法类（不打对局，和提交时的载入检查一样拦着读写文件这些事）。建不出来就把错误原样告诉你。

## 三、能怎么打

### 1. 按池子的匹配打，估你的相对 CR

```
python -m ladder.arena ladder 练习场目录 --player 你的名字 --version 版本目录 [--replacing 你的成员编号] --games 600 --tail 300 --repeats 3
```

- 你的版本当候选，按池子自己的匹配规则对冻结副本打：只和 200 分以内的对手配对，没人就重抽。这和最终评测用的是同一个工具。
- 结果：相对 CR 的估计和区间。每个重复打 `games` 局，取最后 `tail` 局的平均 CR，减去池子的平均；区间按重复之间的差别算。
- 作废的局（什么样的局作废，见 rules.md 第九节）和平局不算进 CR，工具会补打，补打的也算局数。所以一次 `ladder` 按 `games × repeats` 再加补打余量（5%，至少 30 局）算局数上限。两种情况会停下、不给读数，`summary.json` 里写 `stopped` 说明原因，命令退出码是 3，已经打的局照样算：作废的局到 30 局、又比打回来的一半还多；或者打到了上限还没打完。多半是你的打法在对局里碰了不许碰的东西：用 `vs` 对基线成员打几局，看 `games.jsonl` 里作废那几局的 `error`。
- `--replacing` 把你的某个成员换成这个版本，这个成员自己就不当对手了。
- **停住的重复**：你的 CR 走到离所有对手都超过 200 分，就没人可打了，这个重复会停在那里。它的读数只是界限：停在顶上的，至少有这么高；停在底下的，至多这么低。结果里会标出来。

### 2. 指定对手或职业打 N 局

```
python -m ladder.arena vs 练习场目录 --player 你的名字 --version 版本目录 --opponent 编号 --games 400
python -m ladder.arena vs 练习场目录 --player 你的名字 --version 版本目录 --class 龙族 --games 400
```

- 结果：胜率和 95% 区间。先后手各一半。用 `--class` 时，这个职业的成员轮流当对手。`errors` 是你这一方出错判负的局数，`void` 是作废的局数。
- 作废的局在 `games.jsonl` 里 `error` 写着原因，前提是对手是基线成员或「基线快照」锚点（主持方的打法，这时只有你的代码是选手的）。对手是别的选手的成员或名人堂锚点时，只写「作废」，不给细节：原因可能在对方那边。
- **比两个版本**：

  ```
  python -m ladder.arena vs 练习场目录 --player 你的名字 --version 新版本 --same-as 旧的那次的编号
  ```

  这会把那一次的局原样重打一遍：同样的发牌、同样的对手、同样的先后手、双方打法用同样的随机种子，只换你的版本。结果里有两版的配对差（百分点）和区间，还有「两版都赢」「都输」「只有新版赢」「只有旧版赢」各几局。真正提供信息的是结果不同的那些局。

  `--same-as` 只能指这一期用 `vs` 打的某一次。上一期的不行：换了一期，对手的打法可能换过，拿同一批局重打会看出谁改了打法（成员打法是第几版不对外说）。

### 3. 从你某一局的某个局面接着打

```
python -m ladder.arena resume 练习场目录 --player 你的名字 --run 那一次的编号 --game 那一局的编号 --decision K --version 版本A [--version 版本B] --continuations 50
```

- `K` 是你在那一局里做的第几个决定，从 0 数，`replay` 里有编号。
- 工具把那一局按原样重打到你的第 K 个决定，然后换上你给的版本接着打。
- 续打 0 用那一局原来的牌序和随机结果。续打 1～N 把双方都还没见过的牌序重新洗、以后的随机结果重新定；每个续打对每个版本都一样，所以两个版本可以一局一局地比。
- 结果：每个版本赢了几局。给了两个版本时，还有配对差和区间。
- 隐藏信息由工具保管，你看不到。
- 注意两点：
  - 续打时，双方的打法都是在那一步新建的，之前攒下的内部状态不带过来。写了回合开始钩子 `turn_start` 的打法，钩子在续打的那一步跑（打法对象第一次被问到的那个决定），可能落在回合中间；要比两个版本的规划，从某个回合你的第一个决定续打。
  - 续打的对局和正式对局一样有时限：一步超过 30 秒墙钟（回合开头那一步的 30 秒里包括钩子）判这一方输，载入超过 120 秒那一局作废；卡住的只是那一局。
  - 续打出来的局不能再续打，也不能回放（续打点之后重新洗了牌）：从原来那一局开始。
  - 只能从这一期练习场里打的局续打，理由同 `--same-as`。正式对局（下面第五节的 `F期号`）只能回放，不能续打。

### 4. 看回放

```
python -m ladder.arena replay 练习场目录 --player 你的名字 --run 编号 --game 编号
```

- 给你自己那一侧在每个决定时看到的局面（和你的打法拿到的公开局面一样），加上双方的全部走法。
- 对手的走法照真人看到的给：对手打出、亮出的牌看得到；对手换牌只显示「换牌」，不显示换了哪几张。
- 不给对手的卡表、手牌、牌序，也不给种子。

## 四、局数、时间、种子

- 每期最多 6 万局（第 3 期起；前两期 2 万）。每一局都算，续打每个算一局。要超过的那一次不跑。局数只按局算，不按算力：用了回合开头预算的打法每局打得慢，同样的局数要等更久（K = 2 时，预算用满的打法每个自己回合大约花默认打法的 3 倍，对默认打法的一局大约要 2 倍的时间；看你实际用了多少），12 小时里实际打得完的局数也少。
- 一次最多 2000 局（`ladder` 按 `games × repeats` 加补打余量算；默认的 600 × 3 = 1800 局，加余量 1890 局，在里面）。多的分几次打。一次跑的时候整台电脑都在打你的局，别人排在后面。
- 排队的命令轮到它时再查一遍：前面跑完的局已经算进去，剩下的局数不够、或者已经过了截止，它就不跑（退出码 2）。
- 时限：五个人共用同一个截止时刻（开窗时间加 12 小时，第 3 期起；`field` 里 `window` 的 `deadline`，UTC），不是从你开工起算。过了截止，练习场不再开跑。
- 种子只用你自己那一段调参种子，由工具替你管，不告诉你具体号码。要在同一批局上比两个版本，用 `--same-as`。
- 电脑上同一时间只跑一个人的对局，别人在跑时你的会排队。**排队按选手轮流（第 2 期起）**：练习场空下来时，先跑主持方的（收提交、检验、期末），再轮到最久没轮到的那位选手，跑他排得最早的一条命令；一条命令算一轮，不管多少局（也不管你的打法一局要多久）。同时挂几条命令不会让你多轮到，只是自己的命令按先后排着。排队的命令要一直开着，进程停了它的位置 30 秒后就没了。
- 要撤掉自己排着的命令，只停命令行里同时有 `ladder.arena` 和 `--player 你的名字` 的 python 进程。别按模型名、目录名这类宽的条件去停进程：会把别人的、主持方的，连你自己这个会话一起停掉。别的选手和主持方的进程一律不许停。

## 五、结果放在哪

- 都在 `练习场目录/players/你的名字/` 下面：
  - `runs/编号/summary.json`：这一次的结果；
  - `runs/编号/games.jsonl`：每一局，你一侧的；
  - `runs/编号/replay-局号.json`：回放；
  - `count.jsonl`：你的局数账。
- 每期天梯打完，主持方再放两样进来：
  - `members.json`：你每个成员（按你起的成员名）现在的匿名编号、职业、还在不在池子里；
  - `runs/F期号/`：这一期正式天梯里你的成员打的每一局，你那一侧的，格式和练习场的一样，每局多一项 `member`（是你哪个成员打的）。对手只标匿名编号和职业。局号从 `F期号-00001` 重新编。你自己的两个成员对上的局有两份，一边一份。用 `replay --run F期号 --game 局号` 看回放；不能续打，也不能拿来 `--same-as`。正式对局不算你的局数。
- 检验结果和这一期哪些职业的新卡组已经收下（合并期里新卡组可交可不交；第 4 期特殊期见 special-P4.md），在你自己目录的 `receipts\` 里（submit.md 第五节）。
- 别的目录不是给你的，不要读（红线 5）。
