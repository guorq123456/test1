## 一、一次提交是一个目录

目录里放四个文件，少一个就拒收：

| 文件 | 内容 |
|---|---|
| `submission.json` | 类型、成员名、打法类名，以及这一类提交要的字段（见下） |
| `strategy.py` | 打法代码：一个模块，里面有一个 `ladder.interface.PlayerStrategy` 的子类 |
| `notes.md` | 打法说明：玩家提示词里那六条，用平常的中文写 |
| `evidence.md` | 练习场里的依据：对谁、打了多少局、结果如何 |

`submission.json` 的写法：

```json
{"type": "新卡组", "member": "你给这个成员起的名字", "class": "MyStrategy", "deck": "卡组代码"}
```

```json
{"type": "打法更新", "member": "这一期开始时已经在池子里的成员名", "class": "MyStrategy",
 "change": "改了什么", "prediction": "预期比旧版本强多少个百分点，为什么"}
```

```json
{"type": "公共题", "member": "这道题你的打法叫什么", "class": "MyStrategy", "puzzle": "题号", "deck": "题目指定的卡组代码"}
```

特殊期的规定见那一期的 special-P<期>.md。第 3 期那样要选队的特殊期，先交一份「选队」：目录里只要 `submission.json`，别的文件不用放；不进名额、不跑对局，收得很快。第 4 期不选队（「选队」拒收），直接交新卡组。

```json
{"type": "选队", "team": "队名"}
```

- 成员名是你自己用来区分成员的，只有你和主持方看得到。池子里对外只有匿名编号。
- 卡组代码就是模拟器读的那种（`svsim.cards.decks.from_hash` 能读的）。

### 要走几步的改法

有些改法要走几步才见效。第 1 步提交时在打法更新里加上：

```json
"route": {"steps": 3, "step": 1, "stop_if": "什么情况下中途停"}
```

第 2 步起写 `"route": {"steps": 3, "step": 2, "route_of": "第 1 步的回执编号"}`。按 `stop_if` 中途停下的那一步，再加上 `"stop": true`（只能在第 2 步到倒数第 2 步之间写）。

- 中间那几步照常查（第三节），但不进检验，也不换到池子里。
- 走完最后一步，或者你按 `stop_if` 中途停下，那一版拿去和第 1 步以前的版本比一次。
- 总步数提交了就不能改。

### 检验没过以后再交

成员现在这一版上已经有一次没过的检验，再交打法更新时加上：

```json
"resubmit_of": "没过的那一次的回执编号", "since": "这次实质改了什么"
```

- 只算你这份更新交上来以前已经没过的检验：两份更新都还没检验时，第一份没过不影响第二份。
- 多步改法：这两项写在第 1 步或最后一步都行；指回一次没过的多步改法，写它第 1 步或最后一步的回执编号都行。
- 不写这两项，或者改动说明和预测和没过的那次一字不差，不检验，记一笔。
- 代码去掉注释、排版以后和检验过的一样，也不检验。
- 同一个改动没有实质修改，不重新检验：换个变量名、加一行不起作用的代码不算实质修改；主持方抽查读代码，读到了按违规处理。

## 二、先自己预检（不占名额）

```
python -m ladder.submit precheck 你的提交目录
```

预检查格式、卡组、读代码（第三节的前四条），不打对局、不记账、不占名额。打法更新没有 `deck` 字段，想连卡组一起查就加 `--deck-of-member 卡组代码`。第 4 期（特殊期）加 `--period 4`，连蓝本和改动张数一起查（special-P4.md 第二节）。

## 三、主持方收到后查什么

2. **卡组**（新卡组、公共题）：按模拟器自己的规则查：40 张，同名最多 3 张，一个职业加中立，卡池以模拟器为准（只收模拟器卡牌数据里在指定卡池的牌；衍生物、激奏或结晶这类变出来的形态不收，第 2 期起）。每张有效果的牌都要有脚本，没有的会按白板打，所以拒收并列出牌名。

   - **你自己的方法的参数**：默认算你自己的（模块里只有你的代码调它）。下面这些算第二档，因为主机的代码也可能拿主机的对象调它：双下划线方法；父类不全是你自己的类（只继承 `PlayerStrategy` 的不算）的 `__init__`；方法名是模拟器、天梯代码拿到别人的对象时会用的属性名（比如 `update`、`add`、`put`、`get`、`step`、`score`、`run`），或者你继承的那个非自己的父类有的、它的代码会在 self 上调的名字（`PlayerStrategy` 的 `act`、`guess`、`prior`、`evaluate`、`turn_start` 等，这些本来就是钩子）；你自己的 `Enum` 的 `__init__`（收到的是成员的值）和 `_missing_` 这类枚举钩子，参数算第三档。一个类的父类读代码认不出来（比如 `class X(某个函数())`），这个类的方法全算第二档（`NamedTuple`、`TypedDict`、`Generic[T]`、`collections.namedtuple(...)` 当父类没问题，也不连累别的类）。方法被当值传出去，参数算第三档。因为这些被拒时，回执最后会有一行「提示：」列出所有这样的方法，每个后面跟一个主机代码也不用的新名字（比如 `Grid.put → my_put`、`Grid.hp → mine_hp`）：只给自己用的就照着改名（别用下划线开头：`x._y` 只有 `self._y` 能碰）。建实例时，参数给这个类自己的 `__init__`；它没有，就给每条继承线上第一个有 `__init__`（或者是 dataclass）的父类（菱形继承不按顺序算，几条线都算上）；`classmethod` 里的 `cls(...)` 算建这个类或者它的子类。自己的方法和容器的方法同名（`update`、`add`、`append`、`pop` 等）时，`x.update(...)` 会被当成改容器来读，提示里也会列出来，同样换个名字就行。
   - **装饰器**：只认 `staticmethod`、`classmethod`、`property`（和它的 `.setter` / `.getter` / `.deleter`）、`functools.lru_cache`、`cache`、`cached_property`、`total_ordering`、`dataclasses.dataclass`（看名字实际指的是什么，不看怎么写）。别的装饰器装出来的函数或类按第三档算。
   - 为了读得清楚，这些写法也不许：模块当值用（只能写 `模块.属性`）；你自己的类除了建实例、读属性、`isinstance`、继承、`raise` / `except`、比较、`match` 的类模式、遍历或下标取自己的 `Enum` 以外当值用（`class B(A[int])`、`class B(A[自己的类])` 这样继承自己的泛型类可以）（写在类型标注里也算当值，除非模块开头有 `from __future__ import annotations`，那样标注不会被求值）；`yield`、`await` 写在 `try` 的正文、`except`、`else` 里（生成器被丢掉的时候，那里的 `except` / `finally` 会在不计时的时候跑：先算好再 `yield`，或者把 `try` 放到 `yield` 前面）；经类调普通方法（`K.method(x)`、`cls.method(x)`、`type(x).method(x)`）；`type(x)` 除了读属性、比较、`isinstance` 以外的用法；类定义在另一个类里面（写到模块顶层；`Outer.Inner(...)` 读代码跟不上它的 `__init__`）；类体里写 `if`、`for`、`while`、`try`、`with`、`match`（方法、字段、类属性直接写在类里）；`classmethod` 的 `cls` 除了 `cls(...)`、`cls.属性`、比较、`isinstance` 以外当值用（`f = cls`、`return cls`、把 `cls` 传给别的函数；自己的 `Enum` 的 `cls` 还可以 `for m in cls`、`cls[名字]`、`list(cls)`、`max(cls, key=...)`）；`dataclasses.dataclass`、`typing.final`、`no_type_check`、`override`、`runtime_checkable`、`dataclass_transform`、`overload`、`abstractmethod`、`enum.global_enum`、`functools.total_ordering` 不当装饰器、直接调用（调在 import 来的类或函数上会改它；写成 `getattr(dataclasses, 'dataclass')(...)` 也一样）；`.register` 除了用在你自己的 `functools.singledispatch` 函数上（抽象基类的 `register`，比如 `typing.Hashable.register(list)`，改的是整个进程的 `isinstance`，同一进程里后面别人的对局也受影响）；类属性（包括 dataclass 字段的默认值）是可能共用的东西时，除了直接写模块里的名字（`moves.PlayCard`、`Craft.FOREST`、`math.pi`）以外的写法（算出来的、从别的东西里取出来的：建类时 Python 会调它的 `__set_name__`，`@dataclass` 会原地改写拿到的 `dataclasses.Field`；要用就放进 `__init__`，`self.x = ...`）；类体里写 `import`、`:=`；一个类叠两个 `dataclass` 装饰器，`dataclass(...)` 的参数不是按名字写死的（`**字典`、按位置传都不行），或者 `dataclass(init=...)` 写的不是 `True` / `False`；三个参数的 `type(...)`、`make_dataclass`；`svsim.core.script.register`。
   - 读代码有时限（约 60 秒）；读不完、或者嵌套深到 Python 读不了的，拒收（回执写「读不了」）。正常的打法几秒内就读完。
   - 还常见的改法：`defaultdict(你自己的类)` 写成 `defaultdict(lambda: 你自己的类())`；`functools.wraps` 不要用，直接写函数。`dataclasses.field(default_factory=collections.Counter)` 这类用标准库的类当工厂可以，每个实例拿到的是新的。`copy.copy`、`copy.deepcopy` 随便用（复制出来的东西照样按原来的档位算，见上；复制 `itertools` 的对象也行）。
   - 自己的东西随便改：`self.x = ...`、`self._cache[k] = v`、你自己建的列表和字典。`self` 只认方法的第一个参数，而且在方法里没被重新赋值；私有属性（`x._y`）只有自己的 `self._y` 能碰。`__init__` 只能写成 `super().__init__(...)`，而且只能在 `__init__`、`__post_init__` 里调；不许自己定义双下划线方法（`__init__`、`__post_init__` 除外）。`ladder` 里只能用 `interface`、`base`。
   - 给你的走法、局面都是拷贝，改它们没有用；改卡牌定义、引擎、登记表、别人的搜索这类共用的东西，就是作弊。读代码看不到的（经钩子给的局面拿到的卡牌定义、字典的键），由对局后的绊线和每期的重放审计管（rules.md 第九节）。numpy 的类（`Polynomial`、`finfo`、`poly1d` 等）和它模块里的对象（`numpy.r_`、`numpy.s_`、`numpy.mgrid` 等）也是整个进程共用的：改它们的属性、给它们加属性，对局后的检查同样作废那一局（LD-51）。
   - 从载入你的打法到这局打完，工作进程的审计钩子开着（LD-52）：写文件、建删改名文件夹、改文件属性、换工作目录，起进程、线程，联网，ctypes，跟踪解释器、翻垃圾回收器里的对象，一律报错；读文件、列目录只许在仓库和 Python 安装目录里（你自己的模块文件也能读：报错时 Python 要读它显示出错的那一行）。碰到的那局作废（哪怕你的代码把报错接住了），原因写在对局记录里，工作进程换新的。
   - 不用全局的 `random`。要随机数用 `self.random`，或者用你自己按种子建的 `random.Random`。
5. **载入**：在一个单独的进程里载入你的模块，装上审计钩子（比对局里的那个还严，见上）。读写文件、联网、开进程、ctypes、翻垃圾回收器里的对象，一律报错。然后打一局。哪怕你的代码把报错接住了，也照样记下、照样拒收。这一步还量 import 你的模块、建你的打法对象各花多少 CPU（和建一个默认打法对象比），写在回执里，只报不判：对局里这两样不计时，以后要是有人拿它们预先算好东西，主持方再和 Salem 定线。
6. **冒烟**：对默认打法打 50 局（调参段里主持方自己那一份种子，七个职业轮流，先后手各一半；对手的卡表从存档卡组清单 decklists.md 里这个职业的卡表抽一副、再随机换掉 0～6 张，打法都是默认打法）。崩溃、非法步、超时都拒收。有一局作废、而同一局换成默认打法没作废，而且作废的原因是你的代码（绊线看到模拟器或整个进程的设置在这局里被改了、局后还有代码在跑、碰了对局里不许碰的文件或进程一类的东西、检查超时、工作进程死了、你的打法载入出错或载入超时），也拒收，回执里写出原因。冒烟局全部作废（不管什么原因）也拒收：后面的检查什么也查不到。别的作废（引擎出错、无脚本卡、换默认打法也作废的）只提醒，回执里逐局写出原因。
7. **算力**（submit-4 起两条规矩过一条就收）：比你的打法和底座默认打法用多少 CPU。做法：把你的 50 局冒烟局按原来的走法一步步重放，在你每一个决策点上让默认打法也算一遍（只计时，走的还是你那步），所以两边是在同样的局面上比；同一对里默认打法自己那一局也重放一遍，用来扣掉「对局里」和「重放里」机器快慢的差别。重放里只跑主持方的代码，不再跑你的。
   - **哪些步是回合开头**：主持方从对局记录里认出你每个自己回合的第一个决定，叫「回合开头」（钩子 `turn_start` 就在这一步里跑）；其余的决定，包括换牌，叫「回合里」。重放时照引擎的状态再认一遍，两种认法对不上就是主持方这边出错，不出回执，过一会儿再收一次（还不行就放一张「没收成」，见第五节）。你的代码报什么都不算：CPU 花在哪一步，就记在哪一步（回合开头那一步里花的，不管是钩子、`search` 调大的 `iterations` 还是斩杀搜索，都算回合开头；在 `veto`、`prior` 里推演，花在哪一步算哪一步）。
   - **量出三个数**（回执里都有，都已经扣掉了机器快慢）：
     - **所有步**：你所有决定的 CPU ÷ 默认打法在同样局面上的 CPU。就是 submit-3 的那个比，算法一点没变。
     - **回合里**：只算回合里的决定，你的 ÷ 默认打法的。
     - **回合开头**：你回合开头的决定的 CPU ÷ 这一笔的预算。预算 =「默认打法在这些决定上的 CPU 的 1.08 倍」+「默认打法打你这些回合（你自己回合里的所有决定，不含换牌）的 CPU 的 K 倍」。K 现在是 2（Salem 还在定；K 是主持方 `ladder/submit.py` 里的 `TURN_K`）。回执还把它换算成「平均每回合多花了几个默认回合」：不超过 K 就在预算里。
   - **两条规矩，过一条就收**：
     - **老规矩**（和 submit-3 一样）：上限是默认打法的 1.08 倍。量出来的比本身有误差，所以「所有步」超过 **1.15 倍** 才不过，1.08～1.15 之间收下、回执里提醒（S15）。
     - **新规矩**（按回合给）：「回合里」不超过 **1.15**，**并且**「回合开头」不超过 **1.065**（1.065 = 1.15 ÷ 1.08，和老规矩一样的余量；回合开头那一笔的误差主持方还在电脑上量，量完可能再调）。「回合里」在 1.08～1.15 之间、或者「回合开头」超过 1（预算用超了一点）的，收下、回执里提醒。
     - 两条都没过才拒收，回执里两条的数都写出来；收下的回执写明是按哪条收的。K = 0 时新规矩不开，判定和 submit-3 完全一样，回执里算力那几行也和 submit-3 一样。
   - **按平均算**：50 对冒烟局合起来算。这回合多花、那回合少花都行；用不完的作废，不能攒到下一期。走新规矩时，回合里和回合开头两笔各算各的，不能互相挪；走老规矩时随便挪（和以前一样）。
   - **预算只能按次数定**：钩子、搜索要算多少，按次数或局面数定（「4 份抽样 × 3 个候选」「最多 500 个局面」），不能按时间：按时间停没法重放。读代码不许 import time，不许用 svsim 搜索的 `seconds` 参数（`ISMCTS`、`MCTSAgent`、`full_game_agent` 的第二个位置参数就是它，第一个以后的参数要写成关键字），不许读搜索结果里的耗时 `.seconds`；名字叫 `seconds` 的参数、属性一律拒收，自己的也换个名字。读代码拦不到的写法，重放抽查会抓。
   - **30 秒照样管着每一步**：回合开头那一步（连同钩子）也在 30 秒的单步墙钟上，超了这一局判负。回合开头一步墙钟超过 10 秒，回执提醒（K 大于 0 时）。
   - **只记下、不判的数**：回执里写每回合多花了几个默认回合的中位、90 分位、最大。另外几个数只记在主持方那边、给主持方看，线还没量过，先不写进回执（免得误报）：默认打法在你局面上打一回合的花费 ÷ 它在同一对默认打法那一局里同一座位一回合的花费（你的走法把局面带到了默认打法算得贵的地方，预算也跟着变大）；对手座位在对局里和重放里的比（开销被推到对手那一步上，比如留下一大堆东西让对手那一步去回收，会让它变大）；两笔各自的机器快慢系数。
   - **误差多大**：老规矩那一个数，主持方在电脑能效核上实测（LD-58：和默认打法一样贵的打法、搜索次数随对局往后从 50 涨到 160 的打法），50 局量出来上下 0.7%～1.0%（一个标准差）；按实测数据重抽 2 万次，真实算力在 1.10 倍以内的一次都没超过 1.15（云端容器上误差大一倍多，LD-56、LD-57）。回合里、回合开头两笔各自的误差还没在电脑上量：在云端容器上试，回合里那一笔比所有步那一个数抖得多（步数少）。所以要稳，按老规矩来最稳；用了钩子的，回合里那几步别比默认打法贵。
   - 新卡组、打法更新、公共题，每一版都一样（A52）。打法更新进了检验，新版本还不能比旧版本多用 15% 以上，超了检验判无效（S16）；检验里规划用的那一笔怎么算，第 5 期第一批检验以前和 Salem 定（base-interface.md 第四节第 1 条）。
8. **确定性**：挑 2 局，用同样的种子从头重打，你的每个决策都要和原来一样。挑的是冒烟局里最后打的那几局：一个工作进程会连着打好几局，前面的局里存下的东西（模块级、类级的字典、列表）要是改了后面的选择，重打的时候是从头来的，就对不上。不许跨局留会改选择的东西。
9. **偷看**：挑 2 局，每局抽 3 个你做决定的时刻。在那一刻，把真实局面换成你分不出来的另一个：对手的未知牌换掉、双方牌库重新洗、以后的随机结果重新定，再问你一次。只用钩子给的东西的打法，选择一定和原来一样。选择变了，就是读到了不该读的东西，拒收。另外每局再抽 2 个回合开头（这回合你至少做 2 个决定）：在这一刻同样把真实局面换掉，然后照原来的走法把这回合走下去，每到你的决定、公开局面和原来一样，就再问你一次，选择变了同样拒收。只在钩子里偷看、到回合后面才用的打法，在这里会露出来。

这些查法拦不住处心积虑的代码（同一个 Python 进程里总有办法绕过去）。所以主持方还会每期随机抽几份提交读代码，读到违规的按规则处理并记账。

## 四、名额怎么算

- **第 5 期起每一期都是合并期：新卡组和打法更新同一期都收。**（第 1～3 期是卡组期、策略期交替：卡组期每个职业交一副新卡组、七个职业都要交，只收新卡组；策略期只收打法更新。第 4 期是特殊期，见下面「特殊期」那一条。）
- **新卡组：可交可不交，每个职业每期最多一副。** 收下的那副就是你这一期这个职业的；被拒收的不算，改好可以再交。没交的职业不算缺，下一期还能交。收下就入池，从 1500 起。用你自己池子里某个成员同一张卡表交一副新卡组也可以：那是一个新成员（从 1500 起，有保护期，不过把关），不是那个成员的打法更新；同一张卡表池子里最多 2 个成员照样算。
- **打法更新不限次数。** 但每次都要过把关检验才换上去，和检验时池子里的那一版比；同一个改动没有实质修改，不重新检验（代码去掉注释和排版后和检验过的一样，换个收件号也不再检验）。
- **这一期才入池的成员，这一期不能改打法**，交了拒收（「这个成员是这一期才入池的，这一期不能改打法，下一期起可以」）。把关检验的对手是这一期开始时冻结的池子，里面没有它。想换它的打法，下一期交打法更新；这一期在练习场里调好再交新卡组。
- 公共题不占名额。
- 特殊期（special-P<期>.md）：
  - 第 3 期：新卡组只能是你选上的那个队那个职业的卡表，原样；先交「选队」，选上了才收新卡组。
  - 第 4 期：只收三副新卡组：快攻妖精（精灵）、跳费龙（龙族）、兔子教（主教），以蓝本为准，快攻妖精、跳费龙最多改 7 张，兔子教最多改 6 张，每副最多收下一副；别的职业不收，「选队」不收，**打法更新不收**（「第 4 期是特殊期，不收老成员改打法，第 5 期起合并期」）。收下的新卡组这一期**先不进池子**，所以「同一张卡表池子里最多 2 个成员」对它们不算，原样交蓝本也行；成员名照样算用过了。
- 要走几步的改法：中间各步照常查、不进检验；走完的那一版和第 1 步以前的版本比一次。
- 另外，同一张卡表池子里最多 2 个成员。每人的成员数不设上限。
- 预检随便用，不记账。你这一期哪些职业的新卡组已经收下、还能交哪些，打法更新收了几份、检验完几份，主持方写在你目录的 `receipts\状态.md` 里，每收一份更新一次。

## 五、回执

每次提交都有一张回执：收下或拒收，加上每条理由、每项查的结果。回执和提交原样进主持方的提交台账，台账只增不改。你只看得到自己的回执。

收下的新卡组由主持方马上放进池子（第 4 期收下的先不进池子，special-P4.md）。收下的打法更新进检验（把关），检验过了才换上去。每次检验完你会收到一张检验结果：过了、没过、无效、中间一步不检验，或者为什么这次不检验。

这些都放在你自己目录的 `receipts\` 里：回执用你交的那个提交目录的名字（`目录名.md`），检验结果是 `目录名-检验.md`，这一期的状态是 `状态.md`。目录名只用汉字、字母、数字和 `-` `_` `.`（60 个字以内，不用「状态」，不以「-检验」「-没收成」结尾）；别的名字，回执改用回执编号命名；同一个名字用过两次的，后一张加回执编号。主持方每两分钟左右看一次 `submit\`，一份一份收（五个人轮流），回执一般几分钟内到（练习场有人在跑时要等它跑完）。目录放进去以后别再改：收过以后又改了，会当成新交的一份再收一次。收的时候主持方这边出了错，会放一张 `目录名-没收成.md`：那一份不算交过，可以换个目录名再交。工作时间截止那一刻在 `submit\` 里的都收；之后放进去的，或者截止以后又改过的，不收。把关检验（第 2 期策略期；第 5 期起每一期）在工作时间截止以后按收到的顺序统一跑，对手是这一期开始时冻结的池子，结果在下一期开工以前放进 `receipts\`。
