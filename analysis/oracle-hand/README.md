# 手牌全知上界：知道对手手牌，在等算力下最多值多少 CR（预注册稿）

**条件**：这个实验里 A 知道对手的手牌；其余对局照常是对手卡表已知（牌序、手牌未知）。

**状态**：预注册稿（架构线程 17:0x 布置，协调线转），写在任何结果之前；等建造线加 `+oracle` 选项。这是测量，不是装机门：A 在作弊，不能上线。

**目的**：给「对手手牌推断」这条线定一个天花板。`+infer` 把抽样的重合度提高了约 2%（`../hand-inference-check/README.md`）；全知是推断能做到的极限，量出它在等算力下值多少 CR，就知道这条线最多还能挖多少。

**`+oracle` 的定义**（须在开跑前由建造线写清楚，我照抄到这里）：
- 建议：A 的确定化里，对手手牌用真实的牌；对手牌库的顺序仍然未知、照常抽样。这样量的是「只知道手牌」的价值，和推断线能达到的东西同一个口径。
- 如果建造线做成连牌库顺序也知道，那量的是「完全信息」，要在这里改写口径。

**门**（同 B 线的两格）：
- A = `mcts:200+plan+learned+phased+oracle`，B = `level-strong`；定长 300 对 × 两格：

| 格 | 模式 | 种子库 |
|---|---|---|
| 跳费龙镜像 | 直接对打（`--fixed --max 600`） | 62300000 |
| 连击妖对机锋 | `--versus level-strong`（`--fixed --max 1200`），A、B 打连击妖，C = 强档打机锋 | 62400000 |

- **算力**：A、B 都是每步 200 次迭代，量的是同样搜索量下信息的价值。门行里的 `ms` / `ms_b` 照报（全知不用为手牌抽样，每次迭代可能更快），只作旁注。
- 输出：`analysis/gates/oracle/<我方>_<对方>.jsonl`。

**读法**：
- 每格和两格合并（按格分层重抽）的一对得分、CR 及 95% 区间。
- **建议的下游判断**（门槛待架构线程定，结果出来前定死）：
  - 合并 CR 的上沿 < +30：知道手牌在等算力下也值不了多少，手牌推断线降级。
  - 合并 CR 的下沿 > +30：值得继续投手牌推断。
  - 其余：分不开，照实记。
- 这不是装机门，不设否决。
