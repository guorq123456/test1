# 手牌全知上界：知道对手手牌，在等算力下最多值多少 CR（预注册稿）

**条件**：这个实验里 A 知道对手的手牌；其余对局照常是对手卡表已知（牌序、手牌未知）。

**状态**：**预注册定稿**（架构线程 17:0x 布置、17:1x 定读法，之后改成三档，见「读法」），都写在任何结果之前；等建造线加 `+oracle` 选项。这是测量，不是装机门：A 在作弊，不能上线。

**目的**：给「对手手牌推断」这条线定一个天花板。`+infer` 把抽样的重合度提高了约 2%（`../hand-inference-check/README.md`）；全知是推断能做到的极限，量出它在等算力下值多少 CR，就知道这条线最多还能挖多少。

**`+oracle` 的定义**（架构线程定）：对手的真实手牌直接进 A 的确定化（determinize），对手牌库的顺序仍然随机抽样。量的是「只知道手牌」的价值，和推断线能达到的东西同一个口径。

**门**（同 B 线的两格）：
- A = `mcts:200+plan+learned+phased+oracle`，B = `level-strong`；定长 300 对 × 两格：

| 格 | 模式 | 种子库 |
|---|---|---|
| 跳费龙镜像 | 直接对打（`--fixed --max 600`） | 62300000 |
| 连击妖对机锋 | `--versus level-strong`（`--fixed --max 1200`），A、B 打连击妖，C = 强档打机锋 | 62400000 |

- **算力**：A、B 都是每步 200 次迭代，等算力天然成立（全知只是把抽样换成真实手牌，开销约等于 0）。门行里的 `ms` / `ms_b` 照报，核一下。
- 输出：`analysis/gates/oracle/<我方>_<对方>.jsonl`。

**读法**：
- 每格和两格合并（按格分层重抽）的一对得分、CR 及 95% 区间。
- **合并胜率折成 CR，当作「手牌推断的价值上界」。**
- **下游判断，三档**（架构线程在 5c293a6 之后改定，**改在任何门结果出来之前**；替换原来那一条「上沿 < 56%」）。看的是两格合并的 CR 区间，用 Salem 的尺度（每 logit 236 CR），+60 CR ≈ 一对得分 56.3%：
  - **上沿 < +60 CR**（< 56.3%）→ 「从对手打出 / 留下的牌更新信念」那条线不做。真实的推断只能拿到上界的一部分，上界都不到 +60 CR，就不值得投。
  - **下沿 > +60 CR**（> 56.3%）→ 投，设计「从对手打出 / 留下的牌更新信念」。
  - **区间跨过 +60 CR** → 交 Salem 定。
  - 原来那一条（5c293a6：合并上沿 < 56%，约 +57 CR，就不做；≥ 56% 就做）作废；我更早建议的 ±30 CR 门槛也作废。
- `+oracle` 只给手牌，牌库顺序照常随机（见上面的定义）。所以这个上界是「只知道手牌」的上界，不含「知道牌序」。
- 这不是装机门，不设否决。

## 结果与正式判定（RC 64ab2fe，代码 91aecd9）

条件：A 知道对手的手牌（`+oracle`），其余照常，对手卡表已知（牌序、手牌未知）。

我用 `pooled.py` 复算了门文件（复制在 `../gates/oracle/`，输出 `pooled_report.txt`），和 RC 报的数逐位一致；两格的种子各 300 个，不重不漏。

| 格 | 种子库 | 一对的得分（95%） | CR（稳态式） | A ÷ B 每搜索决策毫秒 |
|---|---|---|---|---|
| 跳费龙镜像（直接对打） | 62300000 | 49.2%（46.3%～52.0%） | −8（−35～+19；−7） | 0.985 |
| 连击妖对机锋（`--versus`，C = 强档打机锋） | 62400000 | 47.5%（43.6%～51.4%） | −24（−61～+13；−20） | 0.987 |
| **两格按对合并 600 对（按格分层重抽 4000 次）** | | **48.3%（46.0%～50.7%）** | **−16（−38～+7；−13）** | |

- **判定：上沿 +7 < +60，按三档读法，「从对手打出 / 留下的牌更新信念」这条线不做。**
- 算力匹配：两格的毫秒比都在 0.90～1.10 内。两格并行各开 8 个进程，所以毫秒绝对值里有并发负载，只看比值。

**为什么全知了也不涨：现架构根本读不到对手手牌的内容。**这是我核出来的，不是推测：
1. **装机向量里没有对手手牌的内容信息**（`learn.features`；24 个装机模型全是 version 2，`potential` 都关，额外特征只有 C2 三格的 `hand`）：
   - 对手一侧按 `hidden=True` 算。和手牌有关的只有：
     - 手牌张数：全知和抽样一样。
     - v2 的手牌角色：用的是「手牌 + 牌库」整池乘以手牌占比，哪几张在手里、哪几张在牌库，算出来完全一样。
   - C2 的 `hand` 只算我方手牌，原注释写明「The opponent's hand: not added」。
   - `potential`（从手牌算下回合伤害）在装机模型里是关的。
2. **强档 v2s 不打对手回合**（建造线 16:29 按 `mcts.py` 复核过）。回合中的叶子也用 ended 模型。所以对手手牌进入决策的唯一通道就是评估器特征，而上一条说明这条通道是空的。
3. **实测**（`channel_check.py`，输出 `channel_check.txt`；在 RC 的检出 64ab2fe 上跑）：
   - 方法：两格各 6 局快速对局（greedy+plan+learned）。同一个局面用同一串随机数各确定化一次，一次照常抽手牌，一次用 `+oracle` 的真实手牌；比较装机评估（ended 和 act）。
   - **局面本身**：跳费龙镜像 462 对、连击妖对机锋 576 对，**分数差全是 0**，特征逐位相同。抽到的手牌和真实手牌没有一次相同。
   - **把这一回合剩下的部分用同样的走法打完，再比**（搜索的叶子就在这里）：回合内的随机效果保持相同时，差也是 **0**；照搜索的实际做法（两次确定化各自重设状态的随机数）时，差最大 0.23 和 3.6 分（÷ 8 = logit）。这部分差完全来自回合内随机效果抽到的数不同，和对手手牌无关。
- **所以这道门在机制上等于一次「A 对 A」**：A 和 B 只差在随机数。合并 48.3%（区间含 50%），和恒等检验一样。
- 协调线列的三个候选解释里：(a)「采样把不确定性平均掉了」不对，不是平均掉，是根本没有地方读；(b)「给了评估器没见过的分布」不对，特征逐位相同，评估器看到的东西完全一样；**(c) 噪声是对的，而且有机制上的原因**：A、B 的决策只差在随机数。
- **结论的正确写法**：**现架构用不上对手手牌的信息**（评估器没有读它的特征，搜索又不展开对手回合），**不是「手牌信息没价值」**。这个上界量的是「现架构下全知值多少」，不是「对手手牌本身值多少」。
- 对 `+infer` 的含义：同理，`+infer` 只改变对手手牌怎么抽，在强档（不打对手回合）下同样进不了决策。它提高的约 2% 重合度（`../hand-inference-check/README.md`），在强档的棋力上不会有任何体现。

## 追加实验：打对手回合 + 全知（预注册稿，排在 C3 十一门之后）

**状态**：预注册稿，架构线程 16:3x 布置（协调线同时转），写在任何结果之前。门命令里 reply 的写法等建造线给出规范，架构线程再交给 RC。

**为什么要做**：上面已经说明，在强档里对手手牌进不了决策。打对手回合（`mcts-reply` 那条路）时，对手的回合由搜索里的对手模型在确定化的局面上打，真实手牌就会影响对手怎么出牌。所以这一门量的是「搜索展开对手回合、而且知道对手手牌时，最多值多少」。

**门**：
- A = 强档 + 打对手回合（reply，规范写法等建造线）+ `oracle`；B = `level-strong`。
- 跳费龙镜像直接对打，`--fixed --max 600`，定长 300 对，**种子库 63600000**（已登记）。
- **N**：reply 比均匀搜索贵，用本机 `search_cost` 按「只算搜索步的每决策毫秒」对齐 B，±3% 以内；门行里的 `ms` / `ms_b` 照报，比值在 0.90～1.10 之外就标「算力不匹配」，只报不判。
- 输出 `analysis/gates/oracle-reply/ramp-t_ramp-t.jsonl`。

**读法（照架构线程 16:3x 原文）**：
- 下沿 > 50%：上限卡在「不打对手回合」，而不在手牌。开「建模对手」的设计讨论。
- 否则：「建模对手」整个方向在现评估器下关闭。这和早先「对手回合展开 ≈ H0」一致。
- **照记一处出入，请架构线程开门前确认**：协调线转的版本写的是「口径沿用三档，合并换单格」（上沿 < +60 关、下沿 > +60 开、中间交 Salem），和架构线程原文「下沿 > 50%」不同。在架构线程确认以前，以架构线程原文为准。

**我补的一条（归因）**：A 和 B 同时差了「打对手回合」和「全知」两样。早先的结果是打对手回合本身 ≈ H0，但那是在另一套设置下量的。如果这道门过了，要说「增益来自打对手回合 + 手牌」，就得再加一道**只打对手回合、不全知**的对照门（同一个库 63600000，有意复用、按种子配对），确认 reply 本身还是 ≈ 0。这道对照门只在 A 过门时才排；不过门就不排，结论照上面的「否则」。
