## 2. 自对弈记录管线（`vnet_data.py`）

**记录**：`python -m svsim.learn.netdata --games 50000 --deck ramp --opponent ramp --agent level-strong --explore 0 --seed 65900000`。
- netdata 的记录本来就够用：
  - 记录能逐步重放整局（种子加全部动作）；
  - `record["search"][i]` 存了每个搜索决策的各合法动作访问次数、最好一步的估值和根的 center，`learn.netdata.search_value` 由它算出行动方的胜率，也就是**根值**；
  - 胜负、种子（`rng_seed`、`agent_seeds`）都在记录里。
- 所以**状态编码可以事后从记录算**，建造线定格式不用先于自对弈：
  - `vnet_data.py export --encoder 模块:函数` 在导出时把编码加进每一行；
  - 也可以训练时边读边编码。

**每行**（一个搜索决策）：局号 g、动作下标 i、行动方、回合、自己第几回合、合法动作数、根值（行动方胜率）、各动作访问次数、该局胜负（对行动方 1 / 0.5 / 0）、split、种子。

**留出**：`g % 20 == 0` 的局（5%）。5 万局留出约 2,500 局。

**规模和时间**：
- 每局约 42 个搜索决策（冒烟测试：4 局 167 个），5 万局约 210 万行。
- 记录每局约 11 KB，5 万局约 0.55 GB。导出时如果带编码（77 维以上），约 2 GB，建议训练时边读边编码。
- 自对弈：5 万局 × 约 4.1～4.5 秒 ≈ 57～62 CPU 小时，**RC 16 进程约 3.6～3.9 小时**；3 万局约 2.2～2.3 小时。导出只是重放，几分钟。

**冒烟测试**（库外种子，4 局）：导出 167 个决策，根值、胜负、split 都对；用现有的 `learn.features.features` 当编码试过 `--encoder`，能用。搜索根值对终局胜负的 log loss，训练局 0.504、留出局 0.533，只有 4 局，没有意义，只说明 `summary` 能跑。

## 4. 价值网络门的预注册（J17～J19 已写入）

- **A** = `level-strong+vnet`（具体的串由建造线定），**B** = `level-strong`。original 跳费龙镜像直接对打，`--fixed --max 600`，定长 300 对，种子 66000000～66000299。
- **等算力**：
  - 每决策毫秒的 A ÷ B 要在 ±3% 以内，照 N 复核的规矩。价值网络每个叶子都要算一次，A 的 N 会明显小于 200，所以一定要用门命令复核：`--fixed --max 40`，20 对，种子取该库 +99000。毫秒比偏差超过 ±3% 就修一次 N = round(N ÷ 毫秒比)，再开门。
  - 门行里 A ÷ B 的毫秒比照报。
- **判定**：单门规矩，下沿 > 50%。装机要 Salem 的话。
- **开门前的检查**：
  1. **留出局 log loss**：只报不挡（J6）。在同一批留出决策上，并列报三个数：
     - 价值网络的 log loss；
     - 现装线性模型的 log loss（同样的局面，按搜索里用的方式取回合末 / 回合开头的模型）；
     - 搜索根值的 log loss（`vnet_data.py summary`）。
