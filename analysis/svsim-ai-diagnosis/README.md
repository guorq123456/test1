# 诊断：AI 为什么看不懂单个动作对整局的影响

> 对象：`guorq123456/test1` 分支 `ccr-165ad1e7-t2zmqu` 上的 svsim（影之诗：超凡世界模拟器）。
> 起点是玩家的观察："一个在人类眼里影响很大的动作，智能体可能完全不会做，所以 AI 自己和自己训练进步很小。"
> 结论里的数字都是在 `08e2de2`（已含"以起点居中"和"不在攻击后进化"两项修复）上测的，另有注明的除外。

## 一句话结论

问题不止出在评估权重上，**搜索的结构**也有问题：

1. 回合内的 ISMCTS 把每个节点的价值算成**所有试过的后续的平均值**。可是在自己的回合里没有对手，一个动作的价值应该是它**最好的后续**。用平均值，任何要两三步配合才兑现的动作（先进化再打、打小牌攒连击、弹回手再出、先解场再出牌）都会被它后面的烂分支拖低。所以 AI 系统性地不做这类动作，而且多给算力也补不回来。
2. 学习版评估**只在"破魔虫 vs 跳费龙"一个对局里学过**。换个对手，它的判断就失灵：对手的守护、必杀、屏障、威慑这些系数全是 0，自信也是虚的。
3. 有几样对局里很重要的东西，评估**根本看不见**（当前 PP、连击数、倒数、手里是哪张牌、随从的能力），有一样**算反了**（送给对手的诅咒纹章被算成对手的资产）。线性模型加这组特征，自对弈再多也只能重新分配这几项的权重，所以进步小。

把第 1 点改掉（**只改回传方式，同样 200 次迭代，速度不变**），在 `08e2de2` 之上实测：

| 对局（各 200 局，座位轮换，同一批种子） | 被测的一方 | 胜率 | 每步耗时 |
|---|---|---|---|
| 跳费龙镜像·学习版：取 max vs 现在的 MCTS:200 | 取 max | **60% ± 7%**（120-80） | 70 ms vs 72 ms |
| 跳费龙镜像·手写：取 max vs 现在的 MCTS:200 | 取 max | **56% ± 7%**（112-88） | 61 ms vs 59 ms |
| 破魔虫（手写）vs 跳费龙 mcts:200+plan | 破魔虫用现在的 MCTS:200 | 12% ± 5% | 113 ms |
| 同上 | 破魔虫用 MCTS:800（4 倍算力） | 14% ± 5% | 315 ms |
| 同上 | **破魔虫用 MCTS:200 取 max** | **24% ± 6%** | 105 ms |

取 max 让破魔虫的胜率翻了一倍，4 倍算力只多了 2 个百分点。（`08e2de2` 的文档里记的破魔虫 17% vs 16%，对手是旧搜索的跳费龙，所以和这里的 12% 不能直接比。）

整回合规划智能体（`turnplan.py`：每步在 3 次重新洗牌的局面上各穷举本回合，预算 4000 个节点，各次结果取平均）在跳费龙镜像·学习版里对现在的 MCTS:200 是 **63% ± 9%**（100 局，63-37），但每步 281 ms，慢 4 倍。

## 1. 回合内搜索用平均值回传，铺垫型动作被系统性低估（影响最大）

### 现象

ISMCTS（`svsim/search/mcts.py`）的树只覆盖当前回合，叶子用静态评估打分，然后：

```python
for n in path:
    n.visits += 1
    n.total += v          # 选择时用 total / visits：所有后续的平均
```

一个动作的子树里，有"正确的下一步"，也有"出完就结束回合""乱打一通"之类的分支。平均下来，**需要后续配合的动作**比它真实的价值低得多。"结束回合"这类一步到位的动作，分数却稳定不变。

**典型例子**（学习版评估，第 15 回合，旧代码上调试；三个随机种子的统计完全相同，说明和随机性无关）：

| 根节点的子动作 | 访问次数 | 平均估值 |
|---|---|---|
| 结束回合 | 39 | 0.7728 |
| 使用「古旧天刀·波菈莱」 | 36 | 0.7674 |

"波菈莱 → 超进化 → 攻击贝鲁"这条线的估值是 0.99，可 MCTS 选了**结束回合**。

### 量化：同一个评估函数，离整回合最优差多少

做法：在实战局面的回合开头，用**穷举整回合所有出牌顺序**（`state_key` 置换表，跳费龙平均 0.7 秒/回合）找出这个评估下能达到的最高回合末评分，再看各智能体实际打出来的差距。数据是 64 局实战里抽出的回合开头，**完全确定的回合**（路线里没有抽牌和随机效果）和含随机的回合分开统计，因为只有前者里穷举不算偷看。

**确定回合**（打出整回合最优的比例 / 平均评分损失）：

| | 回合数 | 贪心 | MCTS:200（现在） | MCTS:800 | **MCTS:200 取 max** |
|---|---|---|---|---|---|
| 跳费龙·手写 | 41 | 63% / 2.34 | 80% / 0.52 | 83% / 0.50 | **98% / 0.09** |
| 跳费龙·学习版 | 32 | 66% / 1.46 | 81% / 0.68 | 91% / 0.46 | **97% / 0.09** |
| 破魔虫·手写 | 15 | 47% / 3.20 | 40% / 2.30 | 47% / 2.26 | **87% / 0.16** |

**含抽牌或随机的回合**：穷举按真实结果打分，等于偷看了运气，所以"最优"是上限；但各智能体之间的比较是公平的，因为都按同一个真实结果算分。

| | 回合数 | 贪心 | MCTS:200 | MCTS:800 | 取 max |
|---|---|---|---|---|---|
| 跳费龙·手写 | 22 | 32% / 3.20 | 45% / **1.60** | 45% / 1.46 | 50% / **2.09** |
| 跳费龙·学习版 | 31 | 19% / 5.10 | 23% / 3.85 | 32% / 3.07 | **58% / 1.29** |
| 破魔虫·手写 | 35 | 23% / 4.47 | 26% / 3.52 | 31% / 2.78 | **40% / 1.56** |

- 纯取 max 在有随机的回合里会偏乐观：手写版跳费龙这一行，它的平均损失反而比现在的 MCTS 大（样本只有 22 个回合，但方向和理论一致）。这正是建议"自己的决策取 max、随机结果取平均"的原因。
- 它**没有明显更爱选抽牌和随机动作**。路线里含随机动作的比例，MCTS:200 / 取 max / 穷举最优分别是：跳费龙·手写 24% / 29% / 27%，学习版 32% / 32% / 35%，破魔虫 50% / 52% / 62%。

- **算力翻 4 倍（MCTS:800）收益很小，只把平均改成取 max 却收益很大**：说明问题在结构上，不是算力不够。
- 破魔虫最明显：66% 的最优回合，第一步都**不是**"单看这一步最好的动作"（打小牌攒连击、弹回手），现在的 MCTS 连一步贪心都不如。

**例子**（确定回合，在 `6a2fe3f` 上的第一轮）：

- 破魔虫第 9 回合
  - 最优：大游戏世界 → 破魔虫打脸 → 昆虫的忠告把破魔虫弹回手 → 再出破魔虫 → 进化 → 再打脸
  - MCTS：进化破魔虫 → 打脸 → 结束
- 跳费龙第 13 回合（学习版）
  - 最优：伊兰翠 → 超进化 → 攻击诺玛格达拉
  - MCTS：安纳提玛 → 进化 → 结束

玩家标出的"先打脸后进化"也是这一类问题。`moves.py` 的剪枝规则修好了这一种，但同类问题还有很多（先上 buff 再攻击、先解场再出牌、先弹回再出），靠一条条写规则补不完。取 max 以后，确定回合里这类情况基本都能选对（上表 98% / 97% / 87%），不需要一条条写规则。

### 建议

- **最小改动**：回合内节点存"后续里最好的叶子值"，选择时用它代替平均值（见 `variants.py`，和现在的 `_iterate` 只差 3 行；最终选根节点下估值最高的动作）。
- 更干净的做法是**自己的决策取 max、随机结果取平均**（expectimax）。纯 max 遇到随机效果和抽牌时会偏乐观，因为它记住的是抽样里最好的那次结果。
- 或者干脆用**整回合规划**替代回合内 MCTS：用穷举加置换表找回合末评分最高的路线，随机和隐藏信息用几次重新洗牌的平均处理（见 `turnplan.py`）。`search/lethal.py` 的框架（置换表、随机节点重抽样）几乎可以直接复用，把目标从"斩杀概率"换成"回合末评估"就行。破魔虫的回合太长，需要预算或者剪枝。

## 2. 学习版只学了一个对局，换对手就失灵

`svsim/learn/weights/dragon.json` 的 `info`：8684 个局面，全部来自破魔虫 vs 跳费龙，跳费龙胜率 88%。

| | 对破魔虫 | 跳费龙镜像 |
|---|---|---|
| 预测胜负的 AUC：学习版 | 0.920 | **0.607** |
| 预测胜负的 AUC：手写评估 | 0.855 | 0.633 |
| 预测胜负的 AUC：只看双方血量差 | 0.786 | **0.659** |
| 学习版自评的平均胜率 / 实际胜率 | 0.884 / 0.986 | **0.773 / 0.529** |
| 自评 > 0.9 的局面，实际胜率 | 1.000（526 个） | **0.580（407 个）** |

镜像局里学习版的判断**不如只看双方血量差**。原因之一是下面这些系数**正好是 0**：训练数据里它们从没变化过，因为破魔虫从不出这类随从。

```
op_ward, op_bane, op_barrier, op_evasive, op_deck_low, op_deck_out,
me_deck_low, me_deck_out, me_drain, me_amulets, me_amulet_cost, me_crests（以及已手动清零的 hp_low）
```

可镜像局里对手满场都是这些：诺玛格达拉和伊兰翠有守护，波菈莱和相枛津有必杀，露莉亚有屏障，伊兰翠进化后有威慑。学习版对它们完全无感，只按身材算。

"以起点居中"解决的是估值被**压扁**（看不出差别），但没有解决**判断本身是错的**。

### 建议

- 训练数据至少覆盖：镜像、对破魔虫、对海盗皇家（`decks.PIRATE_SWORD`），最好再加上随机卡组。或者按"我方卡组 × 对方卡组"分开建模，没学过的对局退回手写评估。
- 训练集里没变化过的特征，系数不应该当作"已知为 0"。可以退回手写权重，或者在报告里标出来。
- 每次更新模型，都要对**多个对手**测强度（隔壁已经在这么做了）。

## 3. 评估看不见的、算反的东西（自对弈学不出来的部分）

特征（`learn/features.py`）和手写评估（`search/evaluate.py`）只看：血量、随从身材和关键词、护符张数和费用、纹章张数、手牌张数、进化点、PP 上限、牌库是否见底、场面威胁。

**算反了**：纹章不分是谁的、对谁有利，一律算作持有者的资产。焦灰的安纳提玛超进化时塞给对手的诅咒纹章（对手每回合开始扣 2 血，回血时再扣 1），被两套评估都当成对手的好东西：

- 学习版：**-3.58 分**；手写：**-2.00 分**（40 个可超进化安纳提玛的决策点上的平均值）
- 实战中 40 次能超进化安纳提玛的机会，AI 只用了 **5 次**。

**看不见**（只要有用的信息不在特征里，自对弈就学不到它）：

| 看不见的东西 | 受影响的牌 | 后果 |
|---|---|---|
| 当前剩余 PP（只有上限） | 露莉亚爆能"回 7 费"、魅禄"回 2 费"、年幼宝石兽超进化"回 3 费" | 回合中间的叶子上，回费价值为 0，要靠搜索再往下走才能兑现（又碰上第 1 点） |
| 本回合连击数 | 屠戮破魔虫（+X 攻击）、发芽组员、枝叶大姐大、磷光辉岩 | 破魔虫这套牌的核心资源完全不可见 |
| 倒数护符的进度 | 大游戏世界 | 只按 1 费护符算 |
| 手里是哪张牌、费用多少 | 破魔虫在手和妖精在手一样；贝鲁的减费不可见 | 留牌、减费、"把用不上的牌融合掉"都看不出价值 |
| 场上随从的能力 | 伊兰翠（每回合结束 8 点：解场 + 回血，进化后打脸）、谢幕曲、光环 | 只按身材和关键词算 |

### 建议

- 先修纹章：在卡牌脚本上标出"诅咒"（对持有者有害），特征拆成"有益纹章"和"诅咒纹章"，手写评估里诅咒纹章算给施放方。
- 给破魔虫加连击数和"手里有破魔虫"之类的特征（`potential` 系列特征已经在往这个方向走）；给回合中间的叶子加当前 PP，或者统一只在回合末打分。
- 长期看，线性模型配手工特征很快会碰到天花板。可以换成以卡牌 id 嵌入为输入的小型价值网络。但**先修第 1 点**：搜索不改，评估再准也用不出来。

## 4. 自对弈的训练信号本身偏弱

- `tools/learn.py` 默认用 `greedy+plan` 自对弈产生数据。可一步贪心打出整回合最优的比例，全部回合里只有 43%~52%（破魔虫 30%），所以胜负标签反映的大多是"贪心会犯的错"，而不是局面本身的价值。改用修好的搜索来自对弈，数据质量会高很多。
- 玩家对局的**单步选择**（`data.choices`）用的是"这一步之后、当作回合结束"的局面，和第 1 点一样短视：玩家弹回破魔虫的那一步，单看就是亏的，硬让模型把它排第一只会把权重拉歪。**整回合比较**（`turn_choices`）才是对的粒度，建议加大它的权重，或者只用它。

## 5. 一个小坑

从 pickle 读回的局面，如果进程里没有导入 `svsim.cards.library`（或 `svsim.cards.decks`），卡牌脚本不会注册：牌照样能打出来，但**静默地没有任何能力**。只导入 `svsim.ui.text` 时只注册了 9 张演示卡，只导入 `svsim.learn.model` 时是 0 张。正常入口没问题，离线分析脚本很容易踩到（我自己第一轮实验就踩了，已全部重跑）。建议在 `engine.apply` 或者反序列化入口加一个"脚本表非空"的断言。

## 复现

脚本都在本目录，在 svsim 的检出目录下运行：`PYTHONPATH=<svsim>:<本目录>`。

| 脚本 | 内容 |
|---|---|
| `collect.py` | 收集决策局面：破魔虫（mcts:200+plan）vs 跳费龙（mcts:200+plan+learned）40 局，跳费龙镜像 24 局，共 3680 个决策点 |
| `sat.py` | 实验 A：学习版估值的饱和程度、对 1/2 点伤害的敏感度、校准 |
| `planning_loss.py` | 实验 B：穷举整回合最优 vs 贪心 / MCTS:200 / MCTS:800 / 取 max |
| `learned_checks.py` | 实验 D：分对局的 AUC 和校准、诅咒纹章的估值、零系数 |
| `variants.py` | 取 max 回传的 ISMCTS（继承现在的 `ISMCTS`，保留居中和剪枝） |
| `turnplan.py` | 整回合规划智能体；`make()` 也认 `mctsmax:N` |
| `duel.py` | 两个智能体对战：`python duel.py A B mirror\|rhino 局数 种子`（rhino 局 A 用破魔虫） |
