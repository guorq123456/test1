# 一个 bot 打所有卡组：方案（2026-10-07 17:40Z，架构线程）

Salem 的问题（17:35Z）：现在一套卡组一个 bot；想要一个能同时操纵所有卡组、看到新卡组能快速理解其运转逻辑的 bot。下面每条都标了把握，括号里是怎么证伪。

## 0. 先纠正一个前提
**C1〔高〕现在已经是"一个 bot"的大半。** 规则、搜索（ISMCTS、斩杀线、候选生成）和卡牌脚本对所有卡组通用，v2 打海盗和打跳费龙用的是同一套搜索。真正按卡组分开的只有两样：终局评分 ENDED/ACT 的线性权重（按对局组合取模，查不到就回退到职业对、再回退到通用模型）和起手规则。所以"通用 bot"不是推倒重来，是换掉评分器的输入和起手规则的来源。

## 1. 共享什么：把"卡组 id"换成"量出来的功能"
**C2〔高〕每张牌的表示 = 规则沙盒量出来的功能向量，不是 id。** 这条路已经在走：roles.py 量面伤/解场/回血/过牌/跳费/身材，payoff.py 量进化和超进化的打脸/价值收益（口人魔 = 打脸 3、价值 0 就是这么来的）。再补三项：费用曲线位置、关键词、它产生什么（衍生牌、纹章、护符）。一张新卡进卡池，沙盒跑一遍就有表示，零对局。
（证伪：挑 20 张比赛卡表里的牌，隐藏 id 只给向量，让 bot 在构造局面上做选择，和有 id 时一致率低于 90% 就说明向量漏了东西。）

**C3〔中〕一套卡组的"运转逻辑"= 一张 goldfish 剖面。** 让这套卡组对着不出牌的对手自己打 2000 局，量出：最快斩杀回合分布（时钟）、引擎上线回合（纹章/护符/跳费第一次生效）、每回合可达的最大面伤（reach）、手里解场和回血的总量（防守）、跳费密度、曲线。这 10 来个数就是评分器的"卡组上下文"，替代卡组 id。跳费龙的剖面会写着"7 回合前没时钟、9–10 回合 reach 陡升"，连击妖写着"4–6 回合引擎上线、靠曲千代 AoE 守"，这正是 meta 文档用文字写的东西，变成数。
（证伪：用剖面对四套比赛卡组做盲分类，分不开就是剖面不够；或者把剖面喂给评分器后，等算力对专用模型反而变差。）

**C4〔中〕评分器共享一份：输入 = 双方局面 + 双方卡组剖面 + 交互项（我的时钟 vs 对手的时钟 = 竞速语境，(b) 里的 racing 项就是它的特例）。** 按对局分开的部分只留一个很小的"残差校准层"，某个对局自对弈够 1500 局才训，没有它共享模型也必须能独立站住，这就是新卡组时用的那一版。
（证伪：10 个对局组合逐个等算力对专用模型 600 局，任何一个显著低于专用模型 3% 以上就不通过。）

手牌价值方案（hand-value-design.md）第 3 节的"卡组 id 门控"按这个思路改成"卡组剖面门控"，否则新卡组进不来。编码器全卡池共享那条不变。

## 2. "看到新卡组快速理解"分三层，越往下越快
1. **零对局**：新卡组的 40 张过沙盒出功能向量，再跑 goldfish 出剖面（纯算力，几分钟）。bot 立刻有一个"大概知道它想干什么"的评分器。
2. **约 200 局自对弈**：只训残差校准层，等算力对"零对局版"过一次门。
3. **对局中**：从对手亮出的牌推断它的卡组。对已知的比赛卡表做贝叶斯更新（**C6〔高〕几回合内就能认出，比赛卡表的牌很有辨识度**）；认不出来的，就用"已见的牌 + 职业先验"现场拼剖面。这一层让同一个 bot 在不知道对手卡组时也能用剖面。

## 3. 怎么验证，各要多少局（闸门规则不变：等算力、成对座位、SPRT 后固定 600、真实先后手分开）
- **A. 数据前提（已在做）**：登记四套比赛卡组，每个对局组合各自的专用评分器。这些专用模型是通用模型要追平的上界。10 个组合 × 自对弈 ≥1500 局 + 各一次 600 局闸门。
- **B. 共享评分器 vs 专用**：10 个组合 × 600 局 = 6000 局。通过 = 没有一个组合显著差于专用 3% 以上，且都好于通用回退。
- **C. 留一套卡组不训（leave-one-deck-out，4 折）**：只用 3 套卡组的数据训共享模型，在第 4 套的对局上对通用回退 600 局 × 4 折。这是"没见过这套卡组"的硬测试（**C5〔中低〕**，我最没把握的一条：功能向量能不能跨卡组迁移，没人验证过）。
- **D. 快速适应**：第 4 套只给 200 局自对弈训残差层，再对 600 局。通过 = 和专用模型的差距至少补回一半。
- **E. 对手卡组推断**：拿已存的对局离线算，第几回合 top-1 archetype 正确率到 90%。便宜，随时能做。

**顺序**：A（进行中）→ B → C → D；E 并行。先做 B 的原因：它只换输入不换结构，失败了也立刻知道是功能向量还是剖面不够。

## 4. 和现有计划的关系
- 导入四套比赛卡组本来就是通用 bot 的数据前提，不改。
- (b) 进化点条件价值改的是线性底座里的条件项，共享评分器建在它之上，闸门分开做。
- 手牌价值学生按剖面门控而不是卡组 id 门控，其余按那份方案。
- 搜索这一侧唯一要补的是连击妖和机锋的组合回合线性搜索（规则层面，所有卡组共用）。
