# 手牌条件价值：让 bot 自己给手牌定价，并以此训练

Salem 2026-10-07 17:29Z 的方向：「让 bot 自己评估不同卡组的不同手牌在不同条件下的价值，以此为导向做进一步训练」。
约束（Salem 13:48Z）：绝不允许每张牌一个固定分。9 张妖精在 9 费后的价值远低于「龙族安娜题码 + 正义」两张。

本文建立在架构线程下午已经做过的教师实验之上（`keep_value`，见 analysis/card-value/README.md），不重复它，只补三件事：
真值怎么脱离评估器族、学生怎么做到按局面定价而不是按牌定价、多卡组怎么共享。

## 0. 现状（查到的）

- 上线的 v2/v2s 评估器里，自己的手牌只有一个特征：张数 `me_hand`。6 费局面把任一手牌换成牌组里 15 种牌中的任一种，评分变化为 0；任何一张牌都值 0.10 logit ≈ 2.6% 胜率。
- 按功能分类的手牌特征（`me_hand_face/removal/heal/draw/ramp/body`）训练时被清零（`STOCK`），因为加上后单回合搜索会囤牌、囤进化点。
- 教师 `keep_value`（有/无这张牌，跨回合推演后的分差）：在 Salem 的 80 个非斩杀回合上，留牌排序 64–66%，不如单回合 Q 对照 70%；在自对弈干预式样本上有明显增量（partial 0.54，AUC +0.19）。但教师和真值都由同一个 phased 评估器族打分，只说明教师在 bot 自己的世界里有信息量，不说明这个世界是对的。学生未训练。
- 搜索里已有机制可借用：`mcts.py` 用 `_root_deck` 区分「根节点就在手里的牌」和「本回合抽到的牌」，并对抽到的牌做重抽平均。

## 1. 真值：脱离评估器族

教师标签 T(c | s) = 「局面 s 下，手里有 c 比没有 c 多多少」。现在它的终点是 phased 评估器的分数，所以继承了评估器的盲点。改成三层终点，越往下越贵但越不依赖评估器：

1. **G_end：打到终局**。两条分支（有 c / 无 c）用同一套随机数和同一牌序（common random numbers），都由当前 bot 打到游戏结束，K 次（K=8 起），标签 = 胜率差。完全不经过评估器。这就是分析会话排队中的 G_end 检查，只是从「检验」变成「生产标签」。
2. **G_next：两回合后由强搜索打分**（现有做法，mcts:400），作为便宜的近似。
3. **Salem 的 27 局**：不做标签，只做尺子。Salem 留下的牌、打出的牌，与学生给出的价值排序比对，是唯一不来自 bot 自己的信号。

训练标签 = G_end 为主，G_next 做方差缩减（控制变量法：G_next 和 G_end 的协方差已知，用 G_end − β·(G_next − E[G_next]) 之类的方式降噪），而不是直接拿 G_next 当真值。

每轮迭代都要报告两个数：Spearman(T, G_end) 和 T 在 Salem 80 回合上的留牌 AUC。前者看教师有没有信息量，后者看它是不是朝 Salem 的方向走。只有后者过了单回合 Q 对照（70%），学生才上线。

## 2. 学生：按局面定价，不是按牌定价

学生 H(hand | context) 给整手牌一个价值，而不是给每张牌打分后求和。

**输入**
- 每张手牌：卡牌 id 嵌入 + `roles.py` 里量出来的功能向量（面伤、解场、回血、过牌、跳费、身材）+ 费用 + 「下回合能不能打出」（费用 vs 下回合 PP）+ 「再过几回合能打出」。功能向量让没见过的牌也有起点。
- 局面 context：回合数、当前和下回合 PP 上限、双方血量、双方场面摘要、我方剩余进化/超进化点、对手未见牌的功能份额（现有 `op_hand_*`）、双方牌库大小、我方卡组 id、对手卡组 id。
- 手牌作为一个集合：每张牌的编码先和 context 拼接过一层，再做集合汇聚（DeepSets 或一层很小的 attention），最后一层输出 H。集合汇聚是为了表达「安娜题码 + 正义」这种两张牌合起来才成立的价值，以及「9 张妖精」这种冗余递减。

**训练目标**：不是回归 H 本身，而是回归差分。
对每个 (s, c) 样本：H(hand | ctx) − H(hand \ {c} | ctx) ≈ T(c | s)。
这样学到的就是「这张牌在这个局面、这手牌里的边际价值」。

**硬约束，用结构保证「没有固定分」**：卡牌嵌入不能直接通到输出；它只能经过和 context 相乘（门控）后才有贡献。这样一张牌在「打不出来」的 context 下可以被门控压到 0。另外写一条单元测试，就用 Salem 的例子：9 费、手里 9 张妖精 vs 手里安娜题码 + 正义，后者的 H 必须更高；再加一组「同一张牌，2 费和 9 费时的边际价值」必须不同。

**接入搜索**：H 作为 ENDED 分数的加项（和 `learn/net.py` 一样，在线性模型之上学修正），只对「根节点就在手里的牌」算 H；本回合抽到的牌用一个「未知牌」token，取牌库平均。这正好绕开夜里 per-card 网络失败的原因：不同 determinization 抽到不同牌造成的叶子抖动。`_root_deck` 已经有了，不用新机制。

**防囤牌**：标签 T 是「有这张牌比没有多多少」的反事实收益，不是「手里有牌和赢相关」。打不出去的牌 T ≈ 0，关键牌 T 大。于是「现在打」和「留着」的比较变成：打出的场面收益 vs 这张牌在后续回合的边际价值，两边都是同一个尺度上的胜率。囤牌当年是因为「有牌 = 赢」这个相关性，这里没有它。但要验证：接入后自对弈的「平均每局打出牌数、进化次数」不能比 v2s 少超过 5%，这是架构线程已经在用的 pacing 指标。

## 3. 多卡组：共享编码，分开校准

- 卡牌编码器（嵌入 + 功能向量）全卡池共享，所有对局的数据一起训练。
- context 里带我方卡组 id 和对手卡组 id 的嵌入，让同一张牌在不同卡组里（连击妖的妖精 vs 别的卡组里的妖精）得到不同门控。
- 线性底座（ENDED 模型）继续按对局分开，这是 Salem 13:43Z 定的；H 是共享的修正层。
- 新对局数据少时先用共享模型，数据够（≥ 1500 局自对弈）再对该对局微调最后一层。
- 导入比赛卡表的那条线每个对局都要跑自对弈，顺手就能产标签；要求是记录时保留 `_root_deck` 信息和分支随机数种子，否则 G_end 做不了配对。

## 4. 迭代回路（「以此为导向做进一步训练」）

1. 当前 bot 自对弈 → 抽样 (s, c) → 配对打到终局算 T → 训练 H → 接入 ENDED → 等算力闸门（SPRT 再固定 600 局，先 strong 对 v2s）。
2. 过闸门后，用新 bot 重新产标签，再训练。每轮报告：Spearman(T_new, T_old)（标签稳定了没有）、Salem 80 回合留牌 AUC、pacing 指标、闸门结果。
3. 停止条件：闸门连续两轮 H0，或 Salem 尺子不再上升。

## 5. 顺序和代价

1. 先把 G_end 配对标签工具做出来，在现有 1200 项干预式样本上跑一遍，只看一个数：Spearman(G_end, G_next)。如果 ≥ 0.6，G_next 可以当方差缩减用；如果低，说明评估器族和终局差得远，这本身就是重要结论，要告诉 Salem。
2. 学生只做到「单元测试过 + Salem 80 回合留牌 AUC ≥ 70%」才接入搜索；接入后等算力闸门。
3. 和正在做的 (b) 进化点条件价值不冲突：(b) 改的是线性底座里进化点的条件项，这里加的是手牌的修正层，两者可以叠加，但闸门要分开做，否则分不清增益来自谁。

## 推断的部分

集合汇聚能学到两张牌的组合价值、门控能压住打不出的牌、G_end 的噪声能靠配对随机数压到可用，这三点都是推断，没有在这个代码库上验证过。第 5 节第 1 步就是用来验证最后一点的。
