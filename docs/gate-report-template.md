# 门控报告模板

2026-11-02 入库（方案第 3 项，论文的门 G4；论文线程起草）。每份门控、联赛、验收报告的开头固定这几行，缺一行不算交付。

```
条件：对手卡表已知（牌序、手牌未知）          # 或写明不同的条件
预注册：<文件路径> <提交号>，预测：<一句话 + 置信度>
模拟器：提交号 <sha>，规则哈希 <hash>；X 方模型训练时的规则哈希 <hash>（一致 / 不一致，已放行原因）
挑选种子库：<编号范围>（配时、挑 N、挑快照、SPRT 都只在这里）
确认种子库：<编号范围>（结论只认这里的数字）
算力：X 与基线每决策 CPU 之比 <ratio>；超过 1.08 时按 round(N / ratio) 重跑一次，写重跑的 N 和比值；两组互比时两边的比值都写
结果：X <胜率> 对 基线 <胜率>，配对差 <±95%>，<对数> 对
按对手：<职业：X / 基线 / 差>
验收题库：明显题 <a/b>，边际题 <c/d>（边际题不单独作为门）
未决裁定：<docs/rulings.md 里状态为「未决」的编号，没有就写「无」>
偏差：<和预注册不一样的地方，没有就写「无」>
账本：F-<编号>（/mnt/project-files/shadowverse/process/ledger.md；被推翻时写新条目指回）
```

说明：
- 「挑选」和「确认」分开写，是论文的 G4，也是我们 10 月的教训：SPRT 提前停止和在挑选种子上选出来的最好快照，换种子会掉。提前停止的数字只能出现在「挑选」一栏。
- 「模拟器」一行是论文的 G2：模型和它训练时的模拟器版本绑定（方案第 2 项，11-02 落地，svsim/learn/provenance.py）。规则哈希用 `python -m svsim.learn.provenance list` 查；门控脚本自动打印这几行之前，手填。
- 「验收题库」一行等方案第 5 项合并脚本后自动生成。
- 种子库编号先登记再用：项目记忆里的种子账（MEMORY.md「Seed ledger」），分析会话分支上的 analysis/seed-banks.md 也记一份。
