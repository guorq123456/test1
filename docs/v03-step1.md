# v0.3 第 1 步：缺口、分岔、反推 —— 接口契约

顶层设计见对话记录。这里只写代码层面的约定，引擎、界面、领域模块都按这份文档对接。

## 1. 尝试的结果

`combine(L, M, R, W)`：四个参数都是卡（item）或 null。`W` 是底板上的世界（一个卡组 item），可以为空。

返回值永远是：

```js
{
  ok: true,
  item: <得到的卡> | null,     // 成立的那部分：值卡或卡组卡；一张都没有时是 null
  holes: [<缺口卡>, ...],     // 零到多张
  text: '说明',                // 为什么这样分
  recipe: '做法文字',          // 只有卡组结果才有
  catId: 'Z',                  // 结果被认成图鉴卡组时才有
}
```

只有"用法提示"才返回 `{ ok: false, msg }`：中间格空着、构造算子放错位置、两种类型之间根本没有这种运算（`reason: 'type'`）。凡是**法适用但某些值走不通**的情况，都不是失败，而是分岔。

## 2. 错误的类别（领域模块要做的）

二元运算 `bin(op, x, y)`、具名算子 `apply(x)`、`call(v, x)` 返回 `{ err }` 时，加一个 `reason` 字段：

| reason | 意思 | 例子 | 引擎怎么处理 |
|---|---|---|---|
| `'type'` | 这两种卡之间没有这条法 | 余数 + 长度、向量 ^ 2、不同模数相加、不同量纲相加 | 用法提示（`ok: false`），和现在一样 |
| `'undefined'` | 法适用，但这个输入没有定义，任何世界都补不上 | 除以 0、0⁰、log 0、[4]₁₂ 没有逆元、奇异矩阵求逆 | 缺口，类别「没有定义」，标"补不上" |
| `'unrepresentable'` | 数学上有结果，引擎写不出来 | √2、2^(1/2)、多项式 ÷ 多项式（分式）、指数分母 > 12、数字太大（OVER） | 缺口，类别「表示不了」；目标查找找不到就是"前沿" |

没写 `reason` 的 `{ err }` 一律当 `'type'`。`null` 当 `'undefined'`，`OVER` 当 `'unrepresentable'`。

## 3. 缺口卡

```js
{
  kind: 'hole',
  id: 'h:<指纹>',
  v: {
    kind: 'undefined' | 'unrepresentable' | 'outside',   // 没有定义 / 表示不了 / 越出世界
    lawText: 'x − 3' 或 '−' 或 '1/x',   // 哪条法
    lawKey: 'bind(sub,r,3)' 等,          // 法的唯一键（指纹用）
    source: <卡组>,                      // 从哪个世界出发（单卡就是只有它的有限卡组）
    sourceName: 'ℕ',
    where: <卡组>,                       // 卡在哪里：没有定义/表示不了 → 走不通的输入；越出世界 → 跑出去的结果
    world: <卡组> | null,                // 底板上的世界（只有越出世界才有）
    status: 'fillable' | 'frontier' | 'unfillable' | 'filled',
    targetId: 'Z' | null,                // 可填时：能填成的最小图鉴世界
    name: '负整数' | null,               // where 被认成图鉴卡组时的名字
  },
  desc: { k: 'hole', from: [L.desc, M.desc, R.desc], w: W?.desc ?? null, kind, idx },  // 存档：重放 combine，取第 idx 张同类缺口
}
```

- 缺口卡放在材料位上，等于它的 `where` 卡组：`ℕ ∪ 缺口(负整数) → ℤ` 直接成立。
- `where` 会像普通卡组一样和图鉴比对，认出来就有 `name`。
- 指纹由 (kind, lawKey, source 指纹, where 指纹) 决定，同一个缺口每次得到同一张卡。

## 4. 目标查找（引擎）

对一张缺口，在图鉴里找**包含出发世界（和越出的结果）、并且这条法在它上面封闭**的最小世界：

- `outside`：候选 = 同类型的图鉴世界 C，满足 C ⊇ world ∪ where，且法在 C 的样本上封闭（结果都在 C 里，或者没有定义）。
- `unrepresentable`：候选同上，但通常找不到（无理数、分式还没有对应的世界），就是"前沿"。
- `undefined`：不查找，状态 `unfillable`。

"最小"：候选里不包含其他候选的那个；有多个时取探针最少的。

## 5. 填与手填（构造算子「填」，id `fill`）

- `[缺口] [填] [空]`：`fillable` → 得到目标世界卡，text「你发明了 ℤ：包含 ℕ、又能做减法的最小世界」，缺口状态变 `filled`；`frontier` → `ok: false`，msg「这个缺口还没有人填过：……可以用现有的卡凑一个世界来填」；`unfillable` → msg 说明为什么补不上。
- `[缺口] [填] [候选卡组]`（手填）：检查 (a) 候选 ⊇ 出发世界（探针上），(b) 法在候选样本上封闭。
  - 合规，且候选等于最小目标 → `item` = 目标世界卡，`grade: 'exact'`（恰好）
  - 合规，但比最小目标大（或前沿缺口、没有目标）→ `item` = 候选卡组（前沿时它成为有名字的自造世界），`grade: 'over'`（多了一块）或 `'frontier'`（首次发现 + 发明者）
  - 不合规 → `item: null`，`holes` = 还跑出去的结果，text 说明
- 返回值多一个 `grade` 字段，界面据此显示徽章。

## 6. 反推（构造算子「反推」，id `reverse`）

`[X] [反推] [一元法]` 或 `[一元法] [反推] [X]`，X 是值或卡组：结果是卡组 `{ x | f(x) ∈ X }`。

- 精确谓词：`x ∈ 原像 ⇔ f(x) 有值且在 X 里`。
- 原像的类型：在各类型的视野里试 f 能算的那个类型。
- 和图鉴比对：x + 1 反推 偶数 → 奇数；x² 反推 4 → {−2, 2}。
- 反推没有缺口；空原像是 ∅。

## 7. 底板（界面）

合成台上方加一格「在……里」，只能放卡组。有底板时：

- 值结果不在底板里 → 得到为空，缺口「越出世界」。
- 卡组结果 → 得到 = 结果 ∩ 底板；越出的部分成缺口。
- 封闭在底板里进行：跑出去的结果记入缺口，不参与后续组合。

## 8. 存档

缺口卡的 `desc` 记录来源，读档时重放 `combine` 取回同一张。`S.slots` 多一个 `W`。

## 9. 测试

- 守恒：像的 得到 ⊎ 没有定义 ⊎ 表示不了 = 出发世界；有底板时 得到 ⊆ 底板，越出 ∩ 底板 = ∅。
- 命名与目标：ℕ − ℕ 在 ℕ 里 → 缺口名「负整数」，目标 ℤ；ℤ ÷ ℤ 在 ℤ 里 → 目标 ℚ；ℕ 经 √x → 前沿；1 ÷ 0 → 补不上。
- 填：三档判定；手填 ℕ ∪ 负整数 → 恰好；手填 ℤ ∪ {1/2} 之类 → 多了一块或不合规。
- 反推的典型例子。
- 现有 88 项测试原样通过（没有底板时所有做法不变）。
