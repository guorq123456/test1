# v0.3 第 1 步：缺口、分岔、反推 —— 接口契约

顶层设计见对话记录。这里只写代码层面的约定，引擎、界面、领域模块都按这份文档对接。

## 1. 尝试的结果

`combine(L, M, R, W)`：四个参数都是卡（item）或 null。`W` 是底板上的世界（一个卡组 item），可以为空。

返回值永远是：

```js
{
  ok: true,
  item: <得到的卡> | null,     // 成立的那部分：值卡或卡组卡；一张都没有时是 null
  holes: [<缺口卡>, ...],     // 零到多张
  text: '说明',                // 为什么这样分
  recipe: '做法文字',          // 只有卡组结果才有
  catId: 'Z',                  // 结果被认成图鉴卡组时才有
}
```

只有"用法提示"才返回 `{ ok: false, msg }`：中间格空着、构造算子放错位置、两种类型之间根本没有这种运算（`reason: 'type'`）。凡是**法适用但某些值走不通**的情况，都不是失败，而是分岔。

## 2. 错误的类别（领域模块要做的）

二元运算 `bin(op, x, y)`、具名算子 `apply(x)`、`call(v, x)` 返回 `{ err }` 时，加一个 `reason` 字段：

| reason | 意思 | 例子 | 引擎怎么处理 |
|---|---|---|---|
| `'type'` | 这两种卡之间没有这条法 | 余数 + 长度、向量 ^ 2、不同模数相加、不同量纲相加 | 用法提示（`ok: false`），和现在一样 |
| `'undefined'` | 法适用，但这个输入没有定义，任何世界都补不上 | 除以 0、0⁰、log 0、[4]₁₂ 没有逆元、奇异矩阵求逆 | 缺口，类别「没有定义」，标"补不上" |
| `'unrepresentable'` | 数学上有结果，引擎写不出来 | √2、2^(1/2)、多项式 ÷ 多项式（分式）、指数分母 > 12 | 缺口，类别「表示不了」；目标查找找不到就是"前沿" |

没写 `reason` 的 `{ err }` 一律当 `'type'`。`null` 当 `'undefined'`。`OVER`（数字太大）当 `'unrepresentable'`，但标 `tooLarge`，状态 `unfillable`（游戏的边界），不做目标查找。

余数的分数 p/q 按 p 乘 q 的逆元算（[1]₇ 经 x/2 得 [4]₇），q 没有逆元时是 `'undefined'`；余数开方不是单值的，是 `'type'`。

## 3. 缺口卡

```js
{
  kind: 'hole',
  id: 'h:<指纹>',
  v: {
    kind: 'undefined' | 'unrepresentable' | 'outside',   // 没有定义 / 表示不了 / 越出世界
    law: { t:'un', f } | { t:'bin', b } | { t:'meta', id } | { t:'pre', f, target },  // 一元 / 二元 / 并交 / 反推
    lawText: 'x − 3' 或 '−' 或 '1/x' 或 '反推 x²',   // 哪条法
    lawKey: 'bind(sub,r,3)' 等,          // 法的唯一键（指纹用）
    source: <卡组>,                      // 从哪个世界出发（单卡就是只有它的有限卡组，如 {0, 1}）
    sourceName: 'ℕ',                     // 越出世界时是底板世界的名字
    inputName: '缺口(负整数)',           // 越出世界时：真正的输入叫什么（只有越出世界才有）
    expr: '1 ÷ 0' | undefined,           // 值级缺口：写不出来的那个式子（卡对卡是玩家做的算式 1 ÷ 0，一元是代入后的 √2、log₂3）
    where: <卡组>,                       // 卡在哪里：没有定义/表示不了 → 走不通的输入；越出世界 → 跑出去的结果
    world: <卡组> | null,                // 底板上的世界（只有越出世界才有，其它缺口一律 null：它们和底板无关）
    operands: [A, B] | undefined,        // 两两运算的缺口：两边的操作数（没有定义/表示不了时，填的世界要装得下它们）
    status: 'fillable' | 'frontier' | 'unfillable' | 'retyped' | 'filled',
    targetId: 'Z' | null,                // 可填时：能填成的最小图鉴世界；换了类型时：跑出去的那个图鉴世界
    minimalIds: ['Z', 'Qnz'],            // 可填时：图鉴里所有极小的候选（互不包含时不止一个，手填成任何一个都是恰到好处）
    name: '负整数' | null,               // where 被认成图鉴卡组时的名字；值级缺口是 expr；只有一个走不通的输入时是那个式子（√2）
    tooLarge: true | undefined,          // 数字太大（OVER）
  },
  desc: { k: 'hole', from: [L.desc, M.desc, R.desc], w: W?.desc ?? null, kind, idx },  // 存档：重放 combine，取第 idx 张同类缺口
}
```

- 缺口卡放在材料位上，等于它的 `where` 卡组：`ℕ ∪ 缺口(负整数) → ℤ` 直接成立。
- `where` 会像普通卡组一样和图鉴比对，认出来就有 `name`。
- 指纹由 (kind, lawKey, source 指纹, where 指纹) 决定，同一个缺口每次得到同一张卡。where 的指纹按内容算（视野里的成员加小探针），不看它是怎么拼出来的：偶数 − 偶数 和 ⟨偶数 | −⟩ 在 ℕ 里是同一张缺口。近似（封闭）和精确（两两）算出来的 where 视野成员可能不同，那是已知的限制。

## 4. 目标查找（引擎）

对一张缺口，在图鉴里找**包含出发世界（和越出的结果）、并且这条法在它上面封闭**的最小世界：

- 出发世界就是缺口的 `source`：越出世界的缺口在造卡时已经把它换成底板；没有定义 / 表示不了的缺口用真正的输入，和底板无关（同一张缺口有没有底板结论一样）。
- `outside`：候选 = 同类型的图鉴世界 C，满足 C ⊇ world ∪ where，且法在 C 上封闭（结果都在 C 里，或者没有定义；有写不出来的结果也算没封闭）。
- `unrepresentable`：候选要 ⊇ 出发世界和走不通的输入（两两运算还要 ⊇ 两边的操作数，两边类型不同就没有候选），但通常找不到（无理数、分式还没有对应的世界），就是"前沿"。
- `undefined` 和 `tooLarge`：不查找，状态 `unfillable`。
- 越出的结果换了类型或换了族：状态 `retyped`，`targetId` 是 where 认出来的图鉴世界（有的话）。这不是这个世界的缺口，不能填。判定按值：跑出去的每个值的族（类型；量按量纲）都不在出发世界里出现过才算；出发世界是混合的（ℕ ∪ ℤ₁₂）就看它每一个来源；常数算 0 次多项式；where 被认成另一种类型的图鉴世界（ℤ mod 12 → 时钟、ax 经 x′ → ℚ∖{0}）也算；出发世界或 where 样本为空时不判。
- 有底板、而且两边只有一边和底板是同一种卡（ℤ² × ℚ 在 ℤ² 里）：法记成 `{ t:'bin', b, other: ℚ, side }`，封闭检查只查 K 里的卡和 other 的卡配对，不做 K × K（ℚ² 和 ℚ² 的 × 是点积，另一条法）。单卡时把不在底板里的那张绑进法里，左右顺序无关。
- `meta`（并、交）和 `pre`（反推）的法没有"再算一次"的封闭条件：只要装得下 world ∪ where 就算封闭。

包含检查（C ⊇ …）用的成员是整段样本、见证值（轨道走到视野外的那些步）和探针里属于它的值，不是样本的前几个。

封闭检查（`lawClosedOn`）的取样：候选自己的样本按来源交错、均匀取，加上小探针；必查值（缺口里的值、出发世界的成员、并集各来源的有限成员、像卡组来源的有限成员经 f 映射、见证值）单独一组，和候选样本正反各配一次，必查值之间也配一次，两组互不挤占；不大于 160 张的有限候选全部两两查；一元法查全部。近似候选（只在视野里算过）说"没有"只在它算过的大小范围内可信，并集要每一边都可信地说没有。

"最小"：候选里不包含其他候选的那个；有多个时取探针最少的，其余极小的记在 `minimalIds` 里。这只是**图鉴里**最小，文案一律写「图鉴里最小的世界」，不写"数学上最小"。

## 5. 填与手填（构造算子「填」，id `fill`）

- `[缺口] [填] [空]`（自动填）：`fillable` → 得到目标世界卡，`grade: 'auto'`，text「这个缺口填成了「整数 ℤ」：图鉴里包含 ℕ 和 负整数、又能做 − 的最小世界」（越出世界写"包含 出发世界 和 缺的部分"，反推写"又装得下 反推 x² 的全部解"，并、交只写"包含 …"），缺口状态变 `filled`；`frontier` → `ok: false`：越出世界的写「… 的结果 {…} 跑出了 W。可以用现有的卡凑一个世界来填」，表示不了的写「现在的数还写不出来。现在的卡填不上，要等新的数出现」；`unfillable` → msg 说明为什么补不上（值级缺口用式子：「1 ÷ 0 没有定义」）；`retyped` → msg「这不是这个世界的缺口：…拿掉底板再做一次」（并、交写"是另一边放进来的另一种东西"）。
- `[缺口] [填] [候选卡组]`（手填；候选也可以是另一张缺口，取它的 where；两边都是缺口时左边那张被填，同一张放两边也一样）：`unfillable`、`retyped` 一律 `ok: false`，理由同上。其余检查 (a) 候选 ⊇ 出发世界 ∪ 越出的部分（没有定义/表示不了时是走不通的输入和两边的操作数），(b) 法在候选上封闭（取样规则见第 4 节；写不出来的结果算没封闭）。近似候选（只在视野里算过）在 (a) 里视野外的值不算缺，在分档里也只在视野范围内比。
  - (a) 不成立 → `ok: false`，msg 列出缺的成员
  - (b) 不成立 → `ok: true`、`item: null`，`holes` = 还跑出去的结果（这张新缺口的 inputName 是候选卡组），text 说明
  - 合规，且候选等于图鉴目标、或图鉴里另一个同样极小的世界（`minimalIds`）→ `item` = 那个世界卡，`grade: 'exact'`（恰到好处）
  - 合规，候选真包含图鉴目标，或者候选本身是图鉴世界但不极小 → `item` = 候选卡组，`grade: 'over'`（多了一块）
  - 合规，自造的候选比图鉴目标小或和它不可比 → `item` = 候选卡组，`grade: 'tighter'`（比图鉴更紧），带 `firstFill: true`（发明者）
  - 前沿缺口合规 → `item` = 候选卡组（它成为有名字的自造世界），`grade: 'frontier'`（首次发现）；`firstFill` 只给自造的世界，图鉴里本来就有的不算发明
  - 成功的文案按法的种类说"关住了 −"（一元、二元）、"装得下 ℕ 和 负整数"（并、交）、"装得下 反推 x² 的全部解"（反推）
- 返回值多一个 `grade` 字段和 `filled`（被填的缺口 id），界面据此显示徽章、记录已填。

## 6. 反推（构造算子「反推」，id `reverse`）

`[X] [反推] [一元法]` 或 `[一元法] [反推] [X]`，X 是值或卡组：结果是卡组 `{ x | f(x) ∈ X }`（X 是单卡时写 `{ x | f(x) = 4 }`）。

- 精确谓词：`x ∈ 原像 ⇔ f(x) 有值且在 X 里`。
- 原像的类型：在各类型的视野里试 f 能算的那些类型；不止一种时卡组标 `mixed`，不和图鉴比对（ℤ ← 求导 既有 ℚ 也有 x + 5，不是 ℚ）。
- 和图鉴比对：x + 1 反推 偶数 → 奇数；x² 反推 4 → {−2, 2}。
- 没有底板时反推没有缺口。只有目标本身是空卡组、或者原像公式证明无解时才是 ∅；视野里一个解都没碰到（det(x) = 7、x′ = 1/7）不算空集，返回精确谓词卡组，标 `unknown`、类型 'set'，不和图鉴比对，名字算进指纹。有底板时，跑出底板的解成为越出缺口，法记成 `{ t:'pre' }`，填它只要求装得下。
- 混合类型的原像和单一类型的底板求交，结果按底板的类型认图鉴：ℤ ← x′ 在 ℚ 里就是 ℚ。

## 7. 底板（界面）

合成台上方加一格「在……里」，只能放卡组。有底板时：

- 值结果不在底板里 → 得到为空，缺口「越出世界」。
- 卡组结果 → 得到 = 结果 ∩ 底板（卡组名带「∩ 底板名」）；越出的部分成缺口，被大小上限丢掉的结果也要和底板比。
- 封闭在底板里进行：跑出去的结果记入缺口，不参与后续组合。延展、封闭在底板里跑出去过时，结果名带「∩ 底板名」，别和没有底板时的同名。名字拼接时带空格的部分加括号：「(奇数 − 奇数) ∩ ℕ」。
- 有缺口时说明写「留在 ℕ 里的结果就是「自然数 ℕ」」，不写「这就是」。
- 并集只有一边跑出去时，缺口就是那一边跑出去的部分，保留它的类型（ℕ ∪ ℤ₁₂ 在 ℕ 里跑出去的就是 ℤ₁₂，认得出来）。
- 近似的底板（只在视野里算过的自造卡组）在视野外说"没有"不可信：这些值不算越出。

## 8. 存档

缺口卡的 `desc` 记录来源，读档时重放 `combine` 取回同一张。`S.slots` 多一个 `W`。

## 9. 测试

- 守恒：像的 得到 ⊎ 没有定义 ⊎ 表示不了 = 出发世界；有底板时 得到 ⊆ 底板，越出 ∩ 底板 = ∅。
- 命名与目标：ℕ − ℕ 在 ℕ 里 → 缺口名「负整数」，目标 ℤ；ℤ ÷ ℤ 在 ℤ 里 → 目标 ℚ；ℕ 经 √x → 前沿；1 ÷ 0 → 补不上。
- 填：三档判定；手填 ℕ ∪ 负整数 → 恰好；手填 ℤ ∪ {1/2} 之类 → 多了一块或不合规。
- 反推的典型例子。
- 现有 88 项测试原样通过（没有底板时所有做法不变）。
