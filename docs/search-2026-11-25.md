# 2026-11-25 公开搜索的一处修改（第 3 期起）

Salem 11-25 定的。只改了 `svsim/search/mcts.py` 给动作编键的地方，规则、卡、引擎都没动。

## 改了什么

搜索把每个动作记成一个「键」，在不同的确定化之间认同一个动作。以前自己手里的牌只按卡号和费用认，同名同费、但状态不一样的两张牌被当成同一步：
搜索试的是排在前面的那张，根节点最后出的是排在后面的那张，两张之间也挑不了。比如手里被 Clue 换过攻防的纯真卖报人（2/2）和没换过的（2/1），
搜索算的是 2/2 那张，出的却是 2/1 那张。

现在自己手里的牌跟一张新卡不一样时（攻防、关键词、倒数、被去掉的能力、卡上计数、附加的能力），键里多一项这些状态：

- 新卡、只有费用变了的卡：键和以前一样，`("H", True, 卡号, 费用)`。
- 状态变了的卡：`("H", True, 卡号, 费用, 状态)`，前四项不变。两张状态一样的照旧算一步。
- 增幅次数不算进状态：每张手牌都会记，没有卡的脚本读它（增幅卡改的是自己的攻防或费用，这些照算）。
- 对手的手牌看不到，照旧只按卡号和费用认。

## 对你有什么影响

- 默认打法、基线成员、锚点和名人堂都用改过的搜索，出牌会变；带这类牌的卡组（比如靠手牌里养牌的）影响最大。
- 第 2 期以前在练习场、正式对局里打出来的成绩和胜率是旧搜索打的，不能直接拿来和这一期比；旧的正式对局用现在的代码按决策重放会对不上。
- 你的打法要是自己用 `action_key` 或 `_locator` 认手牌、或者自己拼这种键，状态变了的牌多一项；只看前四项的写法照样能用。

主持方在云端量过：默认打法双方 238 局，以前「搜的是这张、出的是那张」56 次，改后 0 次；每局耗时没有变化。
